# Changelog

## Unreleased

- Lowered checked direct and parenthesized string literals through the canonical expression planner. Each accepted leaf emits one zero-operand `IC_STR_CONST` with its decoded bytes unchanged, its internal `U8 *` result type, and its exact source span. Function bodies and executable top-level roots use the same JIT and AOT path. This boundary does not allocate string storage, add a terminator, or expose partial IR for conversion-bearing or otherwise unsupported uses.
- Evaluated completed aggregate `sizeof` targets in function bodies. Direct class and union names plus zero-rank aggregate parameters, automatic locals, static locals, and module globals now retain their completed layout size. Member paths keep each exact current-or-inherited lookup and use the final member's full storage size, including checked member-array dimensions. Nested paths continue only through by-value aggregate members, and trailing stars select the eight-byte pointer size. Supported values lower to one internal-`I64` `IC_IMM_I64` in JIT and AOT mode. Root arrays, pointer traversal, executable top-level and unmappable outer aggregates, and function debug ranges remain unsupported without partial IR.
- Evaluated ordinary function-body `sizeof` roots that select a checked scalar binding. Parameters, automatic and static locals, module globals, and metadata-bearing outer globals now retain their type, value shape, and array rank. Primitive objects use their audited byte count, while object pointers, aggregate pointers, scalar function pointers, and trailing source pointer layers use the eight-byte pointer size. A declaration such as `U8 I64` still wins over the built-in spelling and now evaluates from its checked `U8` type. Known values use the existing internal-`I64` `IC_IMM_I64` lowering in JIT and AOT mode. Root arrays and direct function extents remain unsupported; completed aggregate targets and members are covered by the entry above.
- Retained ordinary HolyC `sizeof` inputs in the shared semantic expression tree. Function bodies and executable top-level code now keep the keyword, balanced wrapper parentheses, root spelling and exact source-ordered query, repeated member path, pointer layers, and generated-source provenance in both JIT and AOT mode. Checked constructors reject mismatched roles, spellings, origins, pointer depths, and query ownership. Target-kind resolution, member lookup, layout arithmetic, byte-size evaluation, and immediate IR lowering remain separate work.
- Lowered HolyC power expressions to `IC_POWER` with an internal `F64` result. Integer operands carry `ICF_RES_TO_F64` on their retained producers, including both operands of an integer-only power; the power instruction stays unflagged. The lowerer preserves right association, keeps unary minus outside power, and uses the same checked path for function bodies and executable top-level code in JIT and AOT mode. Constant folding, numerical execution, `SYS_POW` selection, and backend emission remain separate work.
- Resolved ordinary executable top-level `defined` names against the exact module prefix visible before each statement and a caller-supplied JIT or AOT outer chain. Earlier module publications and supported outer or assembler records produce one; a complete miss produces zero. Known results reuse the existing `IC_IMM_I64` lowering in both compilation modes.

- Resolved ordinary function-body `defined` names against the source-visible compilation-unit namespace. Resolution reuses the checked publication records already replayed at each function header and requires their exact semantic identity. Executable top-level lookup remains separate work.
- Resolved ordinary `defined` expressions against the source-visible function-local namespace.
