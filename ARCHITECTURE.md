# holyc-ocaml architecture

The compiler is split into explicit stages. Each stage consumes immutable inputs and returns either a value or structured diagnostics. Sessions own source IDs and configuration; compiler modules do not rely on hidden global state.

Module-level expression binders share one immutable publication cursor. `Sema.Module_binding_environment` validates the mixed module stream, compilation mode, and outer snapshot once. `Sema.Global_binding_environment` adds the checked global-record association: initializer binding advances through the owner, while dimension binding stops immediately before it and advances afterward. Function-default binding advances through the current named header without installing its parameter namespace. These entry points expose their separate source boundaries without evaluating expressions.

The current slice has seven layers:

- `Common` owns source files, byte positions, spans, diagnostics, deterministic rendering, and target-width integer helpers.
- `Frontend` owns token definitions, the audited keyword table, streaming lexical state, canonical include resolution, nested file, definition, and predefined-value frames, `#include`, `#define`, constant `#if` and `#assert` evaluation, mode and symbol conditionals, help-directive metadata, the spanned syntax tree, primitive globals, bound primitive function prototypes, and the implemented top-level statement forms. The declaration parser preserves ordered storage, visibility, and calling modifiers, binding modes, alternate symbol targets, `_intern` expression targets, bounded pointer layers, comma-delimited global groups, global array dimensions, named or unnamed parameters, parameter register qualifiers, recursive function-pointer parameter declarators, prototype punctuation, terminal varargs markers, and optional parameter defaults. Default values, array dimensions, `_intern` targets, and statement conditions use one bounded Pratt parser driven by the audited operator table. Its AST distinguishes literals, identifiers, `$$`, grouping, prefix operations, binary operations, parenthesized and parenthesis-free calls, indexes, direct and pointer members, an absent default, an omitted call slot, and an unsized first array dimension. Statement nodes retain comma-linked sequences, blocks, conditional branches, all three implemented loop headers, `goto`, function labels, `lock`, structural switches, paired `try`/`catch`, `break`, `return`, and source-shaped output shorthand. `goto`, `break`, and `return` keep optional semicolons where the common statement loop accepts a comma boundary, while a `for` update uses a dedicated boundary that stops before `)` without acquiring a semicolon. A label keeps its name and colon, a lock node preserves the region around one recursively parsed statement, a switch node keeps its delimiter mode and ordered case, default, statement, and nested sub-switch elements, a try node preserves both recursive sides of the required pair, and a return node separately retains an absent or parsed value. Parenthesized call suffixes bind before every binary operator and keep their callee, punctuation, provided argument expressions, zero-width omitted slots, and commas. A direct function entry also retains a compact fixed-parameter shape. Without parentheses, that shape adds omitted slots for defaults, parses adjacent expressions for required parameters, and leaves variadic extras absent. Address-of and local or newer nonfunction shadowing prevent this direct-call rewrite. Index suffixes have the same postfix binding and keep their base, brackets, and index tree. Member suffixes share that binding and keep their base, access kind, operator, and identifier. A lexer frame points to its caller, so scanners request only the lookahead bytes they need and can finish a token or trivia item after one or more frame returns. Tokens and trivia store ordered source segments instead of copying the caller suffix into a temporary buffer. The preprocessor expression evaluator uses explicit 64-bit target values and the generated HolyC precedence table. Each preprocessing stream owns its mutable cursors, one-token expression lookahead, conditional stack, current help index, ordered help-file records, selected compilation mode, deterministic date and time settings, command-line source state, generated-byte budget, expression-node budget, and ordered pending diagnostics. The parser keeps a bounded two-token buffer so it can distinguish an unresolved declaration name from `name:` without losing include or definition context. Block, conditional, loop, lock, switch, and try recursion each has an independent 256-level hosted guard. Declaration modifiers, bindings, binding targets, register qualifiers, explicit register names, pointer stars, names, array brackets, delimiters, parentheses, variadic markers, expression operators, member names, and expression terms are explicit AST nodes with their source segments and definition origins. A binding target is an explicit no-target, symbol-target, or expression-target variant. Function-pointer nodes distinguish return pointer layers from declarator indirection and contain the same parameter AST recursively. The parser reads the configured compilation mode before it accepts either import spelling; `_intern` has no corresponding mode gate. The session owns source IDs, the source-ordered definition environment, and a typed view of compiler hash entries. Later parser and semantic work can publish declarations to that view between token requests. It is not the final semantic symbol table.
- `Generated` contains deterministic source facts produced only after pinned checksum and table-shape validation.
- `Sema` exposes primitive type identity, compiler-option metadata, the audited function-flag and member-list-flag models, and a session-owned symbol table. The table assigns stable symbol and scope IDs, represents task, module, function, block, aggregate, and assembler-block contexts, and keeps newest-first entries without discarding older declarations. Kind-filtered lookup can select later matches across an explicit parent chain. The session seeds the 17 internal type spellings from `Compiler/CInit.HC`. `Sema.Declaration_collection` accepts a checked batch of top-level declaration facts, creates one module scope, and records stable entries with their AST positions. `Sema.Aggregate_resolution` gives each forward a distinct identity, completes only the newest same-name unresolved forward, and retains both sites when a definition completes it. `Sema.Type` distinguishes public primitive spellings, intrinsic storage spellings, and aggregate identities with a checked pointer depth; `Sema.Type_reference` adds the checked source spelling and pointer origins shared by later passes. `Sema.Aggregate_header_resolution` records one definition header with its optional backing and base, validates module ownership and source order, and retains token-level provenance. `Sema.Member_collection` associates aggregate definitions with their existing symbols, creates aggregate scopes, and records named direct members with their anonymous-union paths and grouped-declarator positions. `Sema.Member_type_resolution` binds those members to checked source type references, keeps objects and callbacks distinct, reuses the complete recursive function-signature model for callback members, derives a zero mask for objects and `MLF_FUN` for callbacks, and retains array rank and dimension origins without evaluating extents. `Sema.Function_collection` associates prototypes and definitions with their existing symbols, creates function scopes, and records named parameters, synthetic variadic bindings, and automatic or static locals in source order. `Sema.Function_type_resolution` binds return and recursive fixed-parameter signatures, preserves unnamed slots and default provenance, associates named parameter symbols, and derives the five source-backed fixed-parameter flag classes. Top-level `argc` and array-shaped `argv` retain their internal types and each carries exactly `MLF_DOT_DOT_DOT`. `Sema.Local_type_resolution` binds each collected local to a source-visible type and retains its storage, register requests, callback signature, arrays, initializer shape, declaration group, and provenance. `Sema.Function_expression_binding` selects parameters and locals at their publication points, then `Sema.Module_expression_binding` selects the newest source-visible aggregate, function, or global publication while retaining explicit outer candidates. `Sema.Outer_environment` validates immutable JIT task-parent or AOT enclosing-compilation chains that end at the assembler table, and `Sema.Outer_expression_binding` resolves only those remaining candidates. `Sema.Global_initializer_binding` publishes through each owning global, binds scalar and recursively braced initializer names against that module prefix, and falls through to the supplied outer chain. `Sema.Label_resolution` validates a complete function batch before mutation, assigns one stable identity per defined name, and binds language `goto` occurrences to language or structural assembly-block definitions. These passes classify default storage but do not bind or evaluate defaults nested in callback members, resolve casts, `sizeof`, `offset`, expression kinds beyond ordinary identifiers, or assembly operands; construct live task tables; evaluate local or global initializers; calculate storage; allocate registers; or apply ABI rules and completed linkage.
- Local declaration records derive their private `CMemberLst` masks from checked storage and callback shape. This distinguishes ordinary automatic objects, automatic callbacks, static objects, and static callbacks without allowing a caller to inject flags; allocation and address lowering remain later passes.
- `Ir` currently exposes the exhaustive intermediate-code identity and source metadata table. Instructions, control flow, verification, lowering, and execution have not entered this layer yet.
- `Backend` currently exposes the audited TempleOS BIN header, patch-record, relocation, loader-action, and AOT-adjustment specification. It does not contain a serializer, loader, or code emitter yet.
- `Driver` owns compilation sessions, AST-to-semantic orchestration, build identity, and deterministic corpus scans. `Driver.Semantic_collection` translates accepted aggregate, global, and function AST items into the dependency-free semantic batch while preserving lexical order and source provenance. `Driver.Aggregate_resolution` pairs aggregate entries with the same AST by kind, item index, name, and origin before applying the source-order reconciliation rule. `Driver.Aggregate_header_resolution` validates that reconciliation against the same declarations and AST, resolves a backing before publishing the current identity, and resolves a base afterward. `Driver.Member_collection` checks that the same AST supplied the aggregate-definition symbols, flattens recursive anonymous-union fields into the containing namespace, and hands the validated facts to `Sema`. `Driver.Member_type_resolution` then walks aggregate publications in source order, validates the header and member batches, publishes the current canonical identity before its fields, and binds each field's base and pointer layers. `Driver.Function_collection` performs the same association for function declarations, preserves unnamed parameter gaps, synthesizes `argc` and `argv` at the ellipsis, and walks recursive statements without inventing block-local namespaces. `Driver.Function_type_resolution` validates that collection with the same declarations, aggregate identities, and AST; replays canonical aggregate publication in module order; and resolves each return and recursive fixed-parameter signature at its declaration. `Driver.Local_type_resolution` follows the same aggregate timeline, matches every local AST declarator to its collected function symbol, and resolves complete object or callback shapes without changing the table. `Driver.Module_expression_binding` reconciles aggregate, function, global, and function-expression results against the original declarations, then builds one mixed source-order publication stream for immutable lookup. `Driver.Outer_expression_binding` converts the selected frontend mode, validates the supplied outer table chain, and maps low-level semantic failures to stable public errors. `Driver.Global_initializer_binding` validates the global-record batch against the same AST, collects ordinary identifier occurrences from scalar and recursive initializer trees, and retains the path to each nested value. `Driver.Label_resolution` checks the function collection against the same AST, walks every recursive statement route, and records language gotos plus structural assembly-block labels in first-occurrence order. A verified corpus scan checks the reference worktree before and after the run, enumerates the pinned Git tree, and reads committed objects so checkout line endings cannot change its result.

`holyc_lib` exposes the supported high-level entry points. `preprocess_detailed` returns tokens, every diagnostic, and per-stream help metadata so callers can keep nonfatal warnings and compiler annotations together. The older `preprocess` convenience result remains available when only tokens and fatal errors matter. `parse` uses deterministic JIT preprocessing, while `parse_with_config` and `parse_detailed` accept an explicit mode. Ordered `public`, `static`, `interrupt`, `haserrcode`, `argpop`, and `noargpop` prefixes and ordinary, alternate-name, or `_intern` bindings retain their source locations but do not alter linkage, storage, or ABI behavior yet. An alternate binding stores its target as a separate source-linked identifier; `_intern` stores the unevaluated target expression. Either import spelling in JIT mode fails before its declared name is published. Each accepted global is published after its delimiter, and each accepted prototype is published as a function after its semicolon, before the parser requests the next token. A following `#ifdef` can therefore observe either declaration. A detailed parse retains warnings, but any error removes the public AST instead of returning a false success. `collect_declarations` turns that successful AST into one semantic module collection; top-level executable statements add no declaration entry. `resolve_aggregates` validates that collection against the same AST and returns its aggregate identities without mutating or renumbering the symbols. `resolve_aggregate_headers` then binds definition backings and bases at their separate publication points. `collect_members` creates aggregate scopes from the exact collection and AST, and `resolve_member_types` checks those scopes against the declarations, aggregate identities, headers, and AST before binding member type references. `collect_functions` creates function scopes and their parameter and local entries. `resolve_function_types` validates that function collection against the same AST, declarations, and aggregate identities before binding source-positioned return and recursive parameter types. `resolve_function_expressions` binds ordinary occurrences to visible parameters and locals, and `resolve_module_expressions` resolves its remaining candidates through the source-visible compilation-unit records. `create_outer_environment` validates a caller-supplied JIT or AOT chain, and `resolve_outer_expressions` resolves the remaining ordinary candidates through it. `resolve_global_initializers` binds scalar and recursively braced initializer occurrences after the owning global publication. `resolve_labels` binds function-local language gotos and label definitions after checking that the function collection came from the same AST and session. `Symbol_visibility.Environment.human` and `json` serialize the parser-owned environment in stable ID order, with an optional filter that omits the pinned seed while retaining source declarations. The schema preserves generated-source ancestry and compact direct-call shapes but deliberately makes no semantic-resolution claim. `Semantic_symbol_table` separately exposes the semantic identity and lookup substrate, including deterministic `holyc-semantic-symbol-table-v1` human and JSON renderers. No public command presents that table as a checked program yet. `Corpus.lex_reference` returns every per-file lexer result and aggregate byte, token, terminator, and payload count. The command-line program uses the same library paths exercised by the CLI golden tests.

Later frontend work will route nonconstant preprocessor expressions and general `#exe` blocks through semantic analysis, verified IR, and the compile-time VM. The current parser accepts direct and comma-separated primitive globals, global array suffixes, bound primitive prototypes, source-shaped top-level `Print` and `PutChars` shorthand statements, blocks, conditionals, pre-test, post-test, and three-part loops, `goto`, function labels, `lock`, bounded and no-bound switches, paired `try`/`catch`, `break`, and `return`. The statement node keeps its literal marker separate from the complete fixed expression, which matters for empty markers and expression continuations, and keeps trailing `Print` arguments in source order. The `for` node separately retains its initializer, condition separator, optional update, and body. Goto and label nodes preserve syntax, and the semantic label pass binds accepted function-local language gotos to language or structural assembly-block definitions. Assembly operand references, repeated assembly-definition address checks, unused-label warnings, and jump construction remain later work. The lock node preserves a lexical region but does not yet set `ICF_LOCK` or select a hardware prefix. The switch node preserves implicit, single, and ranged cases, `default:`, source order, and nested `start:`/`end:` regions. It does not assign case values, check duplicates, enforce front-porch restrictions, build jump tables, or emit switch ICs. The try node preserves both ordinary statement bodies but does not emit `SysTry` or `SysUntry` calls, track active handlers, or implement exception transfer. The `break` node records syntax only; target validation belongs to semantic control-flow analysis. The `return` node keeps each checked expression result, declared type, integer or `F64` conversion intent, and value-presence warning fact. Function-context diagnostics, active-`try` unwinding, return IR, leave-label control flow, lowering, and execution remain later work. Both `import` and `_import` require AOT mode.

Assembler operand references and direct-assembly labels; member-callback, cast, `sizeof`, and `offset` type resolution; aggregate-member lookup; live task and compiler table construction; alias address resolution; `_intern` evaluation; `lastclass` substitution; expression typing and evaluation; local extent and initializer evaluation; local layout and storage; register allocation; ordinary and implicit call checking; remaining syntax; semantic checking; executable IR; interpretation; optimization; assembly; hosted code generation; and TempleOS module emission follow in separate changes. A stage enters the supported list only after its verifier boundary and focused tests exist.

## Function and global expression binding

`Sema.Function_binding_index` consumes the checked function collection, function signatures, and local declaration types. It validates one completed namespace per prototype or definition, rejects ordinary repeated names, retains the exact `pad`, `reserved`, and `_anon_` exceptions, and returns source-ordered immutable lookup data without changing use counts. `Driver.Function_binding_index` verifies that all three semantic batches own the same stable symbols and scopes. The public `index_function_bindings` entry point exposes this boundary after `resolve_function_types` and `resolve_local_types`.

`Driver.Function_expression_binding` then walks ordinary function-body expressions in parser order. Parameters and synthetic variadic bindings enter the initial environment. A declarator's array dimensions are visited before its local is published, while its initializer is visited afterward. Publication is function-wide and permanent for the remaining source, so leaving a block does not hide the local. `Sema.Function_expression_binding` validates those events against the completed index and returns every occurrence as either a selected function binding or an explicit nonlocal candidate. Member names, type syntax, `sizeof`, `offset`, `defined`, labels, and assembly tokens stay outside this pass. The public `resolve_function_expressions` entry point is read-only.

`Driver.Module_expression_binding` next reconciles aggregate and function identities plus global records with the original declaration stream. `Sema.Module_expression_binding` publishes those mixed records through each function header and resolves only the remaining candidates. Local bindings keep precedence. Aggregate and function sites keep both source and canonical identities, globals keep their record identity, and names absent from the compilation unit stay explicit outer candidates. The public `resolve_module_expressions` entry point is read-only.

`Sema.Outer_environment` represents the rest of `CHashTable.next` as validated, immutable table snapshots. A JIT chain contains the current task at depth zero, zero or more parent tasks, and one final assembler table. An AOT chain contains zero or more enclosing compilations followed by one assembler table, so top-level AOT has no task table. Entries arrive oldest to newest, and each table indexes the final same-name record without flattening table precedence. `Sema.Outer_expression_binding` preserves local and module results, resolves only explicit outer candidates, and returns the selected stable symbol plus table and record provenance. `HCSEMA0022` rejects malformed chains, `HCSEMA0023` rejects mismatched semantic inputs, and `HCSEMA0024` rejects an ordinary name missing from the complete chain. The public `create_outer_environment` and `resolve_outer_expressions` entry points are read-only. Live task construction, addresses, alternate binding targets, imports, fixups, expression-kind validation, use counts, member resolution, typing, storage, register allocation, lowering, and ABI behavior remain later stages.

`Sema.Module_binding_environment` combines the mixed module publication stream with one checked outer snapshot and exposes cursors immediately before or through a selected record. `Driver.Function_default_binding` pairs top-level named function headers with resolved declaration sites and collects ordinary identifier expressions from each fixed-parameter default. `Sema.Function_default_binding` publishes through the current header, searches the visible module prefix before the outer chain, and deliberately omits the function parameter namespace. It retains the source declaration, joined canonical identity, parameter and occurrence positions, and generated-source provenance. `lastclass` stays on the resolved parameter as a separate marker and contributes no ordinary occurrence. `HCSEMA0029` rejects inconsistent cross-pass input; `HCSEMA0030` reports a name absent from both lookup stages. The public `resolve_function_defaults` entry point is deterministic and read-only. It does not evaluate or substitute a default, compare headers, check calls, or traverse defaults nested inside callback declarators.

`Compiler/PrsStmt.HC:PrsGlblVarLst` calls `HashAdd` for a new global record before it calls `PrsGlblInit`. `Sema.Global_initializer_binding` therefore advances the same mixed module publication stream through the owning record before resolving its initializer. Self references and earlier comma declarators are visible; later declarators and module items are not. A missing module spelling continues through the caller-supplied JIT or AOT outer environment. `Driver.Global_initializer_binding` visits ordinary identifiers in scalar and recursive braced values, preserves a zero-based path through nested elements, and excludes member suffix names. `HCSEMA0025` rejects inconsistent semantic inputs, and `HCSEMA0026` reports an ordinary name missing from both visible module records and the complete outer chain. The public `resolve_global_initializers` entry point is deterministic and read-only. It does not type, evaluate, convert, store, lower, or execute an initializer.

`Sema.Global_binding_environment` extends the shared cursor with the checked global-record sequence. Array dimensions resolve with the cursor immediately before their owner, then publish that owner for the following declarator. `Driver.Global_dimension_binding` validates every suffix against the resolved global type, retains an empty first dimension, and assigns one occurrence order across a multidimensional declarator. The public `resolve_global_dimensions` entry point does not evaluate an extent, convert a target value, assign storage, or change layout.

## Source authority

TempleOS source at `c26482bb6ad3f80106d28504ec5db3c6a360732c` is authoritative when prose and implementation disagree. `reference/traceability.toml` links each claimed behavior to the pinned function or table, implementation files, and tests.

## Determinism

Byte offsets and source order are preserved. Reports sort data only when source order has no meaning. Version output always names the pinned reference commit. Tests override data that could depend on clocks, locale, process IDs, or temporary directories.
