# holyc-ocaml architecture

The compiler is split into explicit stages. Each stage consumes immutable inputs and returns either a value or structured diagnostics. Sessions own source IDs and configuration; compiler modules do not rely on hidden global state.

The current slice has seven layers:

- `Common` owns source files, byte positions, spans, diagnostics, deterministic rendering, and target-width integer helpers.
- `Frontend` owns token definitions, the audited keyword table, streaming lexical state, canonical include resolution, nested file, definition, and predefined-value frames, `#include`, `#define`, constant `#if` and `#assert` evaluation, mode and symbol conditionals, help-directive metadata, the spanned syntax tree, primitive globals, bound primitive function prototypes, and the implemented top-level statement forms. The declaration parser preserves ordered storage, visibility, and calling modifiers, binding modes, alternate symbol targets, `_intern` expression targets, bounded pointer layers, comma-delimited global groups, global array dimensions, named or unnamed parameters, parameter register qualifiers, recursive function-pointer parameter declarators, prototype punctuation, terminal varargs markers, and optional parameter defaults. Default values, array dimensions, `_intern` targets, and statement conditions use one bounded Pratt parser driven by the audited operator table. Its AST distinguishes literals, identifiers, `$$`, grouping, prefix operations, binary operations, parenthesized and parenthesis-free calls, indexes, direct and pointer members, an absent default, an omitted call slot, and an unsized first array dimension. Statement nodes retain comma-linked sequences, blocks, conditional branches, all three implemented loop headers, `goto`, function labels, `lock`, structural switches, paired `try`/`catch`, `break`, `return`, and source-shaped output shorthand. `goto`, `break`, and `return` keep optional semicolons where the common statement loop accepts a comma boundary, while a `for` update uses a dedicated boundary that stops before `)` without acquiring a semicolon. A label keeps its name and colon, a lock node preserves the region around one recursively parsed statement, a switch node keeps its delimiter mode and ordered case, default, statement, and nested sub-switch elements, a try node preserves both recursive sides of the required pair, and a return node separately retains an absent or parsed value. Parenthesized call suffixes bind before every binary operator and keep their callee, punctuation, provided argument expressions, zero-width omitted slots, and commas. A direct function entry also retains a compact fixed-parameter shape. Without parentheses, that shape adds omitted slots for defaults, parses adjacent expressions for required parameters, and leaves variadic extras absent. Address-of and local or newer nonfunction shadowing prevent this direct-call rewrite. Index suffixes have the same postfix binding and keep their base, brackets, and index tree. Member suffixes share that binding and keep their base, access kind, operator, and identifier. A lexer frame points to its caller, so scanners request only the lookahead bytes they need and can finish a token or trivia item after one or more frame returns. Tokens and trivia store ordered source segments instead of copying the caller suffix into a temporary buffer. The preprocessor expression evaluator uses explicit 64-bit target values and the generated HolyC precedence table. Each preprocessing stream owns its mutable cursors, one-token expression lookahead, conditional stack, current help index, ordered help-file records, selected compilation mode, deterministic date and time settings, command-line source state, generated-byte budget, expression-node budget, and ordered pending diagnostics. The parser keeps a bounded two-token buffer so it can distinguish an unresolved declaration name from `name:` without losing include or definition context. Block, conditional, loop, lock, switch, and try recursion each has an independent 256-level hosted guard. Declaration modifiers, bindings, binding targets, register qualifiers, explicit register names, pointer stars, names, array brackets, delimiters, parentheses, variadic markers, expression operators, member names, and expression terms are explicit AST nodes with their source segments and definition origins. A binding target is an explicit no-target, symbol-target, or expression-target variant. Function-pointer nodes distinguish return pointer layers from declarator indirection and contain the same parameter AST recursively. The parser reads the configured compilation mode before it accepts either import spelling; `_intern` has no corresponding mode gate. The session owns source IDs, the source-ordered definition environment, and a typed view of compiler hash entries. Later parser and semantic work can publish declarations to that view between token requests. It is not the final semantic symbol table.
- `Generated` contains deterministic source facts produced only after pinned checksum and table-shape validation.
- `Sema` exposes primitive type identity, compiler-option metadata, the audited function-flag model, and a session-owned symbol table. The table assigns stable symbol and scope IDs, represents task, module, function, block, aggregate, and assembler-block contexts, and keeps newest-first entries without discarding older declarations. Kind-filtered lookup can select later matches across an explicit parent chain. The session seeds the 17 internal type spellings from `Compiler/CInit.HC`. `Sema.Declaration_collection` accepts a checked batch of top-level declaration facts, creates one module scope, and records stable entries with their AST positions. `Sema.Aggregate_resolution` gives each forward a distinct identity, completes only the newest same-name unresolved forward, and retains both sites when a definition completes it. `Sema.Member_collection` associates aggregate definitions with their existing symbols, creates aggregate scopes, and records named direct members with their anonymous-union paths and grouped-declarator positions. `Sema.Function_collection` associates prototypes and definitions with their existing symbols, creates function scopes, and records named parameters, synthetic variadic bindings, and automatic or static locals in source order. `Sema.Label_resolution` validates a complete function batch before mutation, assigns one stable identity per defined name, and binds language `goto` occurrences to language or structural assembly-block definitions. These passes do not reconcile functions or globals, resolve named-type uses or inheritance, calculate layout or storage, apply linkage, or resolve ordinary expression and assembly operand references.
- `Ir` currently exposes the exhaustive intermediate-code identity and source metadata table. Instructions, control flow, verification, lowering, and execution have not entered this layer yet.
- `Backend` currently exposes the audited TempleOS BIN header, patch-record, relocation, loader-action, and AOT-adjustment specification. It does not contain a serializer, loader, or code emitter yet.
- `Driver` owns compilation sessions, AST-to-semantic orchestration, build identity, and deterministic corpus scans. `Driver.Semantic_collection` translates accepted aggregate, global, and function AST items into the dependency-free semantic batch while preserving lexical order and source provenance. `Driver.Aggregate_resolution` pairs aggregate entries with the same AST by kind, item index, name, and origin before applying the source-order reconciliation rule. `Driver.Member_collection` checks that the same AST supplied the aggregate-definition symbols, flattens recursive anonymous-union fields into the containing namespace, and hands the validated facts to `Sema`. `Driver.Function_collection` performs the same association for function declarations, preserves unnamed parameter gaps, synthesizes `argc` and `argv` at the ellipsis, and walks recursive statements without inventing block-local namespaces. `Driver.Label_resolution` checks that collection against the same AST, walks every recursive statement route, and records language gotos plus structural assembly-block labels in first-occurrence order. A verified corpus scan checks the reference worktree before and after the run, enumerates the pinned Git tree, and reads committed objects so checkout line endings cannot change its result.

`holyc_lib` exposes the supported high-level entry points. `preprocess_detailed` returns tokens, every diagnostic, and per-stream help metadata so callers can keep nonfatal warnings and compiler annotations together. The older `preprocess` convenience result remains available when only tokens and fatal errors matter. `parse` uses deterministic JIT preprocessing, while `parse_with_config` and `parse_detailed` accept an explicit mode. Ordered `public`, `static`, `interrupt`, `haserrcode`, `argpop`, and `noargpop` prefixes and ordinary, alternate-name, or `_intern` bindings retain their source locations but do not alter linkage, storage, or ABI behavior yet. An alternate binding stores its target as a separate source-linked identifier; `_intern` stores the unevaluated target expression. Either import spelling in JIT mode fails before its declared name is published. Each accepted global is published after its delimiter, and each accepted prototype is published as a function after its semicolon, before the parser requests the next token. A following `#ifdef` can therefore observe either declaration. A detailed parse retains warnings, but any error removes the public AST instead of returning a false success. `collect_declarations` turns that successful AST into one semantic module collection; top-level executable statements add no declaration entry. `resolve_aggregates` validates that collection against the same AST and returns its aggregate identities without mutating or renumbering the symbols. `collect_members` creates aggregate scopes from the exact collection and AST, while `collect_functions` creates function scopes and their parameter and local entries. `resolve_labels` binds function-local language gotos and label definitions after checking that the function collection came from the same AST and session. `Symbol_visibility.Environment.human` and `json` serialize the parser-owned environment in stable ID order, with an optional filter that omits the pinned seed while retaining source declarations. The schema preserves generated-source ancestry and compact direct-call shapes but deliberately makes no semantic-resolution claim. `Semantic_symbol_table` separately exposes the semantic identity and lookup substrate, including deterministic `holyc-semantic-symbol-table-v1` human and JSON renderers. No public command presents that table as a checked program yet. `Corpus.lex_reference` returns every per-file lexer result and aggregate byte, token, terminator, and payload count. The command-line program uses the same library paths exercised by the CLI golden tests.

Later frontend work will route nonconstant preprocessor expressions and general `#exe` blocks through semantic analysis, verified IR, and the compile-time VM. The current parser accepts direct and comma-separated primitive globals, global array suffixes, bound primitive prototypes, source-shaped top-level `Print` and `PutChars` shorthand statements, blocks, conditionals, pre-test, post-test, and three-part loops, `goto`, function labels, `lock`, bounded and no-bound switches, paired `try`/`catch`, `break`, and `return`. The statement node keeps its literal marker separate from the complete fixed expression, which matters for empty markers and expression continuations, and keeps trailing `Print` arguments in source order. The `for` node separately retains its initializer, condition separator, optional update, and body. Goto and label nodes preserve syntax, and the semantic label pass binds accepted function-local language gotos to language or structural assembly-block definitions. Assembly operand references, repeated assembly-definition address checks, unused-label warnings, and jump construction remain later work. The lock node preserves a lexical region but does not yet set `ICF_LOCK` or select a hardware prefix. The switch node preserves implicit, single, and ranged cases, `default:`, source order, and nested `start:`/`end:` regions. It does not assign case values, check duplicates, enforce front-porch restrictions, build jump tables, or emit switch ICs. The try node preserves both ordinary statement bodies but does not emit `SysTry` or `SysUntry` calls, track active handlers, or implement exception transfer. The `break` node records syntax only; target validation belongs to semantic control-flow analysis. The `return` node likewise defers function-context checks, value typing, active-`try` unwinding, function metadata, leave-label control flow, lowering, and execution. Both `import` and `_import` require AOT mode.

Assembler operand references and direct-assembly labels; parameter and local type resolution; target lookup; alias resolution; `_intern` evaluation; `lastclass` substitution; expression evaluation; layout and storage; ordinary and implicit call resolution; remaining syntax; semantic checking; executable IR; interpretation; optimization; assembly; hosted code generation; and TempleOS module emission follow in separate changes. A stage enters the supported list only after its verifier boundary and focused tests exist.

## Source authority

TempleOS source at `c26482bb6ad3f80106d28504ec5db3c6a360732c` is authoritative when prose and implementation disagree. `reference/traceability.toml` links each claimed behavior to the pinned function or table, implementation files, and tests.

## Determinism

Byte offsets and source order are preserved. Reports sort data only when source order has no meaning. Version output always names the pinned reference commit. Tests override data that could depend on clocks, locale, process IDs, or temporary directories.
