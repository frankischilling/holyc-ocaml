# Reference source map

All findings in this document refer to TempleOS commit `c26482bb6ad3f80106d28504ec5db3c6a360732c`.

## Compiler assembly order

`Compiler/Compiler.PRJ` includes kernel headers first, enables conversion of extern declarations to imports while loading later kernel headers, and then loads compiler units in this order: templates, extensions, initialization, exceptions, lexer, hashes, assembler, parser, optimizer, backend, and final optimization passes. The OCaml architecture keeps the same conceptual dependencies without copying the source's global-state layout.

## Lexer state

`Kernel/KernelA.HH` defines `CLexFile` and `CCmpCtrl`. `Compiler/Lex.HC:LexFilePush` maintains the lexical frame stack, while `LexGetChar` owns one-byte pushback and line tracking. Root depth is -1 and the first pushed frame has depth 0. `LexBackupLastChar` saves the caller cursor and one-character lookahead before a push; `LexGetChar` restores that state and continues without an intermediate EOF after a buffer ends. This return can happen while `Lex` is still scanning one token or trivia item. The OCaml source model stores each full byte buffer and its precomputed line starts, links its lexer cursor to the caller cursor, and records the consumed ranges as ordered spans. Each `Lexer_frame` also retains its kind and relevant include, definition, or predefined-value provenance. Hosted include and generated-text depth are tracked separately.

`Kernel/StrA.HC` shows that the lexer is byte oriented. Identifier starts include ASCII letters, underscore, at sign, and bytes 128 through 255. Digits are accepted after the first byte. The hosted lexer preserves non-ASCII bytes rather than requiring UTF-8.

`LexGetChar` treats byte zero as the end of its current buffer. Several committed `.HC` files place an inserted binary payload after that terminator. The corpus lexer enables this behavior explicitly and records the terminator offset and trailing byte count. The ordinary hosted lexer keeps its stricter embedded-NUL diagnostic for untrusted standalone source.

The `KW_DEFINE` replacement loop removes backslash followed by LF or CR, including CRLF. `Compiler/LexLib.HC:LexExtStr` also consumes an immediate backslash before it asks the normal lexer for the next string. `Kernel/KernelA.HH` uses the first form in continued definitions, and `Kernel/KernelC.HH` uses the second form in help metadata. The raw lexer retains these newline forms as `line-continuation` trivia. A backslash without a following line ending remains an invalid source byte.

## Include paths and source frames

The `KW_INCLUDE` branch in `Compiler/Lex.HC:Lex` requires a string token, calls `ExtDft` with `HC.Z`, resolves the result through `FileNameAbs`, and pushes the file with `LexIncludeStr`. `Doc/PreProcessor.DD` rules out a C-style angle-bracket form.

`Kernel/BlkDev/DskStrA.HC:FileNameAbs` delegates to `DirNameAbs`, which starts relative paths from `Fs->cur_dir`; it does not consult the including file's directory. `DirNameAbs` handles root, `::`, home, drive, dot, and parent components. `ExtDft` adds its default only when no extension is present.

`Frontend.Include_resolver` preserves that working-directory rule and adds ordered hosted include roots. `Frontend.Lexer_frame` retains the active canonical path, display spelling, source ID, cursor, include origin, caller, and source depth. `Frontend.Preprocessor` pushes the resolved source and allows the active scanner to continue into the caller when the included bytes end. It labels canonical root confinement, cycle checks, and depth and byte caps as hosted security behavior because the pinned lexer does not provide those rejections. [The preprocessor notes](preprocessor.md) record the command, diagnostics, and current directive boundary.

## Definition capture and expansion

The `KW_DEFINE` branch in `Compiler/Lex.HC:Lex` sets `CCF_NO_DEFINES` before reading the name. It then skips only space, tab, and byte `0x1f`, as established by `char_bmp_non_eol_white_space` in `Kernel/StrA.HC`. Replacement capture retains raw bytes, removes LF and CRLF continuations, recognizes `//` only outside double quotes, and leaves block comments for the replacement's later lexical pass. Empty and EOF-terminated definitions are valid.

`CHashDefineStr` in `Kernel/KernelA.HH` stores the name, text, source location, and `cnt = -1`. `Compiler/CHash.HC` and `Kernel/KDefine.HC` provide the related definition APIs. `Kernel/KHashA.HC:HashAdd` inserts at the front of a bucket and `HashFind` returns the first match, which makes the newest same-name definition visible while older entries remain allocated.

Identifier recognition in `Compiler/Lex.HC:Lex` checks `HTT_DEFINE_STR` before it returns a token. A match calls `LexIncludeStr` with a copy of the stored text and marks the pushed `CLexFile` with `LFSF_DEFINE`. `Compiler/CExcept.HC:ParenWarning` and `Compiler/PrsExp.HC` inspect that flag, so the OCaml frame model keeps definitions distinct from physical includes for later parser work.

`Frontend.Definition` assigns source-ordered identities, retains replacement spans and byte-segment maps, and keeps both current lookup state and redefinition history. `Driver.Session` owns that environment because the native `CmpCtrlNew` points definition lookup at the task hash table. `Frontend.Preprocessor` creates a logical source for each expansion, adds invocation and declaration provenance to tokens and diagnostics, and leaves the caller available to the same lexical scan at replacement EOF. Active-definition cycle checks and definition depth and byte budgets are hosted security rules; the pinned lexer has no equivalent guard.

## Predefined compiler values

`Kernel/KernelA.HH:2035-2043` defines `__DATE__`, `__TIME__`, `__LINE__`, `__CMD_LINE__`, `__FILE__`, and `__DIR__` as definition strings containing narrow `#exe` bodies. `Doc/Directives.DD` publishes the same six definitions. The line and file forms read the active lexical frame. The command-line form also requires `CCF_CMD_LINE` and a source depth below one. `Compiler/Lex.HC:LexFilePush` establishes root depth -1 and the first included depth 0.

`Compiler/CMisc.HC:StreamDir` calls `DirFile` on the active `full_name` and injects a quoted string through `StreamPrint`. `Kernel/StrPrint.HC:MPrintDate` renders `%D` as `MM/DD/YY`, while `MPrintTime` renders `%T` as `HH:MM:SS`.

`Frontend.Predefined` keeps those six spellings and recognizes their exact standard bodies by comparing raw token sequences. Whitespace may differ without allowing separate tokens to fuse. `Frontend.Preprocessor` expands each value into a bounded generated lexical frame with invocation provenance. An exact source definition retains its declaration span; a different source definition with the same name remains ordinary replacement text. Date and time come from explicit deterministic configuration. File and directory results use canonical hosted paths, so compatibility reports do not claim byte equality with TempleOS drive names. General `#exe` execution remains future compile-time VM work.

## Help directives and source links

The `KW_HELP_INDEX` branch in `Compiler/Lex.HC:Lex` replaces `CCmpCtrl.cur_help_idx` with one string. `Compiler/LexLib.HC:LexExtStr` receives `lex_next=FALSE`, so it joins more text only through an immediate backslash followed by another string token. `Kernel/KernelC.HH:195-196` contains the pinned continuation example. An empty string remains stored on the controller, but `HashSrcFileSet` treats it as no active index.

The `KW_HELP_FILE` branch applies `ExtDft(...,"DD.Z")`, passes the result to `FileNameAbs`, creates a public `HTT_HELP_FILE` source symbol, and calls `HashSrcFileSet`. `Kernel/BlkDev/DskStrA.HC:FileExtDot` establishes the extension rule. `FileNameAbs` and `DirNameAbs` establish default-directory, root, drive, dot, and parent handling. Their call to `Kernel/StrA.HC:StrUtil` removes leading and trailing whitespace and other control bytes as documented in the preprocessor notes. `Kernel/KHashB.HC:HashSrcFileSet` writes `FL:<full_name>,<line>` and copies a nonempty current index.

`Frontend.Help_metadata` keeps source-ordered index events and help-file records. `Frontend.Preprocessor` attaches source spans, include stacks, and definition traces, while `Frontend.Include_resolver.resolve_metadata` produces a confined hosted path without reading the named file. `holyc preprocess --dump-help-metadata` emits the versioned report. The pinned `Kernel/KernelC.HH` test observes all 104 index directives and 20 help-file directives with no diagnostic. Semantic hash insertion and DolDoc loading remain outside this slice.

## JIT and AOT conditional selection

`Kernel/KernelA.HH` defines `CCF_AOT_COMPILE` at bit 35. `Compiler/CMain.HC:CmpBuf` sets the flag before it joins an AOT compilation, while a normal controller starts without it. The OCaml preprocessor mirrors that distinction with an explicit `Jit` or `Aot` configuration and defaults to JIT. Host operating-system details do not affect the selection.

The `KW_IFAOT` and `KW_IFJIT` cases in `Compiler/Lex.HC:Lex` continue into the matching branch. A false condition scans with `LexGetChar` until the first depth-one `#else` or its `#endif`. Nested depth increases for all five opener spellings: `#if`, `#ifdef`, `#ifndef`, `#ifaot`, and `#ifjit`. The scan calls `Lex` only after it sees `#`, so ordinary discarded identifiers do not expand and inactive includes or definitions do not run. `PrsKeyWord` reads the resolved hash entry, which also permits a definition to supply the directive name.

`LexGetChar` removes exhausted include and definition frames during the search. `Frontend.Preprocessor` therefore owns conditional state above individual `Lexer_frame` values, and `Frontend.Lexer.scan_to_directive_marker` advances through inactive bytes without ordinary tokenization. A conditional can open in an included or definition-backed frame and close after that frame returns to its caller.

Outside `CCF_IN_IF`, the pinned lexer discards an unmatched `#endif`, treats an unmatched `#else` as a request to scan forward, and returns EOF without a mismatch diagnostic when a false branch is unterminated. The hosted stream reports `HCPP0015` through `HCPP0018` instead. [Issue #27](https://github.com/frankischilling/holyc-ocaml/issues/27) records that diagnostic difference and the missing oracle fixtures. The `KW_IFJIT` path also returns `TK_IFAOT` while `CCF_IN_IF` is set; that source quirk concerns later `#if` expression parsing and is not part of the mode-only state.

## Symbol-presence conditionals

The `KW_IFDEF` and `KW_IFNDEF` branches in `Compiler/Lex.HC:Lex` set `CCF_NO_DEFINES` while they read one identifier. Identifier lookup still finds the matching hash entry, but a definition's replacement text does not enter the stream. `#ifdef` continues when `cc->hash_entry` is non-null; `#ifndef` continues when it is null.

`CmpCtrlNew` initializes `hash_mask` to `HTG_TYPE_MASK-HTT_IMPORT_SYS_SYM`. The 17 `HTT_*` bits in `Kernel/KernelA.HH` show that this is a compiler-symbol predicate rather than a definition-only predicate. Imports are excluded. `Compiler/CMain.HC:LexStmt2Bin` builds the local and global table chain for the current compilation mode. Before that hash lookup, `Lex` calls `MemberFind` against `local_var_lst`; a local match suppresses `HashFind` and leaves `hash_entry` null.

`Compiler/AsmInit.HC:AsmHashLoad` inserts language keywords, assembly keywords, opcodes, registers, and all 17 records from `Compiler/CInit.HC:internal_types_table` into `cmp.asm_hash`. `Driver.Session` seeds every one of those static compiler names from checked generated data. `Frontend.Symbol_visibility` models every hash kind, masked lookup, and local shadows with deterministic identities and source provenance. The parser can publish later declarations to the same environment between calls to `Frontend.Preprocessor.next`.

The generated seed contains 48 language keywords, 25 assembly keywords, 17 internal types, 106 registers, 325 canonical opcodes, and 49 opcode aliases. The standalone preprocessor still cannot discover unparsed HolyC declarations. The source corpus has no active `#ifdef` or `#ifndef` occurrence, so focused fixtures establish this slice's behavior.

## Conditional and assertion expressions

The `KW_IF` branch in `Compiler/Lex.HC:Lex` sets `CCF_IN_IF`, reads one token, and calls `LexExpression`. It treats the returned 64 bits as the branch predicate and leaves the token following the expression in the ordinary lexer lookahead. `KW_ASSERT` uses the same evaluator but reports a warning when the result is false.

The assertion branch calls `LexWarn(cc,"Assert Failed ")` and then returns through `lex_end`. `Compiler/CExcept.HC:LexWarn` increments `warning_cnt` without incrementing `error_cnt` or throwing. `Frontend.Preprocessor` therefore queues `HCPP0024` as a warning, while `preprocess_detailed` returns that warning beside the retained tokens and the CLI exits successfully. TempleOS prints the warning at the current lookahead token. The hosted renderer instead uses the directive span and records the lookahead as related context; the compatibility report identifies that diagnostic-only difference.

`Compiler/PrsExp.HC:LexExpression2Bin` calls the normal expression parser, appends return operations, compiles the resulting intermediate code, and returns executable memory. `LexExpression` calls that code without forcing the result to I64 or F64. Native conditions can therefore use any expression term available to the current compiler controller, including calls, globals, memory, and compiler state. The hosted constant evaluator implements only the terms that do not need semantic state or execution. [Issue #33](https://github.com/frankischilling/holyc-ocaml/issues/33) records the remaining VM path.

`PrsExpression2` obtains binary identity, precedence, and association from `cmp.binary_ops`. `Compiler/CInit.HC:CmpFillTables` puts power and shifts in `PREC_EXP`, marks power right associated, and leaves shifts left associated. The parser moves unary minus below power unless parentheses force the negative value to become the base. Consecutive comparison operations use `IC_PUSH_CMP` and combine adjacent comparisons. `Compiler/OptPass012.HC` establishes the constant integer, floating, comparison, and logical behavior used by the hosted evaluator. Its result-class assignments make complement and integer shifts I64. Its immediate folding converts U64-class bits to F64 through the signed I64 field, compares F64 equality by raw bits, and retains an F64 result for unary `!`. Logical operations consume both operands rather than introducing a C-preprocessor short-circuit rule.

`PrsUnaryTerm` handles `defined` without setting `CCF_NO_DEFINES`, so ordinary definition expansion may replace its operand first. This is intentionally different from the `KW_IFDEF` and `KW_IFNDEF` paths. A local variable makes `defined` true, while it suppresses hash lookup and makes `#ifdef` false. The default hash mask still excludes imports.

`Frontend.Conditional_expression` parses with the checked operator records, stores explicit I64, U64, and F64 values, and returns its first unconsumed token. `Frontend.Preprocessor` owns the one-token lookahead so selected body text and adjacent conditional boundaries survive expression parsing. The hosted node limit, stable arithmetic diagnostics, and inert recovery after an invalid condition are project safety rules rather than native TempleOS behavior.

## Tokens and operators

`Kernel/KernelA.HH` assigns numeric values to compound tokens. `Compiler/CInit.HC:CmpFillTables` defines two-character tokens, three-character shifts, and expression precedence. `Compiler/OpCodes.DD` supplies the keyword spellings consumed by `Compiler/AsmInit.HC`.

Generated tables retain the complete language keyword list and operator spellings. Numeric TempleOS token IDs remain available for audit and deterministic dumps, while OCaml variants provide compiler identity after lexing.

## Operator recognition and precedence

`CmpFillTables` builds three `dual_U16_tokens` arrays. `Lex` checks them in order. The first array recognizes spellings such as `!=`, `&&`, `*=`, `++`, and `->`; the second handles alternatives with the same first byte, including `&=`, `--`, `<<`, and `^^`; the third supplies `-=` and `/=`. The `/` entries for `/*` and `//` have no token result because they enter nested block-comment or line-comment handling.

Shift assignments are not ordinary entries in those arrays. After recognizing `<<` or `>>`, `Lex` reads one more byte and changes the token when it sees `=`. Dot handling similarly distinguishes a floating literal, `.`, `..`, and `...`. The `$$` form comes from the lexer's dollar handling and has no `TK_*` compound-token ID.

`cmp.binary_ops` contains 31 records. Each record combines a precedence constant and any explicit association flag in the high half with an IC number in the low half. Some entries, including multiplication and addition, have no association flag in the source. `Frontend.Operator` exposes that state as `Unspecified` instead of assigning a conventional default.

`Doc/HolyC.DD` lists the same precedence bands but omits `%=` from its assignment line. `Compiler/CInit.HC` includes `TK_MOD_EQU` mapped to `IC_MOD_EQU`, so the generated source follows the compiler table and records the prose omission as a documentation difference.

`tools/operator_table_source.ml` validates token IDs, association flags, precedence constants, every dual sequence, required IC numbers, all binary mappings, and the lexer-only forms. `tools/operator_table_gen.ml` writes their source lines and the four pinned checksums to `src/generated/operator_tables.ml`. Expression parsing remains outside this slice.

## Opcode database records

`Compiler/AsmInit.HC:AsmHashLoad` parses `Compiler/OpCodes.DD` with the compiler lexer. Register statements select one of eight register kinds and pair a spelling with a numeric register value. `KEYWORD` and `ASM_KEYWORD` statements each contain a spelling and integer ID. An `OPCODE` statement contains one canonical spelling, up to 32 implicitly delimited instruction forms, an optional colon-led alias list, and a final semicolon.

`AsmPrsInsFlags` accepts the eight opcode modifiers, operand-size markers 16 and 32, `+` and `/` selectors, eight punctuation flags, and `$$`. Each form has no more than four opcode bytes and two `ST_ARG_TYPES` operands. Argument sizes come from the five masks initialized by `AsmHashLoad`. The pinned file contains 106 registers, 48 language keywords with IDs 0 through 47, 25 assembler directives with IDs 64 through 88, 325 canonical opcodes, 49 aliases, and 924 forms. The leading comma on `REP_OUTSB` causes the source loader to create an empty first form; the checked data keeps it.

`tools/opcode_table_source.ml` tokenizes and validates that complete grammar. It rejects missing semicolons, duplicate names or IDs, unexpected and reordered records, incomplete keyword ranges, malformed aliases, unknown arguments, out-of-range numeric fields, excess bytes, and excess forms. `tools/opcode_table_gen.ml` writes the deterministic OCaml table with the reference commit, `Compiler/OpCodes.DD` checksum, original source lines, and every parsed field. The lexer and `Asm_directive` use the keyword subsets, while `Driver.Session` publishes registers, canonical opcodes, and aliases with their source hash kinds. [The assembler notes](assembler.md) give the field-level map. Operand matching and encoding remain future assembler work.

## Primitive raw types and internal names

`Kernel/KernelA.HH` assigns raw IDs 2 through 15. The low bit is `RTF_UNSIGNED`; `RT_PTR` deliberately aliases signed `RT_I64` at ID 10. The same block marks `RT_F32` as unimplemented, `RT_UF32` as unimplemented and fictitious, and `RT_UF64` as fictitious. These slots remain visible in generated audit data but are not semantic HolyC primitive constructors.

`Compiler/CInit.HC:internal_types_table` contains 17 records. Several raw IDs have more than one name. In particular, `Bool` shares `RT_I8`, while the names ending in `i` provide internal storage for public declarations. `Compiler/AsmInit.HC:AsmHashLoad` inserts every record into the compiler hash and leaves the final record for each raw ID in `cmp.internal_types`.

The public `I16`, `U16`, `I32`, `U32`, `I64`, and `U64` names are unions declared near the start of `Kernel/KernelA.HH`. Their leading internal type names select whole-value storage, while their members expose smaller signed and unsigned views. `Primitive_type` records this union-backed declaration form but does not calculate member layout yet.

`tools/primitive_type_source.ml` validates the constants, the six union headers, and every internal record. `tools/primitive_type_gen.ml` embeds the pinned commit, both source checksums, and original line numbers in `src/generated/primitive_raw_types.ml`. `Sema.Primitive_type` uses those records for the 12 supported semantic identities.

## Primitive declarations and core call expressions

`Compiler/PrsStmt.HC:PrsStmt` checks whether a top-level identifier resolves to `HTT_CLASS` or `HTT_INTERNAL_TYPE`. It advances past that type token and calls `PrsGlblVarLst`. `Compiler/PrsStmt.HC:PrsGlblVarLst` repeatedly calls `Compiler/PrsVar.HC:PrsType`, accepts a comma for another declarator, and otherwise requires and consumes a semicolon. `Compiler/CMain.HC:CmpJoin` calls the statement path repeatedly, preserving top-level source order without requiring `main`.

Before type dispatch, `PrsStmt` recognizes `KW_PUBLIC`, `KW_STATIC`, `KW_INTERRUPT`, `KW_HASERRCODE`, `KW_ARGPOP`, and `KW_NOARGPOP`. `Compiler/CompilerA.HH` assigns the calling keywords IDs 44 through 47 and maps their staging bits directly to `Ff_INTERRUPT` through `Ff_NOARGPOP`. The calling cases retain the existing `FSG_FUN_FLAGS2` group plus assembly state, and the interrupt case adds `FSF_NOARGPOP`. The `public` case follows the same preservation rule. The `static` case retains assembly state while clearing the other staged bits. `PrsFunJoin` copies only `FSG_FUN_FLAGS1` into stored function flags, while `PrsGlblVarLst` separately checks public state when it publishes a name. `Frontend.Parser` keeps each modifier token as an ordered, source-linked AST node. Parser tests reproduce the staging transitions with `Sema.Function_flag.apply_modifier`; parsing does not apply export, linkage, storage, interrupt, or argument-cleanup behavior.

After those modifiers, `PrsStmt` recognizes ordinary `KW_EXTERN` and `KW_IMPORT`, whose keyword IDs are 10 and 27. They select the `PRS0_EXTERN` and `PRS0_IMPORT` declaration modes defined as `0x000004` and `0x000005` in `Compiler/CompilerA.HH`. The `_extern` and `_import` paths use keyword IDs 11 and 28, consume a target identifier before the type, set the `FSF__` staging bit, and select `PRS0__EXTERN` or `PRS0__IMPORT`. `PrsGlblVarLst` rejects both import modes unless `CCF_AOT_COMPILE` is set. `Kernel/KernelC.HH:10` supplies a grouped ordinary example: `public extern U8 *rev_bits_table,*set_bits_table;`. `Kernel/KernelB.HH:37` and `Kernel/KernelC.HH:23-29` supply alternate-name globals, while `Compiler/CExts.HC:42-46` supplies alternate-name arrays. The OCaml parser retains one source-linked binding node after the modifier list, stores an alternate target as a separate identifier, and applies the same AOT gate. It does not yet look up that target, resolve aliases, or apply `OPTf_EXTERNS_TO_IMPORTS`.

`KW__INTERN` has keyword ID 14 and selects `PRS0__INTERN`, whose mode value is `0x000002`. Unlike an alternate-name binding, `PrsStmt` obtains its target by calling `Compiler/PrsExp.HC:LexExpressionI64`. The `PrsGlblVarLst` function path assigns that evaluated value to `exe_addr`, sets `Ff_INTERNAL`, and clears `Cf_EXTERN`. The pinned tree contains 60 `_intern` declarations, all in `Kernel/KernelB.HH`, including `Bsf`, `Bt`, `ATan`, and `GetTSC`. The OCaml AST stores this target as a source-positioned expression and accepts it in JIT and AOT modes. Parsing does not evaluate the expression, assign the address, or apply the flags.

`Compiler/PrsVar.HC:PrsType` consumes ordinary `*` tokens before it reads the identifier. It increments `ptr_stars_cnt` for each token and throws an error when the count exceeds `PTR_STARS_NUM`. `Kernel/KernelA.HH` defines that limit as four. `Compiler/PrsLib.HC:PrsClassNew` allocates five adjacent class records for the base type and pointer depths one through four. `Compiler/CExcept.HC:ICClassPut` checks the same bound when assigning a class to intermediate code.

`Frontend.Parser` accepts `modifier* binding? primitive declarator (, declarator)* ;`, where a modifier is `public`, `static`, or one of the four calling modifiers. A binding may be ordinary `extern` or `import`, alternate `_extern target` or `_import target`, or `_intern target-expression`. Each declarator has zero through four pointer stars, one identifier, and zero or more array dimensions. The primitive is one of the 12 public spellings checked by `Sema.Primitive_type`. The parser reuses the modifier list, binding, and base type across the declaration and starts pointer depth and array-dimension state again for each name, matching the saved inputs in `PrsGlblVarLst`. Pinned examples include `Demo/MultiCore/Primes.HC:2`, `Demo/MultiCore/MPRadix.HC:11`, `Kernel/KDefine.HC:16`, `Kernel/KernelB.HH:37`, `Kernel/KernelC.HH:10`, and the arrays at `Kernel/KernelC.HH:32-44` and `750-751`. `Kernel/KernelC.HH:17` supplies the bound `public argpop extern` order. Type names remain ordinary identifier tokens, matching the compiler hash-table design rather than introducing lexer-only type keywords. Parenthesized function-pointer globals follow a separate `PrsType` path and remain unsupported, as do class and union prefixes and anonymous forms.

`Compiler/PrsVar.HC:PrsArrayDims` runs at the end of `PrsType`. It accepts `[]` only while the linked dimension list is empty, evaluates each nonempty dimension with `LexExpressionI64`, rejects negative results, multiplies the linked `total_cnt` values, and checks the closing bracket. The parser implements the syntax boundary: ordered bracket nodes, an optional first expression, and the shared source-precedence expression tree. It does not evaluate signs, compute totals, or allocate storage. `Compiler/Lex.HC:322` supplies an expression dimension. `Compiler/Asm.HC:393` supplies an array suffix followed by an initializer; this slice accepts the suffix form but still rejects the complete initialized declaration. `Adam/Gr/GrGlbls.HC:28-35` supplies pointer and multidimensional member forms for later class parsing. `PrsArrayDims` rejects all array suffixes in `PRS1B_FUN_ARG`, and the prototype parser retains that rejection as `HCPARSE0011`.

If the token after a declared name is `(`, `PrsGlblVarLst` dispatches bound modes to `PrsFunJoin` and unbound mode to `PrsFun`. `PrsFunJoin` registers or updates a `CHashFun`, retains the return class, and calls `PrsVarLst` with `PRS1_FUN_ARG`. In that mode, `PrsVarLst` accepts types, pointer layers, optional parameter names, commas, defaults, register requests, and a terminal `TK_ELLIPSIS`; `PrsDotDotDot` marks `Ff_DOT_DOT_DOT`. `PrsArrayDims` rejects an array suffix when the parser mode is `PRS1B_FUN_ARG`. `Kernel/KernelB.HH:44`, `122-163`, and `270-274` supply alternate-name prototypes, while `Compiler/CExts.HC:10-40` supplies ordinary prototypes.

`PrsVarLst` processes `KW_REG` and `KW_NOREG` both before a type and immediately after it. `reg` assigns `REG_ALLOC`; `noreg` assigns `REG_NONE`. Only `reg` attempts to consume a following identifier, and it does so only when `DefineMatch` finds that spelling in `ST_U64_REGS`. `Compiler/CInit.HC` defines the accepted sequence as the 16 canonical U64 registers from `RAX` through `R15`. Repeated qualifiers are legal, with later assignments replacing `_reg` for compiler behavior. `PrsVarLst` passes the resulting value to both `MemberLstNew` and `PrsDotDotDot`. `Doc/Options.DD` places `OPTf_NO_REG_VAR` at a later optimization boundary rather than changing this grammar.

The OCaml prototype parser accepts only bound forms with primitive return and parameter types. It preserves ordered declaration and calling modifiers, return pointers, both parentheses, comma-separated named or unnamed parameters, parameter pointers, recursive function-pointer parameter declarators, optional ordinary or `lastclass` defaults, a distinct terminal `...`, and the semicolon. It also preserves every `reg` or `noreg` qualifier, its position before or after the type, and an optional explicit U64 register. The accepted explicit-register set is derived from the first checked R64 record for register numbers 0 through 15 in `Generated.Opcode_table`; aliases and narrower register families remain parameter identifiers. Qualifiers after pointer stars receive `HCPARSE0013`. A completed prototype is published with `Symbol_visibility.Function` only after its semicolon. JIT imports fail before the function name can be published. Register allocation, unbound bodies, semantic flag validation, default substitution, and header matching remain outside this slice and receive explicit diagnostics rather than partial AST nodes.

`Compiler/PrsVar.HC:PrsType` first consumes zero through four return pointer stars. Its function-pointer branch then requires `(`, one through four more stars, an optional identifier in function-argument mode, `)`, and a signature opening parenthesis. It calls `PrsFunJoin` with a null name and stores the resulting metadata through `CMemberLst.fun_ptr`; `PrsVarLst` marks that member with `MLF_FUN`. Since `PrsFunJoin` calls `PrsVarLst` again, function-pointer parameters may nest. Pinned examples include `Kernel/QSort.HC:1`, `Kernel/KernelB.HH:49-53`, and `Kernel/KernelC.HH:17-22, 517, and 603-605`. `Frontend.Ast.function_pointer_declarator` keeps the two pointer depths distinct and recursively records signature parameters. A hosted depth limit of 32 rejects deliberately nested denial-of-service input with `HCPARSE0017`; this limit is not a TempleOS language rule.

In `Compiler/PrsVar.HC:PrsVarLst`, the `PRS1B_FUN_ARG` branch checks for `=` on each member. A following `KW_LASTCLASS` sets `MLF_LASTCLASS` and consumes exactly that token. Every other default is compiled with `LexExpression2Bin`, executed, converted to the parameter type, and copied when it produces string storage. Both branches then set `MLF_DFT_AVAILABLE`, and there is no rule requiring defaults to trail. The OCaml AST mirrors this split with distinct expression and `lastclass` default values while retaining the shared equals sign. `Compiler/PrsExp.HC:PrsExpression2` supplies the precedence loop and its special unary-minus handling for `IC_POWER`; `PrsUnaryTerm` supplies the supported primary and prefix forms. The binary metadata comes from `Compiler/CInit.HC`, with precedence constants from `Compiler/CompilerA.HH`.

`Frontend.Parser` uses that checked binary table directly for ordinary parameter defaults, array dimensions, call arguments, indexes, member chains, postfix updates, primitive postfix casts, `sizeof`, `offset`, and `defined` terms, and `_intern` targets. Only entries marked `ASSOCF_RIGHT` group to the right; all remaining entries group to the left, as the source loop does. The parser represents an absent default separately from an expression or `lastclass` value and applies the same split inside function-pointer signatures. Every term, operator, and `lastclass` keyword retains source and definition provenance. This stage does not execute expressions, perform the source conversions, set member or internal-function flags, store strings, fill omitted call arguments, validate index, member, update, cast, `sizeof`, or `offset` operands, resolve the truth of a `defined` term, or assign executable addresses. Resolved nonprimitive cast targets and special forms receive `HCPARSE0020`, while a fixed 256-level depth guard reports `HCPARSE0021`.

`Compiler/PrsExp.HC:PrsFunCall` accepts an opening parenthesis when present and walks the fixed member list in declaration order. For a member carrying `MLF_DFT_AVAILABLE`, a current `)`, a current `,`, or a call made without parentheses selects the stored default. `PrsFunCall` tracks the optimized class of each explicit argument. When a selected default also carries `MLF_LASTCLASS` and a previous explicit argument established a class, it substitutes that class's unstarred name string. Otherwise it leaves the stored default value in place. Parsing retains the declaration marker but does not perform this call-time substitution. `Doc/HolyC.DD` documents both parentheses-free default-only calls and the non-trailing default example `Test(,3);`. The pinned compiler itself uses consecutive holes in `PrsStmt(cc,,,cmp_flags)`, leading holes in `GetStr(,,GSF_SHIFT_ESC_EXIT)`, and a middle hole while loading `OpCodes.DD`.

The OCaml AST now stores a call as its callee, opening and closing parentheses, and an ordered slot list. A slot is explicitly omitted or contains an expression, and it owns the comma that follows it. Omitted slots have zero-width source locations at their insertion points, with definition and generated-source provenance copied from the delimiter. Calls bind before all audited binary operators and can nest or follow a parenthesized callee. `HCPARSE0024` reports a missing argument separator and `HCPARSE0025` reports a missing closing parenthesis. Semantic resolution still needs to identify direct and indirect callees, validate fixed and variadic arguments, check default availability, convert values, fill holes, and lower the call. Parentheses-free calls remain outside this syntax slice.

The `[` branch of `Compiler/PrsExp.HC:PrsUnaryModifier` calls `PrsExpression`, requires a matching `]`, and returns `PE_UNARY_MODIFIERS`, so indexes can repeat or mix with calls. The same branch consults `_tmpad`, resolved classes, pointer depth, array and register flags, and element sizes while constructing address arithmetic. The OCaml AST stores only the source-level base, brackets, and index expression. It assigns the same postfix binding used by calls and emits `HCPARSE0026` when the closing bracket is missing. Type validation, multidimensional stride calculation, scaling, address formation, implicit dereference, and lvalue classification remain semantic and lowering work.

The `.` and `TK_DEREFERENCE` cases in `PrsUnaryModifier` converge before requiring `TK_IDENT` and calling `MemberFind`. The source keeps direct and pointer access distinct while it determines whether the current expression represents an address, value, pointer, or register-backed object. `CmpFillTables` constructs `->` as the `TK_DEREFERENCE` compound token, whose numeric ID is defined in `Kernel/KernelA.HH`. The OCaml AST records the distinction as `Direct_member` or `Pointer_member`, preserves the operator and identifier locations, and returns to the postfix loop for further calls, indexes, or members. `HCPARSE0027` reports a missing identifier. Type resolution, member lookup, inheritance, layout, offset arithmetic, implicit dereference, and lvalue classification remain semantic and lowering work.

The `TK_PLUS_PLUS` and `TK_MINUS_MINUS` cases in `PrsUnaryModifier` set `CCF_POSTINC` or `CCF_POSTDEC`, set the postfix precedence to `PREC_UNARY_POST`, consume one token, and return `PE_DEREFERENCE`. `PrsExpression2` maps those flags to `IC__PP` or `IC__MM`, whose numeric identities are `0x27` and `0x28`. Unlike calls, indexes, and members, the update does not return to `PE_UNARY_MODIFIERS`. The OCaml parser records the operand, update kind, operator, and combined provenance in a distinct postfix node. It then permits only a binary continuation. `HCPARSE0028` reports a call, index, member, or second update that attempts to continue the postfix chain. Type checking, modifiable-lvalue validation, old-value behavior, mutation, and IC lowering remain unimplemented.

The `(` case in `PrsUnaryModifier` first handles a function expression through `PrsFunCall`. For any other operand it calls `PrsType` with `PRS0_TYPECAST`, rewrites the current IC class, adds `IC_HOLYC_TYPECAST`, requires `)`, and returns `PE_UNARY_MODIFIERS`. `PrsUnaryTerm` separately rejects a parenthesis whose first token resolves to a class or internal type and directs the user to postfix syntax. `Doc/HolyC.DD` states the same rule, and forms such as `ptr(U8 *)++`, `buf[0](U32)`, and `value(F64)` occur throughout the pinned tree. The OCaml parser treats `(` followed by one of the 12 checked primitive spellings as a cast and treats other contents as call arguments. Its AST stores the complete operand, both parentheses, primitive target, zero through four pointer layers, and combined provenance. Casts return to the modifier loop, while a cast after a terminal update remains invalid. `HCPARSE0029` rejects C-style prefix casts and `HCPARSE0030` reports an unclosed primitive target. Class, union, array, and function-pointer targets require resolved type names and are not guessed by this syntax-only slice. Conversion, warnings, and `IC_HOLYC_TYPECAST` lowering remain unimplemented.

The `KW_SIZEOF` case in `PrsUnaryTerm` sets `PREC_TERM`, consumes zero or more opening parentheses, calls `PrsSizeOf`, requires the same number of closing parentheses, and returns `PE_MAYBE_MODIFIERS`. `PrsSizeOf` requires an identifier, resolves it among local variables, internal types, classes, globals, functions, and exports, loops over dot-separated members, and then consumes every trailing pointer star. That star loop does not use the `PTR_STARS_NUM` limit from `PrsType`. A pointer target forces the result to `sizeof(U8 *)`; other targets use class size, array byte count, or function debug range before the routine adds an immediate I64 result. The OCaml AST preserves the keyword, wrapper pairs, unresolved target, complete member path, target stars, and combined provenance. It intentionally follows the repeated-member loop even though `Doc/HolyC.DD` claims only one member level. Because the source returns `PE_MAYBE_MODIFIERS`, only a postfix cast can follow the raw term; calls, indexes, member accesses, and updates become available after that cast. `HCPARSE0031` through `HCPARSE0034` cover malformed target shapes and direct suffixes. Name and member resolution, local use counts, byte-size calculation, and immediate lowering remain unimplemented.

The adjacent `KW_OFFSET` case has the same `PREC_TERM`, wrapper, and `PE_MAYBE_MODIFIERS` behavior, but it calls `PrsOffsetOf`. That routine resolves the first identifier as a local variable, class, or global variable, requires a dot, and follows one or more member names. Each step adds `CMemberLst.offset` and moves to `member_class`; the final sum is emitted as `IC_IMM_I64`. The OCaml AST records the unresolved root and every member segment. It follows the executable `do ... while` loop despite the one-level statement in `Doc/HolyC.DD`. Unlike `PrsSizeOf`, this routine has no pointer-star loop. `HCPARSE0035` through `HCPARSE0039` cover missing roots, missing dots or member names, unmatched wrappers, and forbidden direct suffixes. Name and member resolution, local-use adjustments, layout arithmetic, and immediate lowering remain unimplemented.

The parser consumes `Frontend.Preprocessor.next` with one token of lookahead. It captures the current include stack and definition trace with each token, publishes an accepted name before requesting the token after its comma or semicolon, and returns no public AST if any error occurred. Declaration recovery stops at a semicolon or EOF. Statement recovery also stops at a closing brace while parsing a block, so one malformed child does not consume the block boundary. Publishing at that point matches the `HashAdd` placement in `PrsGlblVarLst` and lets a following `#ifdef` observe the declaration. A rejected JIT import is diagnosed before declarator parsing, so no rejected name is published. `Frontend.Ast` records the root-module span and the primary span plus ordered source segments for each accepted modifier, binding, symbol or expression target, type, pointer layer, identifier, array bracket and expression, call parenthesis, call slot, index bracket, member operator and name, postfix update operator, cast parenthesis and target, `sizeof` keyword, wrapper, member, and star, `offset` keyword, wrapper, and member, delimiter, declarator, declaration group, statement separator, block brace, conditional keyword, and conditional parenthesis. Definition-generated nodes retain both their expansion and definition sites. `Frontend.Ast_dump` renders the versioned `holyc-ast-v1` human and JSON formats.

The `KW_DEFINED` case sets `PREC_TERM`, consumes zero or more opening parentheses, inspects exactly one token, consumes it with one `Lex` call, closes the wrappers, and returns `PE_MAYBE_MODIFIERS`. It emits true only when that token is `TK_IDENT` and has a hash entry or local-variable entry; every other case emits false. `PrsKeyWord` confirms that language keywords remain `TK_IDENT` values backed by keyword hash entries, so the OCaml AST classifies both keywords and ordinary identifiers as name-shaped while retaining every other token as non-name. The parser keeps the keyword, wrapper pairs, one operand spelling and classification, and combined provenance. `HCPARSE0040` through `HCPARSE0042` cover a missing token at EOF, unmatched wrappers, and forbidden direct suffixes. Hash and local lookup, Boolean selection, and `IC_IMM_I64` lowering remain unimplemented. No language-expression use was found in the pinned Compiler, Kernel, Adam, or Demo `.HC` and `.HH` files, so focused fixtures provide the current gate.

`Compiler/PrsStmt.HC:PrsStmt` sends a statement-position `TK_STR` or `TK_CHAR_CONST` token to `PrsFunCall` instead of discarding the literal. In `Compiler/PrsExp.HC:PrsFunCall`, a character marker selects `PutChars` and a string marker selects `Print`. A zero character marker or a string whose first byte is zero is consumed before the fixed argument is parsed, which gives `'' value;` and `"" fmt,args;` their variable-value forms. A nonempty marker remains the first token of the fixed argument expression, so a continuation such as `'A'+1;` belongs to that argument. Comma-led expressions after a `Print` format become its variadic arguments. `Doc/HolyC.DD` documents all four forms, and `Kernel/KExts.HC` supplies the corresponding prototypes.

The OCaml AST stores this behavior as a statement with an explicit `Print` or `PutChars` target. It retains the marker even when a following expression supplies the fixed argument, records whether the fixed expression began at or after the marker, and keeps each `Print` argument and its leading comma. A `Print` statement still requires its own semicolon. A `PutChars` statement may instead end at a sequence comma, so its semicolon field is optional. The same node is accepted at top level and recursively inside a block. Definitions and includes keep their normal origin metadata. `HCPARSE0043`, `HCPARSE0044`, and `HCPARSE0046` cover a missing fixed expression, an empty `Print` argument, and a missing required semicolon. This slice does not yet parse the same form inside a function body, resolve either runtime symbol, check argument types, lower the call, or execute top-level code.

At the start of its main loop, `PrsStmt` consumes every comma. A lone semicolon is an empty statement; otherwise the ordinary path calls `PrsExpression`. When semicolon parsing is enabled, that expression may end with `;` or at a comma. After blocks, empty statements, labels, literal calls, and expressions, a comma returns control to the same loop. `Compiler/CMain.HC:LexStmt2Bin` and `CmpJoin` repeatedly enter this path, which preserves top-level source order in JIT and AOT modes.

The OCaml parser represents ordinary expression statements, empty statements, and comma-linked sequences directly. A sequence retains leading commas, ordered statement elements, and every comma following an element, including repeated and trailing separators. The same representation is used at top level and inside blocks. Known global or function symbols can begin an expression; unresolved identifiers remain on the source declaration-or-label path. `HCPARSE0047` reports an expression without `;` or a statement comma. `HCPARSE0048` reports a declaration, label, or other unsupported statement form encountered after a comma. Control flow, labels, local declarations, and function-body parsing remain pending.

The opening-brace branch of `PrsStmt` calls `Lex`, recursively invokes `PrsStmt` until `}` or `TK_EOF`, and then consumes the closing brace. If the following token is a comma, the enclosing statement loop continues. A comma before the closing brace does not terminate the block; it asks the recursive statement loop for another child. The OCaml AST mirrors that control flow with a recursive block node holding both braces and ordered children. Empty blocks, nested blocks, block children, and a block followed by a sequence comma are represented directly. `HCPARSE0049` reports EOF before the close and retains the opening brace as a secondary location. `HCPARSE0050` reports an unmatched close at top level. `HCPARSE0051` caps hosted recursion at 256 blocks; no corresponding language limit was identified in the pinned source. Scopes, local declarations, remaining control flow, labels, function bodies, lowering, and execution remain pending.

`Compiler/PrsStmt.HC:PrsIf` requires `(`, calls `PrsExpression`, and requires `)` before emitting `IC_BR_ZERO` and passing the next input to `PrsStmt`. It then uses `PrsKeyWord` to test for `KW_ELSE`. When present, it emits a jump around the false branch and calls `PrsStmt` a second time. The recursive calls make a following `else` part of the nearest unfinished conditional. `Compiler/CompilerA.HH` assigns `KW_IF` value 6 and `KW_ELSE` value 7. `Doc/HolyC.DD` demonstrates that the condition follows HolyC expression rules with `if (13<=age<20)`.

The OCaml AST keeps the `if` keyword, both condition parentheses, the condition expression, the then branch, and an optional else keyword and branch. Each branch uses the common statement parser, so blocks, comma-linked sequences, output literals, empty statements, expressions, and nested conditionals retain their existing shapes and provenance. `HCPARSE0052` through `HCPARSE0056` report malformed parentheses, missing branches, or an unmatched `else`. `HCPARSE0057` caps hosted conditional recursion at 256; no corresponding source-language limit was identified. This slice does not reproduce truth conversion, `IC_BR_ZERO`, label allocation, control-flow construction, semantic checks, lowering, or execution.

`Compiler/PrsStmt.HC:PrsWhile` requires `(`, calls `PrsExpression`, requires `)`, emits `IC_BR_ZERO`, and passes the next input to `PrsStmt` with the loop's completion label. It then emits `IC_JMP` back to the condition label. `Compiler/CompilerA.HH` assigns `KW_WHILE` value 9, and `Kernel/Job.HC` contains representative single-statement and compound loop bodies.

The OCaml AST keeps the `while` keyword, both condition parentheses, the condition expression, and the recursively parsed body. The common statement path preserves blocks, comma-linked sequences, output literals, empty statements, expressions, nested loops, and conditionals. Tests also lock nearest-`if` else association on both sides of a loop boundary. `HCPARSE0058` through `HCPARSE0060` report malformed parentheses or a missing body. `HCPARSE0061` caps hosted loop recursion at 256 and shares its count with post-test loops; no corresponding source-language limit was identified. This slice does not reproduce truth conversion, `break`, label allocation, `IC_BR_ZERO`, the loop back edge, semantic checks, lowering, or execution.

`Compiler/PrsStmt.HC:PrsDoWhile` emits its entry label before it passes the body to `PrsStmt`. It then requires `KW_WHILE`, `(`, an expression, `)`, and `;` in that order. The final `IC_BR_NOT_ZERO` targets the entry label, followed by the break label. `Compiler/CompilerA.HH` assigns `KW_DO` value 15. `Kernel/Job.HC:TaskRstAwaitingMsg` provides a representative compound body followed by `while (task=task->popup_task);`.

The OCaml AST retains both keywords, the recursively parsed body, both parentheses, the condition, and the final semicolon as separate source locations. The common statement path supports pre-test and post-test loop nesting and preserves nearest-`if` else association. `HCPARSE0062` through `HCPARSE0066` cover a missing body and each required trailing component; an empty condition uses `HCPARSE0018`. The shared `HCPARSE0061` guard covers mixed loop nesting. Truth conversion, `break`, label allocation, `IC_BR_NOT_ZERO`, semantic checks, lowering, and execution remain later work.

## Compiler option state

`Kernel/KernelA.HH` assigns 12 compiler-option bit indices. They are not pre-shifted masks. Bits 0 and 1 control echo and trace behavior, bits 16 through 19 control warnings, and bits 32 through 37 affect linkage, symbol retention, allocation, optimization, and code emission. The ranges 2 through 15 and 20 through 31 are unused in the pinned definitions.

`Compiler/Lex.HC:CmpCtrlNew` creates a controller with `OPTf_WARN_UNUSED_VAR` and `OPTf_WARN_HEADER_MISMATCH` enabled, giving an initial mask of `0x90000`. `Compiler/CMain.HC` copies a parent controller's option mask when compilation is nested. This makes the options part of compile-stream state rather than process-wide settings.

`Compiler/CMisc.HC:Option` and `GetOption` operate on `Fs->last_cc->opts`. `Option` calls `BEqu`, whose `_BEQU` implementation in `Kernel/KUtils.HC` uses `BTS` or `BTR` followed by `ADC`; its result is the bit's state before the change. The OCaml API exposes the same return contract as a pure update that yields the new mask and previous state.

The audited core consumers establish these phase assignments:

| Option | Bit | Initially enabled | Observed core use |
| --- | ---: | --- | --- |
| `OPTf_ECHO` | 0 | No | Lexer echo and compiler option display |
| `OPTf_TRACE` | 1 | No | Parser and compiler trace output |
| `OPTf_WARN_UNUSED_VAR` | 16 | Yes | Function-level unused-variable diagnostics |
| `OPTf_WARN_PAREN` | 17 | No | Unnecessary-parenthesis diagnostics |
| `OPTf_WARN_DUP_TYPES` | 18 | No | Duplicate local type diagnostics |
| `OPTf_WARN_HEADER_MISMATCH` | 19 | Yes | Function header comparison |
| `OPTf_EXTERNS_TO_IMPORTS` | 32 | No | Declaration parsing and AOT linkage |
| `OPTf_KEEP_PRIVATE` | 33 | No | Private source symbol retention |
| `OPTf_NO_REG_VAR` | 34 | No | Register-variable optimization passes |
| `OPTf_GLBLS_ON_DATA_HEAP` | 35 | No | Global allocation and AOT initialization rules |
| `OPTf_NO_BUILTIN_CONST` | 36 | No | Floating constant selection in the backend |
| `OPTf_USE_IMM64` | 37 | No | Import call lowering and emission; marked incomplete in the source |

`tools/compiler_option_source.ml` validates the definitions, source comments, initial mask, public API, `_BEQU` behavior, and core references while ignoring occurrences in comments and literals. `tools/compiler_option_gen.ml` writes the pinned checksums and line references to `src/generated/compiler_options.ml`. `Sema.Compiler_option` provides immutable lookup and mask operations. It does not yet connect these values to a compiler controller or implement their downstream effects.

## Function and calling flags

`CHashFun` inherits the `U16 flags` field declared by `CHashClass` in `Kernel/KernelA.HH`. `Cf_EXTERN` and `Cf_INTERNAL_TYPE` occupy bits 0 and 1 of that shared field. The eight `Ff_*` function positions are contiguous from bit 8 through bit 15; the lower-byte gap is part of the representation and is not compacted in the OCaml model.

`Compiler/CompilerA.HH` defines a second flag set used while `PrsStmt` reads a declaration. `FSF_PUBLIC`, `FSF_ASM`, `FSF_STATIC`, and `FSF__` occupy bits 0 through 3 of this temporary value. The four calling modifiers use the same masks as their stored `Ff_*` counterparts. `FSG_FUN_FLAGS1` selects only those four stored bits, while `FSG_FUN_FLAGS2` adds public parser state.

`PrsFunJoin` copies `FSG_FUN_FLAGS1` into `CHashFun.flags` and transfers `FSF_PUBLIC` to the hash type separately. It derives `Ff_RET1` only when the fixed argument block is nonempty, no varargs marker is present, and the eight-byte argument slots fit a signed 16-bit return immediate. This gives a fixed-argument range of 1 through 4,095.

The declaration modifier assignments are order-sensitive. `interrupt` sets both `FSF_INTERRUPT` and `FSF_NOARGPOP`. The calling modifiers and `public` retain existing calling, public, and assembly state. `static` keeps assembly state but clears the other staged bits. A leading underscore handled by `_extern` or `_import` adds `FSF__` without clearing state.

`PrsExp.HC` selects caller cleanup with `(Ff_RET1 || Ff_ARGPOP) && !Ff_NOARGPOP`. `OptPass789A.HC` applies the same rule in function epilogues. That backend also uses `Ff_INTERRUPT` for interrupt save/restore and `IRETQ`, and it removes an eight-byte error-code slot when `Ff_HASERRCODE` is present. `PrsVar.HC` marks varargs with `Ff_DOT_DOT_DOT`; `OptPass3.HC` accounts for the synthetic `argc` and `argv` members. Internal functions are dispatched as IC operations in `PrsExp.HC`, excluded from ordinary call clobbering in `OptPass6.HC`, and omitted from address-to-function lookup in `Kernel/FunSeg.HC`.

`tools/function_flag_source.ml` checks the definitions, source expressions, structure ownership, modifier assignments, downstream predicates, and every core consumer while ignoring comments and literals. `tools/function_flag_gen.ml` emits immutable nested modules and source references in `src/generated/function_flags.ml`. `Sema.Function_flag` provides typed lookup and pure transition helpers. The parser now retains all four calling modifier tokens on bound prototypes. Validity diagnostics, stored flag assignment, call lowering, and native ABI emission remain later work. [The ABI notes](holy-abi.md) keep that boundary explicit.

## TempleOS BIN header and patch records

`Kernel/KernelA.HH` defines the `'TOSB'` signature, the seven-field `CBinFile` header, 21 named `IET_*` values, five reserved numeric slots, and eight `AAT_*` adjustment operations. The header occupies 32 bytes. `Compiler/CMain.HC:Cmp` writes the code and initialized-data body immediately after that header, places the patch table after the body, terminates it with `IET_END`, and rounds the complete file size to 16 bytes.

`Kernel/KLoad.HC:Load` treats the byte after the header as `module_base`. `LoadPass1` registers exports, resolves or defers imports, applies absolute-address patches, and creates heap allocations. `LoadPass2` walks the same variable-length records and calls `IET_MAIN` entries. Relative import fields receive `target - field_address - field_width`; immediate fields receive the target itself. The source retains fictitious zero-width import values, marks 64-bit exports as not implemented, and marks three heap forms as not really used. The OCaml model preserves those comments instead of treating every loader switch case as a compatibility claim.

`Kernel/KStart16.HC` locates the boot patch table, and `Kernel/KStart32.HC:CPatchTableAbsAddr` performs the boot absolute-address pass. Compiler producers and consumers in `AsmResolve.HC`, `Asm.HC`, `PrsVar.HC`, `BackFA.HC`, `BackLib.HC`, `BackC.HC`, `OptPass3.HC`, and `OptPass789A.HC` establish which record and adjustment kinds reach assembler, parser, optimizer, and backend paths.

`tools/bin_record_source.ml` requires that exact 13-file source set. It validates checksums, table order, numeric gaps, status comments, header fields, writer behavior, loader formulas, both passes, boot handling, and source consumers while ignoring comments and literals. `tools/bin_record_gen.ml` emits typed entries, adjustments, record shapes, relocation metadata, loader actions, checksums, and line references to `src/generated/bin_records.ml`. `Backend.Bin_spec` exposes that data through `Holyc_lib.Templeos_bin_spec`.

This slice is an executable format specification, not format compatibility. It has no serializer, parser, loader model, generated module, or actual TempleOS loader result. [The BIN format notes](templeos-bin-format.md) describe the byte grammar and the validation still required for M8.

## Literals

`Compiler/Lex.HC:Lex` accumulates integers in a target `I64`, so overflow wraps. Hex and binary prefixes are case insensitive. Character constants store up to eight decoded bytes in little-endian order. `LexInStr` defines the recognized escapes. The hosted lexer diagnoses unterminated literals instead of relying on an in-memory NUL terminator.

## Comments

The pinned lexer nests `/* ... */` comments. It consumes `//` through the end of the line. The OCaml lexer retains both as leading trivia so later diagnostics and formatting tools can recover their exact bytes.

## Diagnostics

`Compiler/CExcept.HC` prints the current token, file, line, and source line before raising the compiler exception. Hosted diagnostics retain those source facts in structured values with stable codes. Rendering is separate from construction so JSON and terminal output share the same diagnostic.

## Interpretation decisions

- Files are finite OCaml byte strings. Ordinary hosted lexing diagnoses an embedded NUL. The verified corpus path can instead apply the pinned buffer-termination rule and reports every trailing payload byte.
- Lines increment on LF, matching `LexGetChar`. CR is whitespace but does not start a new line by itself.
- A raw lexer command returns `#` as punctuation. `#include` and `#define` execute only through the separate preprocessed stream, so tooling can still inspect directive and replacement tokens.
- Extensionless hosted includes try `.HC.Z` and then the decompressed `.HC` form used by the pinned Git checkout. Transparent TempleOS `.Z` decompression remains unimplemented.
- Allowed-root enforcement, active-path cycle diagnostics, and nesting and size limits are hosted security differences. They are not attributed to the native TempleOS lexer.
- Dollar-delimited text is retained as comment trivia in raw-source mode. Interpreting DolDoc markup is outside this slice, while `$$` is recognized as the HolyC current-position token.
