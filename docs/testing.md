# Testing holyc-ocaml

Run the local checks with:

```text
dune build @fmt
dune build @generated-check
dune build
dune runtest
powershell -File tools/verify-reference.ps1
```

Unit tests cover source positions, spans, token construction, literal decoding, comments, diagnostic rendering, include and generated-value frames, predefined values, primitive global declarations, declaration modifiers and bindings, comma-separated groups, pointer layers, strict extraction of the complete opcode database, operator tables, primitive type metadata, compiler options, function flags, the complete intermediate-code table, and the TempleOS BIN specification. The generated-table tests reject malformed statements, duplicate records, missing or reordered entries, changed aliases, unknown opcode arguments, excess instruction bytes or forms, unknown operator tokens or ICs, precedence drift, unavailable-type drift, option default drift, function-flag expression or transition drift, BIN record or loader-formula drift, API contract drift, and source checksum mismatches. The option, function-flag, and BIN scanners also prove that comments and literals do not create false consumers; the option tests separately confirm that `_BEQU` retains its previous-state result.

The current `dune runtest` invocation runs 444 registered Alcotest cases plus 57 CLI golden rules. A passing count describes only the implemented slices listed below; it is not a whole-compiler compatibility percentage. The reference verifier checks 51 individually audited Git blobs and the lexer corpus test reads all 528 relevant blobs from the pinned Git tree.

Corpus tests cover deterministic extension filtering and path order, LF and CRLF continuation trivia, a NUL-terminated source with a retained payload count, malformed-input diagnostics, file-size rejection, dirty and mismatched reference rejection, stable human and JSON rendering, and the complete pinned source set. The validated scan reads Git objects rather than converted worktree files. This keeps byte counts and token spans identical on Windows and Unix while the pre-scan and post-scan worktree checks still detect local changes. The checked human report records 528 tokenized files, zero failures, 4,190,323 canonical source bytes, 719,304 tokens, 54 NUL terminators, and 1,266,852 trailing payload bytes. `.github/workflows/corpus.yml` publishes the complete per-file JSON report and the human summary as an Actions artifact.

Preprocessor tests build isolated temporary source trees. Include cases check nested token order, caller resumption, stable source IDs, byte positions across LF and CRLF files, working-directory rather than caller-directory resolution, ordered roots, extensionless `.HC` fallback, empty includes, include-at-EOF behavior, TempleOS root mapping, and the unchanged raw lexer. Negative cases cover missing files, directory targets, canonical path escape, self and multi-file cycles, depth exhaustion, oversized sources, malformed directive arguments, unsupported directives, and unmapped TempleOS paths. A nested lexer failure is checked in both human and JSON form to ensure the complete include chain survives rendering.

Definition cases check raw text capture, empty and whitespace-only replacements, strings, character constants, retained block-comment trivia, line comments, trailing spaces, CRLF continuation, EOF capture, byte-segment maps, use-before-declaration, latest-definition lookup, keyword names, nested expansion, definition-supplied include paths, injected directives, caller resumption, and persistence across streams in one session. Boundary cases split every multi-byte operator at every possible point and also cover numbers, quoted literals, both comment openers, an exhausted intermediate definition frame, three nested include frames, and a line continuation split across an included file and its caller. They verify raw bytes, following-token order, and every source segment. Direct and indirect cycles, depth exhaustion, generated-byte exhaustion, embedded NULs, unterminated strings, and unterminated comments are negative tests. Token JSON records invocation and declaration spans; replacement diagnostics check those spans in both renderers. The exact `holyc-definition-dump-v1` output is a reviewed golden assertion. The matching native results are recorded in [`test/oracle/frame-boundaries.json`](../test/oracle/frame-boundaries.json).

Predefined-value cases cover all six standard names, exact recognition of their pinned `KernelA.HH` bodies, explicit date and time settings, root and include depth for `__CMD_LINE__`, ordinary source overrides, `#ifdef` visibility, the pinned `defined` expansion behavior, canonical file and directory values, generated-string escaping, shared depth and byte limits, declaration and invocation provenance, and byte-identical JSON across runs. The date and time formats are checked against `Kernel/StrPrint.HC`. Two CLI golden rules exercise the real command in human and JSON modes.

Mode-conditional cases run the same inputs in explicit JIT and AOT configurations. They cover each branch with and without `#else`, nested selections, unsupported openers nested inside discarded input, inactive includes and definitions, a recursive definition that must not expand in discarded text, definition-supplied directive names, boundaries that cross include and definition frames, and byte-identical JSON from repeated runs. Malformed inactive strings and comments confirm that discarded bytes use the pinned raw scan rather than ordinary tokenization. Negative cases cover embedded NULs, stray and duplicate boundaries, missing `#endif`, conditional-depth exhaustion with side-effect-free recovery, and include or definition provenance on an unterminated conditional.

Constant-expression cases cover true and false branches, adjacent lookahead boundaries, chained definitions, integer, character, multi-character, and floating literals, all supported unary and binary families, source precedence, right-associated power, mixed power and shifts, comparison chains, wrapping, signed and unsigned comparison, shift result types, masked shifts, division, modulo, signed integer-to-F64 promotion, raw floating truth and equality, F64 logical-not encoding, and logical XOR. `defined` is checked for visible functions, locals, shadows, excluded imports, missing symbols, keyword operands, and definition-expanded operands. Negative cases cover missing terms, assignments, postfix forms, runtime identifiers, unmatched parentheses, zero divisors, signed division overflow, and node-budget exhaustion. Logical tests prove that both operands are evaluated. Repeated token and diagnostic renders are byte identical, and expression failures inside include or definition frames retain their provenance.

Assertion cases cover true and false results, definition-expanded constants, `defined` symbols, retained lookahead, expression errors, node-budget exhaustion, inactive branches, include backtraces, and definition-generated directive provenance. They distinguish warnings from errors and check both `preprocess_detailed` and the existing convenience result. Two Dune rules run the actual `holyc preprocess` executable in human and JSON modes. The reviewed stdout and stderr files prove that a failed assertion returns its following tokens, renders `HCPP0024`, and exits successfully.

Help-directive cases cover current-index replacement and clearing, explicit backslash-only string continuation, ordinary adjacent strings, default and existing extensions, TempleOS root mapping, lexical path confinement, file-name sanitation, inactive input, include state, definition provenance, retained malformed input, raw-lexer stability, and per-stream isolation. Human and JSON golden rules run the actual `--dump-help-metadata` command. A pinned `Kernel/KernelC.HH` test records all 104 `#help_index` directives and all 20 `#help_file` directives, matching direct source counts without opening any target help document.

Symbol-conditional cases cover definitions without operand expansion, missing names, checked language and assembly keywords, internal types, every register family, canonical opcodes, aliases, commented-out opcode records, registered functions, classes, globals, exports, excluded imports, and the pinned local-variable shadow result. A streaming test registers a function after consuming the preceding token and before `#ifdef`, which proves that parser work can update the environment without rebuilding the stream. Include and definition frames share the environment, while inactive symbol conditionals leave invalid operands unparsed. Separate unit tests verify all 17 `HTT_*` bit assignments, all 570 static seed entries, masked lookup, local-context stack order, stable IDs, source provenance, and the exact `holyc-symbol-visibility-v1` dump.

Parser cases cover empty input, comment-only input, all 12 public primitive spellings, multiple globals in source order, ordered declaration prefixes, repeated and reordered modifiers, ordinary `extern` and AOT `import` bindings, alternate-name `_extern` and AOT `_import` bindings, `_intern` expression bindings in both modes, comma-separated names, primitive global arrays, and bound primitive function prototypes. `_intern` cases verify the exact total of 60 declarations in the pinned `Kernel/KernelB.HH` and parse representative prototypes. They also cover every core binary and prefix operator, grouping, definition and include provenance, streaming `#ifdef` visibility, deterministic dumps, malformed targets, unsupported continuations, the expression depth limit, and rejected-name publication. Array cases cover direct and pointer declarators, comma groups, multidimensional order, an unsized first dimension, the difference between `[]` and `[0]`, every audited binary operator inside brackets, grouping, definition and include provenance, pinned compiler and kernel declarations, deterministic dumps, and rejected suffixes without rejected-name publication. Prototype cases include pinned ordinary and alternate-name headers, all four calling modifiers, return pointers, empty parameter lists, named and unnamed parameters, pointer depths zero through four, commas, terminal `...`, exact punctuation spans, AOT imports, and function visibility to a following `#ifdef`. Function-pointer cases cover separate return and declarator depths, one through four declarator stars, named and unnamed forms, empty, fixed, and variadic signatures, nested callbacks, register-qualified nested parameters, definition-generated punctuation, recursive human and JSON dumps, and the fixed 32-level hosted limit. Default-expression cases cover every literal and prefix form, every audited binary operator, every adjacent precedence boundary in both operand orders, source-defined association, grouping, the unary-minus power rule, non-trailing defaults, nested callback defaults, generated and included provenance, malformed terms, unsupported postfix continuations, no partial symbol publication, and the fixed 256-level hosted limit. Parameter-register cases cover `reg` and `noreg` before and after a type, every explicit U64 register from `ST_U64_REGS`, repeated qualifiers, qualified varargs, definition provenance, and the rule that non-U64 spellings remain parameter names. Calling-modifier tests fold ordered AST nodes through the checked transition model, covering `interrupt` with implicit `noargpop`, preservation across `public`, and the `static` reset. Definition-backed tests retain invocation and definition sites on modifiers, register names, parentheses, commas, defaults, array dimensions, `_intern` targets, and operators. Source checks read the pinned declaration dispatch, `_intern` expression and function branches, function-pointer branch, default branch, array-dimension loop, expression loop, unary-minus power case, metadata assignment, `PrsFunJoin`, `PRS1_FUN_ARG`, both register-qualifier loops, `ST_U64_REGS`, register sentinels, parameter loop, array-parameter rejection, variadic flag and token IDs, and representative compiler and kernel declarations. Negative cases reject JIT imports before symbol publication, missing parameter types or delimiters, trailing commas, nonterminal varargs, missing or unsupported expression operands, empty later dimensions, missing brackets, array parameters, qualifiers after pointer stars, invalid qualifier sequences, malformed function-pointer declarators, a fifth pointer star, excessive nesting, missing prototype punctuation, and unbound functions. Existing tests continue to cover global declaration errors, include stacks, and definition traces. Human and JSON CLI rules check the `holyc-ast-v1` dumps, source provenance, mode-sensitive diagnostic text, JSON structure, accepted default, dimension, and `_intern` expression trees, and exit status 1 after a parse error.

Opcode-database tests parse the pinned source and check all 106 registers, 325 canonical opcodes, 49 aliases, and 924 instruction forms. They cover each register kind, every instruction field family, argument-size derivation, aliases, nested comments, deterministic output, source lines, and representative `MOV`, `ENTER`, and x87 forms. A regression assertion keeps the empty first `REP_OUTSB` form created by the pinned loader's leading-comma behavior.

Operator API tests cover prefix boundaries, source provenance, all precedence bands, raw association flags, and binary mappings. Semantic type tests cover every supported spelling, raw ID, size, signedness, declaration form, `Bool`, zero-sized types, and the pointer raw alias. Compiler-option API tests cover all names and bit indices, intentional gaps, the initial mask, immutable updates, consumer lines, phase classifications, and the source-marked incomplete state of `OPTf_USE_IMM64`.

Intermediate-code tests cover all 185 constructors and numeric slots. They compare every generated metadata field with a fresh parse of the pinned source, check all lookup directions, retain the 13 constant/display-name differences, and reject malformed shapes, counts, Booleans, padding, and records. Golden tests compare deterministic token dumps. Negative fixtures check malformed comments, strings, characters, and bytes. QCheck generates source buffers to verify offset and line-column invariants.

Function-flag tests cover the two shared flag positions, all eight stored function bits, all eight parser-staging masks, both source groups, and every modifier transition. The transition test checks all 4,096 possible staging masks. Boundary and truth-table tests cover automatic `RET1`, varargs, caller cleanup, interrupt error-code handling, internal functions, and the distinction between public hash state and stored function flags.

BIN source tests cover the exact header layout and signature, entry order and numeric gaps, source status comments, import displacement biases, record payloads, loader-pass actions, AOT adjustments, checksum normalization, and source provenance. Mutation tests reject changed, duplicate, missing, or reordered entries, changed reserved gaps, altered import formulas, altered adjustment operations, unknown consumers, and incomplete source sets. Public API tests distinguish known, reserved, and unknown codes and check every name and numeric round trip. These are specification tests; loader and actual-TempleOS oracle tests remain pending with the serializer.

Golden changes require a reviewed fixture update. Tests must not rewrite expected files automatically.

Corpus, differential, fuzz, loader, and bootstrap suites will be added with the stages they exercise. A suite is not marked passing until its command runs in CI and publishes its exact reference commit.
