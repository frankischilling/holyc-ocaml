# HolyC language notes

Every compatibility statement on this page refers to TempleOS commit `c26482bb6ad3f80106d28504ec5db3c6a360732c`.

## Primitive types

The current semantic API recognizes these 12 spellings:

| HolyC spelling | Raw code | Raw ID | Bytes | Signedness | Declaration form |
| --- | --- | ---: | ---: | --- | --- |
| `I0` | `RT_I0` | 2 | 0 | Signed | Internal type |
| `I8` | `RT_I8` | 4 | 1 | Signed | Internal type |
| `I16` | `RT_I16` | 6 | 2 | Signed | Public union over `I16i` |
| `I32` | `RT_I32` | 8 | 4 | Signed | Public union over `I32i` |
| `I64` | `RT_I64` | 10 | 8 | Signed | Public union over `I64i` |
| `U0` | `RT_U0` | 3 | 0 | Unsigned | Internal type |
| `U8` | `RT_U8` | 5 | 1 | Unsigned | Internal type |
| `U16` | `RT_U16` | 7 | 2 | Unsigned | Public union over `U16i` |
| `U32` | `RT_U32` | 9 | 4 | Unsigned | Public union over `U32i` |
| `U64` | `RT_U64` | 11 | 8 | Unsigned | Public union over `U64i` |
| `F64` | `RT_F64` | 14 | 8 | Not applicable | Internal type |
| `Bool` | `RT_I8` | 4 | 1 | Not applicable | Internal type using `I8i` storage |

`I0` and `U0` are distinct zero-sized types. `Doc/HolyC.DD` describes `U0` as void-like while stressing that its size is zero. The semantic model retains both types rather than folding either into an OCaml unit value.

`Bool` is also distinct. It shares the `RT_I8` code and one-byte storage with `I8`, but lookup returns a separate `Bool` constructor. Later conversion rules must make any relationship explicit.

## Internal names and public integer unions

`Compiler/CInit.HC` registers names ending in `i` as internal storage types. `I0`, `U0`, `I8`, `U8`, `F64`, and `Bool` also appear directly in that table. The larger public integer names do not. They are unions in `Kernel/KernelA.HH` whose leading type selects `I16i`, `U16i`, `I32i`, `U32i`, `I64i`, or `U64i` storage.

Those unions expose subinteger members such as bytes and words. The current API records which primitive comes from a public union and preserves the storage spelling and declaration line. Closed aggregate layouts now retain each member offset, and the aggregate index makes that layout available through direct and inherited lookup. Whole-value conversion and subinteger load or store semantics remain unimplemented.

Internal spellings such as `I32i` remain outside `Primitive_type.of_spelling`, which is the public primitive lookup. `Primitive_type.of_storage_spelling` maps the 11 intrinsic `*i` names to their audited raw primitive identities. The parser represents those names with a distinct internal type specifier instead of rewriting them as public spellings. This records source identity only; it does not implement whole-value or subinteger access.

## Unavailable floating slots

The raw table reserves three slots that are not supported HolyC primitives:

| Raw code | Raw ID | Pinned source marker |
| --- | ---: | --- |
| `RT_F32` | 12 | Not implemented |
| `RT_UF32` | 13 | Not implemented, fictitious |
| `RT_UF64` | 15 | Fictitious |

The generator preserves these records so changes in the reference cannot pass unnoticed. The semantic API has no `F32`, `UF32`, or `UF64` constructor, and lookup rejects all three spellings.

## Pointer raw representation

`RT_PTR` has raw ID 10, the same ID as signed `RT_I64`. The source comment explains that signed representation permits negative error codes. `Primitive_type.pointer_representation` records the alias for later pointer work, but `I64` values do not thereby become pointers.

## Declarations, aggregates, prototypes, and definitions

The current parser grammar is deliberately narrow:

```text
module             := item*
item               := global-declaration | bound-function-prototype
                    | unbound-function-definition
                    | aggregate-forward-declaration
                    | aggregate-definition
                    | top-level-statement
aggregate-forward-declaration := declaration-modifier* "extern"
                                 aggregate-keyword identifier ";"
aggregate-definition := declaration-modifier* aggregate-backing? aggregate-keyword identifier
                        aggregate-base? "{" aggregate-member* "}" aggregate-tail
aggregate-tail       := ";" | global-declarator ("," global-declarator)* [","] ";"
aggregate-backing  := type-specifier pointer-star{0,4}
aggregate-base     := ":" visible-class-name
aggregate-member   := member-declaration | aggregate-offset-directive
                    | anonymous-union | ";"
member-declaration := type-specifier member-declarator
                      ("," member-declarator)* ";"
member-declarator  := pointer-star{0,4} member-declarator-core array-dimension*
                      member-metadata*
member-declarator-core := aggregate-member-name
                        | "(" pointer-star{1,4} aggregate-member-name ")"
                          "(" parameter-list? ")"
aggregate-member-name := identifier | language-keyword
language-keyword    := one of the 48 checked KW_* spellings
member-metadata     := aggregate-member-name member-metadata-value
member-metadata-value := extended-string | core-expression
extended-string     := string-literal+
aggregate-offset-directive := "$$" "=" core-expression ";"
anonymous-union    := "union" "{" aggregate-member* "}" ";"?
aggregate-keyword  := "class" | "union"
global-declaration := declaration-modifier* declaration-binding? type-specifier
                      global-declarator ("," global-declarator)* [","] ";"
bound-function-prototype := declaration-modifier* declaration-binding type-specifier return-declarator
                             "(" parameter-list? ")" ";"
unbound-function-definition := declaration-modifier* type-specifier return-declarator
                                "(" parameter-list? ")" function-body
function-body      := statement-sequence | end-of-input
declaration-modifier := "public" | "static" | "interrupt" | "haserrcode"
                      | "argpop" | "noargpop"
declaration-binding := ordinary-binding | alternate-binding identifier
                     | intern-binding core-expression
ordinary-binding   := "extern" | "import"
alternate-binding  := "_extern" | "_import"
intern-binding     := "_intern"
global-declarator  := pointer-star{0,4} global-declarator-core
                      array-dimension* global-initializer?
global-declarator-core := identifier | global-function-pointer-declarator
global-function-pointer-declarator := "(" pointer-star{1,4} identifier ")"
                                      "(" parameter-list? ")"
global-initializer := "=" initial-value
initial-value      := core-expression | "{" initializer-elements? "}"
initializer-elements := initial-value ("," initial-value)* ","?
return-declarator  := pointer-star{0,4} identifier
parameter-list     := variadic | parameter (("," | ";") parameter)* (("," | ";") variadic)? ";"?
parameter          := register-qualifier* type-specifier register-qualifier*
                      pointer-star{0,4} parameter-declarator? parameter-default?
parameter-declarator := identifier | function-pointer-declarator
function-pointer-declarator := "(" pointer-star{1,4} identifier? ")"
                               "(" parameter-list? ")"
array-dimension    := "[" core-expression? "]"
parameter-default  := "=" (core-expression | "lastclass")
top-level-statement := statement-sequence
statement-sequence := comma* (statement (comma+ statement)* comma*)?
statement          := ";" | statement-expression statement-terminator
                    | print-statement | put-chars-statement
                    | compound-statement | if-statement | while-statement
                    | do-while-statement | for-statement
                    | goto-statement | label-statement | lock-statement
                    | try-catch-statement | break-statement | return-statement
                    | assembly-block-statement | inline-assembly-statement
                    | local-declaration
compound-statement := "{" statement-sequence* "}"
if-statement       := "if" "(" core-expression ")" required-statement-sequence
                      ("else" required-statement-sequence)?
while-statement    := "while" "(" core-expression ")" required-statement-sequence
do-while-statement := "do" required-statement-sequence "while"
                      "(" core-expression ")" ";"
for-statement      := "for" "(" required-statement-sequence
                      core-expression ";" required-statement-sequence?
                      ")" required-statement-sequence
goto-statement     := "goto" identifier statement-terminator
label-statement    := unresolved-identifier ":"
lock-statement     := "lock" required-statement-sequence
try-catch-statement := "try" required-statement-sequence
                       "catch" required-statement-sequence
break-statement    := "break" statement-terminator
return-statement   := "return" (";" | core-expression statement-terminator)
assembly-block-statement := "asm" "{" assembly-token* "}"
inline-assembly-statement := inline-assembly-operation+
inline-assembly-operation := operand-free-opcode ";"?
required-statement-sequence := statement-sequence containing at least one statement
statement-expression := core-expression not beginning with a string or character literal
statement-terminator := ";" | comma-boundary
comma-boundary     := a comma retained by statement-sequence
print-statement     := string-marker print-fixed-argument ("," core-expression)* ";"
put-chars-statement := character-marker character-fixed-argument
                       (";" | comma-boundary)
local-declaration   := type-specifier automatic-local-declarator
                       ("," automatic-local-declarator)* ";"
                     | "static" type-specifier static-local-declarator
                       ("," static-local-declarator)* ";"
automatic-local-declarator := register-qualifier* pointer-star{0,4}
                              identifier array-dimension*
                              ("=" core-expression)?
                            | register-qualifier* pointer-star{0,4}
                              global-function-pointer-declarator
                              array-dimension*
static-local-declarator := pointer-star{0,4} identifier array-dimension*
                           ("=" initial-value)?
                         | pointer-star{0,4}
                           global-function-pointer-declarator
                           array-dimension*
core-expression    := postfix-expression
                    | prefix-operator core-expression
                    | core-expression binary-operator core-expression
postfix-expression := ordinary-primary chain-suffix* postfix-update?
                    | sizeof-expression
                      (type-cast-suffix chain-suffix* postfix-update?)?
                    | offset-expression
                      (type-cast-suffix chain-suffix* postfix-update?)?
                    | defined-expression
                      (type-cast-suffix chain-suffix* postfix-update?)?
ordinary-primary   := literal | identifier | "$$" | "(" core-expression ")"
                    | direct-function-call
direct-function-call := known-function-identifier fixed-argument*
fixed-argument     := omitted-default | core-expression
omitted-default    := no source token for one defaulted fixed parameter
sizeof-expression  := "sizeof" open-parenthesis{n} identifier
                      ("." identifier)* pointer-star* close-parenthesis{n}
offset-expression  := "offset" open-parenthesis{n} identifier
                      ("." identifier)+ close-parenthesis{n}
defined-expression := "defined" open-parenthesis{n} source-token
                      close-parenthesis{n}
source-token        := one non-EOF lexical token other than "("
chain-suffix        := call-suffix | index-suffix | member-suffix
                     | type-cast-suffix
call-suffix        := "(" ")"
                    | "(" call-slot ("," call-slot)* ")"
call-slot          := core-expression?
index-suffix       := "[" core-expression "]"
member-suffix      := "." identifier | "->" identifier
type-cast-suffix   := "(" type-specifier pointer-star{0,4} ")"
postfix-update     := "++" | "--"
prefix-operator    := "+" | "-" | "!" | "~" | "*" | "&" | "++" | "--"
variadic           := register-qualifier* "..."
register-qualifier := "noreg" | "reg" u64-register?
u64-register       := RAX | RCX | RDX | RBX | RSP | RBP | RSI | RDI
                    | R8 | R9 | R10 | R11 | R12 | R13 | R14 | R15
pointer-star       := "*"
primitive          := I0 | I8 | I16 | I32 | I64
                    | U0 | U8 | U16 | U32 | U64 | F64 | Bool
intrinsic-storage  := I0i | I8i | I16i | I32i | I64i
                    | U0i | U8i | U16i | U32i | U64i | F64i
type-specifier     := primitive | intrinsic-storage | visible-class-name
```

Empty and comment-only inputs are valid modules. Declarations retain source order, the exact modifier, binding, type, and identifier spellings, and ordered source segments. A comma-separated group has one shared modifier list, optional binding, and type specifier, plus a source-linked declarator for every name. A type specifier is a checked public primitive, one of the 11 intrinsic storage spellings, or a name currently published as a class symbol. Class and union forwards both use that symbol category, matching `HTT_CLASS`; an unresolved or locally shadowed name does not become a type based on capitalization. Each declaration prefix is a separate ordered AST node. An ordinary `extern` or `import` token becomes a binding node without a target. `_extern` and `_import` store the following target identifier in that node, separate from the HolyC name being declared. `_intern` instead stores a source-positioned expression target. A type-safe target variant keeps these three cases distinct. Each global declarator records an ordinary name or a recursive function-pointer signature, its optional array and initializer suffixes, and its terminating comma or semicolon. Initializer nodes distinguish scalar expressions from recursively braced lists and retain every brace and comma. Return-pointer stars and callback-indirection stars are numbered independently from one through four, and their state starts again for every declarator. A modifier, binding, target, layer, parenthesis, bracket, delimiter, or initializer boundary keeps its raw spelling, generated frame, invocation span, and definition span. Includes and definitions run through the integrated stream before parsing. A parser diagnostic produced inside an include retains its include stack, while a diagnostic on definition-generated text records both the expansion and declaration sites.

`Compiler/PrsStmt.HC` routes `extern class` and `extern union` to `PrsClass` with extern mode enabled. That branch creates a class hash entry, stores the source name, sets `Cf_EXTERN`, attaches source information, and publishes the entry before its next `Lex` call. `Kernel/KernelA.HH:4-17` relies on this order for 14 class names near the start of the main header. `Doc/ScopingLinkage.DD` lists the form in both its JIT and AOT tables.

The AST represents this syntax as a dedicated aggregate forward item. It distinguishes class from union, retains the optional ordered modifiers, ordinary `extern` binding, aggregate keyword, name, semicolon, and composite source provenance, and publishes the accepted name as a class symbol before reading later input. JIT and AOT parser modes accept the same shape. `HCPARSE0107` reports a missing name, while `HCPARSE0108` reports a missing semicolon, a comma list, or a body. Rejected names are not published. A published name can immediately serve as a type specifier in a global, function return, parameter, nested function pointer, automatic or static local, array declarator, or postfix cast. The unfiltered first 27 lines of `Compiler/CExts.HC` exercise those named return and parameter forms after the required forwards are supplied.

For a definition, `Compiler/PrsStmt.HC:PrsClass` creates or reuses the named class entry and adds a newly created entry before its first `Lex` call. After an optional colon, it requires one `HTT_CLASS` symbol and rejects a comma that would introduce a second base. This path runs before the source selects class or union member handling. The parser then delegates both bodies to `Compiler/PrsVar.HC:PrsVarLst`. That routine skips empty semicolons, restarts a member declaration after a comma, parses pointer, array, and function-pointer suffixes through the shared type path, and recursively handles an unnamed `union` body. At global scope, `PrsStmt` consumes a definition semicolon when one is present; otherwise `PrsGlblVarLst` and `PrsType` may continue directly into another class or union definition. The AST keeps a written semicolon and represents that omission as absent. `Demo/Graphics/Pick3D.HC:27-38` places `PObj` directly after the unterminated `PCSprite` definition. `Kernel/KernelA.HH:116-179` supplies 12 consecutive ordinary class definitions with primitive fields, named self references, grouped members, pointers, and arrays. `Doc/HolyC.DD` confirms that a named union is subsequently referenced like a class and states that only one base class is allowed.

The definition AST retains ordered modifiers, an optional backing type with zero through four pointer layers, the distinct aggregate kind, keyword, name, an optional base, both braces, every member, and either a standalone semicolon or attached global declarators. The base record keeps the colon and identifier spellings and locations separately. An ordinary member group keeps one primitive, intrinsic, or visible named type plus independent return-pointer layers, an optional recursive function-pointer declarator, array dimensions, metadata, and comma or semicolon delimiters for each name. An anonymous union owns its recursive member list and records whether a semicolon followed its closing brace. Empty member semicolons remain explicit nodes. The aggregate name enters the parser environment before the base token or members are read, matching the source publication point. Both compile modes share this syntax, and generated definitions retain their invocation and definition locations. `HCPARSE0121` rejects a missing or nonclass base, while `HCPARSE0126` reports a second base. Other `HCPARSE0109` through `HCPARSE0125` diagnostics cover malformed bodies, nested named definitions, unknown backings, and a binding before a backed definition. `HCPARSE0133` and `HCPARSE0134` cover malformed member callbacks. A hosted limit of 256 nested anonymous unions prevents parser exhaustion.

Inside `PrsVarLst`, class mode enables `CCF_CLASS_DOL_OFFSET`, initializes `class_dol_offset` from the current class size or union base, skips ordinary member semicolons, and then accepts repeated `$$ = LexExpression;` directives. The pinned corpus contains four direct forms: `Demo/Lectures/NegDisp.HC:35` starts `Person` at `-128`; `Kernel/KernelA.HH:447` aligns `CKernel`; line 3422 advances `CSysFixedArea` to a page boundary; and line 3806 sets `CFunSegCache` to 64. The aggregate-member AST has a distinct offset-directive node that retains the `$$` marker, equals sign, ordinary HolyC expression, semicolon, complete span, and generated-source provenance. The same member loop covers classes, named unions, and anonymous unions. `HCPARSE0142` reports a missing equals sign, `HCPARSE0018` reports a missing value in the aggregate-offset expression context, and `HCPARSE0143` reports a missing semicolon. Outside an aggregate member list, `$$` remains the existing current-position expression, so `$$=8;` is represented as an ordinary assignment statement rather than an aggregate directive.

Outside class-offset and assembler-expression modes, `Compiler/PrsExp.HC:707-721` lowers `$$` with `IC_RIP` and the internal `RT_PTR` class. The checked function and top-level expression layers represent that result as zero-depth internal `I64`, an address value, and an integer result. Grouping, call arguments, and surrounding scalar expressions retain the same leaf identity. `$$` is not an lvalue, so assignment and update forms receive `HCSEMA0046`. The checked IR lowerer now emits the zero-operand `IC_RIP` producer with that type and the exact source span. It does not choose a concrete instruction address or cover the separate class-offset and assembler relocation branches.

After a class-mode member receives its size and offset, `PrsVarLst` consumes repeated identifier/value pairs. A string value goes through `LexExtStr`, which joins adjacent string tokens; every other value goes through the ordinary `LexExpression` path. Each source entry is prepended to `CMemberLst.meta`, and `MemberMetaData` or `MemberMetaFind` later walks that list. The AST keeps entries in source order, including duplicate names, so semantic analysis can reproduce the source list and its last-written lookup precedence deliberately. Extended strings retain each literal plus the combined decoded bytes, while expression values reuse the ordinary expression tree. All six metadata-bearing members and 13 entries in `Demo/ClassMeta.HC:16-28` parse in JIT and AOT modes. `HCPARSE0144` reports a metadata name without a value. Expression failures name the aggregate-member metadata context. Evaluation, `MLMF_IS_STR`, class metadata allocation, and runtime lookup remain pending.

TempleOS does not assign a distinct lexer token kind to language keywords. `Compiler/Lex.HC:493-514` attaches the hash entry and still returns `TK_IDENT`; `Compiler/PrsLib.HC:PrsKeyWord` interprets that token as a keyword only when the active grammar asks. `PrsType` consequently accepts a keyword spelling whenever it reaches a name slot, and `PrsVar.HC:332-337` is the single routine behind members, globals, parameters, and locals alike. `PrsExp.HC:335`, `:373`, and `:996` repeat the same `TK_IDENT` test for the member paths in `sizeof`, `offset`, and ordinary `.` or `->` access. The OCaml lexer retains its more descriptive keyword token kind, while the parser converts that token to an ordinary source-positioned identifier in each of those slots. This covers ordinary, pointer, array, grouped, and recursive function-pointer declarators in classes, named unions, anonymous unions, global declarations, function names, parameter lists, and function bodies, plus the three member-reference paths.

The lexer checks the current function member list before the global hash tables. If that local lookup succeeds, `PrsExp.HC:761-766` emits the local-variable operand before its keyword switch, and `PrsStmt.HC:1183-1184` routes the token through expression parsing. The OCaml parser applies the same ordering to parameters and locals already visible in its function-wide context. It preserves the identifier's spelling and source provenance in arithmetic, comparisons, calls, indexes, and a leading statement position. A declaration inside a nested block remains visible to later parser routing because TempleOS stores function locals in one member list rather than a block-local parser table.

Global variables and functions follow the next lookup tier. `PrsGlblVarLst` inserts a new `HTT_GLBL_VAR`, while `PrsFunJoin` inserts a named `HTT_FUN`, at the head of the compilation table. `CmpJoin` chains that table before assembler keywords in AOT mode and before the current task table in JIT mode. The first matching global becomes `hash_entry`, so `PrsKeyWord` does not see the same-named keyword record. `PrsStmt.HC:1156-1179` routes the selected record to expression parsing. `PrsExp.HC:842-865` handles a function call and lines 867-904 handle a variable. The OCaml parser follows this source-ordered rule at top level and inside functions, including direct calls, parenthesis-free default calls, and address-of. A keyword spelling without a visible parameter, local, global variable, or global function still follows ordinary keyword dispatch. This keeps `sizeof;` invalid until a prior declaration publishes a suitable variable or function named `sizeof`.

Aggregate declarations follow the same contextual rule because `PrsClass` requires `TK_IDENT` without asking `PrsKeyWord`. Once `class start` is published, `start value;` resolves that class before the keyword table in global and local declaration positions, and `class Derived:start` resolves the same identity as its base. Without a visible class named `start`, the spelling keeps its ordinary keyword role. A pinned scan finds no keyword-spelled aggregate declaration in Compiler, Kernel, Adam, or Demo, so focused JIT and AOT fixtures establish this source-exposed edge. The same scan finds 12 direct `U0 start;` members in `Kernel/KernelA.HH`, `Adam/Gr/Gr.HH`, and `Adam/Gr/SpriteMesh.HC`; the exact `CKernel` region parses through the aligned `sys_gdt` member. `Demo/TimeIns.HC:10` and `Kernel/BlkDev/DskFmt.HC:3` supply keyword-named local groups, while `Adam/Gr/GrMath.HC:9`, `Kernel/KExts.HC:8`, and `Adam/Gr/SpriteNew.HC:41` cover parameters and member paths.

After `PrsClass` consumes the closing brace, it calls `PrsGlblVarLst` with the completed aggregate type unless the next token is a semicolon. That path admits the same pointer, array, comma-list, and initialization syntax as an ordinary global declaration. `PrsVarInit`, `PrsVarInit2`, and `PrsGlblInit` recursively consume scalar and braced initial values. The AST mirrors that handoff with `attached_declarators` and a recursive initial-value tree. Each completed attached name enters the streaming environment before the next token is requested. `HCPARSE0127` through `HCPARSE0130` report a missing initial value, a missing list separator, an unclosed list, and excessive nesting.

The six public integer unions at `Kernel/KernelA.HH:67-113` parse with their exact intrinsic backings. Tests also cover `CDate`, `CICType`, `CAbsCntsI64`, the backed color wrappers, all 17 sprite definitions at `Adam/Gr/Gr.HH:18-115`, and representative kernel inheritance chains. A byte-preserving structural scan finds 37 inherited class headers and 40 valid aggregate definitions with attached globals in the pinned Compiler, Kernel, Adam, and Demo `.HC` and `.HH` set. The attached set contains six pointer forms, 18 array forms, eight comma groups, and four initialized forms. `Compiler/CInit.HC:1-14` supplies all 17 initialized intrinsic type descriptors and parses in both JIT and AOT modes. Four inherited headers occur in files that ordinary text-mode searches treat as binary, so the scan forces byte input. The shared source path still permits a union base, which has a focused syntax test but no corpus claim. Semantic passes now reconcile aggregate identities, validate definition backings and bases, and bind direct member heads to public, intrinsic, or canonical aggregate types. They do not add inherited size, resolve inherited members, evaluate offset directives or metadata, update negative-offset or union-base state, calculate storage, overlap union members, apply alignment, evaluate initializers, or implement subinteger access. Nested named aggregate definitions and automatic local braced initializers remain separate parser gates. Static local initializer, aggregate-offset, and member-metadata syntax are retained without claiming any of those semantic effects.

`Compiler/PrsStmt.HC:PrsStmt` handles visibility, storage, and calling modifiers before it recognizes a binding. The staged assignments are order-sensitive. `public` and each calling modifier retain calling, public, and assembly state. `interrupt` also sets `FSF_NOARGPOP`. `static` keeps assembly state and clears the other staged bits. The AST preserves this source order, and tests fold the nodes through the checked `Function_flag.apply_modifier` model. It does not apply the resulting calling convention or interrupt behavior.

Ordinary `KW_EXTERN` and `KW_IMPORT` select `PRS0_EXTERN` and `PRS0_IMPORT`. The `_extern` and `_import` paths consume a target identifier before the type and select `PRS0__EXTERN` or `PRS0__IMPORT`. `KW__INTERN` instead calls `LexExpressionI64` and selects `PRS0__INTERN`. Its function path assigns the evaluated value to `exe_addr`, sets `Ff_INTERNAL`, and clears `Cf_EXTERN`. `PrsGlblVarLst` rejects both import modes unless the compile controller is AOT; `_intern` has no such gate. The current syntax tree preserves the ordered prefix tokens, binding mode, symbol target, or unevaluated expression target. It does not look up a target, resolve an alias, evaluate an `_intern` address, set internal-function state, allocate storage, or emit an import. A missing alternate target reports `HCPARSE0007`. The routine calls `PrsType` again after a comma while passing the saved base class and mode. `Compiler/PrsVar.HC:PrsType` counts stars and rejects a depth greater than `PTR_STARS_NUM`; the pinned `Kernel/KernelA.HH` sets that value to four. `Compiler/PrsLib.HC:PrsClassNew` creates the matching depth-zero through depth-four class records. The syntax tree records pointer layers and list boundaries. Later semantic passes resolve direct aggregate member heads, member callback parameters, top-level function signatures, globals, and locals. Cast and direct-call dereference results cover the boundary documented below; other type-use conversions remain unresolved. The closed aggregate layout pass covers only its documented dependency set.

`OPTf_EXTERNS_TO_IMPORTS` is applied at the semantic declaration boundary. Each function or global record retains the source binding, the effective binding, and the option mask present at that declaration. When bit 32 is enabled, `extern` becomes an ordinary import and `_extern` becomes an alternate import before function identity selection or global mode validation. Converted imports retain the local name or explicit target name used by `PrsGlblVarLst`. They are rejected in JIT mode through the same AOT-only guard as explicit imports. An `extern class` or `extern union` item stays an aggregate forward because the pinned `KW_EXTERN` branch dispatches it before checking the option. The high-level API currently supplies one mask for a whole batch; executing source-positioned `Option(...)` changes remains later work.

After the identifier, `PrsType` calls `PrsArrayDims`. That routine reads dimensions in source order, accepts an empty expression only in the first pair of brackets, evaluates every sized dimension through `LexExpressionI64`, and requires a closing `]`. The parser mirrors the syntax without performing the evaluation. Each dimension stores both brackets and either a core expression or an explicit unsized state, so `[]` and `[0]` cannot collapse into the same AST. `HCPARSE0022` rejects an empty later dimension, and `HCPARSE0023` reports a missing closing bracket. Dimension expressions use the same checked operator table and 256-level hosted limit as parameter defaults. Negative-size rejection, total element counts, alignment, allocation, and initializers belong to semantic analysis and layout.

The current list grammar accepts forms found in the pinned corpus such as `I64 prime_range,my_mp_cnt,pending;`, `I32 *arg1,*arg2;`, `U8 *ptr,**idx;`, `public extern U8 *rev_bits_table,*set_bits_table;`, `public extern U16 mon_start_days1[12];`, `_extern MEM_BOOT_BASE U32 mem_boot_base;`, and `_intern Bsf I64 Bsf(I64 bit_field_val);`. It also accepts expression dimensions such as `I64 cmp_type_flags_src_code[(DOCT_TYPES_NUM+63)/64];`. Bound prototypes may use ordered and repeated `public`, `static`, `interrupt`, `haserrcode`, `argpop`, or `noargpop` prefixes. Both extern spellings and `_intern` work in every compile mode, while both import spellings work only in AOT mode. Each completed name is published before the parser asks the integrated stream for the next token, so a following conditional can observe it even when the directive appears after a comma. A JIT `import` or `_import` receives `HCPARSE0006` before its declarator is parsed, so the rejected name cannot become visible.

When a bound declaration name is followed by `(`, `Compiler/PrsStmt.HC:PrsGlblVarLst` calls `PrsFunJoin` instead of creating a global variable. `PrsFunJoin` delegates the parentheses and members to `Compiler/PrsVar.HC:PrsVarLst` in `PRS1_FUN_ARG` mode. That path admits omitted parameter names, consumes commas between parameters, and sends `TK_ELLIPSIS` through `PrsDotDotDot`, which establishes `Ff_DOT_DOT_DOT` and the later `argc` and `argv` members. It rejects array dimensions in function arguments.

`PrsVarLst` accepts `reg` and `noreg` in two loops: before a parameter type and immediately after it, before any pointer star or name. `reg` sets `REG_ALLOC`; `noreg` sets `REG_NONE`. A following identifier belongs to `reg` only when `DefineMatch` finds it in `ST_U64_REGS`. The pinned definition contains exactly `RAX`, `RCX`, `RDX`, `RBX`, `RSP`, `RBP`, `RSI`, `RDI`, and `R8` through `R15`. Other register spellings from `OpCodes.DD`, such as `EAX` or `R8u64`, remain available as parameter names in this context. The OCaml parser derives the accepted set from the first R64 record for each register number in the checked opcode database instead of maintaining another register list.

Repeated qualifiers are valid. TempleOS overwrites the working `_reg` value as it reads them, so the final qualifier controls later allocation. The AST keeps every qualifier in source order, records whether it appeared before or after the type, and retains an optional explicit-register identifier. This preserves enough information for the semantic pass to reproduce the overwrite while diagnostics and dumps still show the original spelling. A qualifier may also precede a terminal `...`, matching the `_reg` argument passed to `PrsDotDotDot`. Once `PrsType` runs it no longer looks for one, so `I64 *reg value` names the parameter `reg` and then fails on `value`. A qualifier that follows a complete parameter receives `HCPARSE0013` instead of being silently moved.

The corresponding `Function_prototype` AST node requires one of the five supported bindings. It keeps the ordered prefix nodes, return type and pointer layers separate from the function name, then records both parentheses, every supported parameter type, its register qualifiers and pointer layers, optional parameter names and defaults, comma or semicolon delimiters, and a distinct terminal variadic marker. A written prototype semicolon is retained, but `PrsFunJoin` returns without requiring one, so an omission remains explicit in the AST. `extern U8 *CmdLinePmt();`, `public _extern _SYS_HLT U0 SysHlt();`, and `_intern Bsf I64 Bsf(I64 bit_field_val);` are pinned examples. `Compiler/CExts.HC` supplies named class returns and parameters such as `extern CDoc *DocNew(...)` and `extern CHashClass *PrsClass(CCmpCtrl *cc,I64 keyword)`. Accepted prototypes enter the streaming symbol environment after the parameter list and before the optional semicolon is inspected.

`Compiler/PrsVar.HC:428,692-713` consumes semicolons in the shared variable-list loop. In function-argument mode, a comma and a semicolon both return to the next parameter type; the semicolon also follows the common result-state transition. The only authored function signature found in the pinned tree is `StrPrintHex(U8 *dst,I64 num;I64 width)` at `Kernel/KernelC.HH:106` and `Kernel/StrA.HC:1`. Its second parameter retains a semicolon delimiter in the AST. A trailing parameter semicolon is also accepted and retained. Leading and repeated semicolons become empty parameter entries. Each entry records its delimiter and the number of concrete parameters before it, so dumps preserve order and provenance while semantic parameter consumers continue to see only concrete declarations. Commas never create empty entries.

An unbound name followed by `(` takes the `PrsFun` path instead. `PrsFun` shares `PrsFunJoin` for the signature, publishes the function, and calls `PrsStmt` once for the body. The `Function_definition` AST node therefore keeps the same modifiers, return type, pointer layers, name, parameter list, and variadic marker as a prototype, followed by any statement shape the parser currently supports. The function is visible before the first body token is requested, which permits a recursive call and lets a following `#ifdef` observe it. Header and body tokens may come from different include or definition frames without losing either origin.

The source statement parser treats a lone semicolon as an empty statement and exits cleanly when it encounters EOF. Those cases remain distinct in the AST: `U0 Empty();` has an explicit empty-statement body, while `U0 End()` at EOF has no body node. A bound form such as `extern U0 Prototype();` is still a prototype, and a following block is rejected rather than reclassified as a definition. Primitive local declaration syntax is implemented as described below. Semantic passes now assign function scopes and resolve header types; local storage and execution remain later work.

`Compiler/PrsVar.HC:PrsType` treats `(` followed by one through four stars as a function-pointer declarator. Stars before that parenthesis belong to the callback's return type; stars inside it record the function-pointer indirection. An optional name appears before the closing parenthesis, and `PrsFunJoin` parses the following empty, fixed, or variadic signature. Because that signature returns to `PrsVarLst`, its parameters may contain another function-pointer declarator. The AST represents this recursion directly and retains all four parentheses, each star, names, nested parameters, commas, and definition provenance. The hosted parser rejects a thirty-third nested function-pointer type with `HCPARSE0017`; the pinned corpus does not approach this safety limit.

At global scope, `PrsType` returns that signature through `tmpf_fun_ptr`. `PrsGlblVarLst` then uses pointer-sized storage, stores the callback metadata on the global variable, and sets `GVF_FUN`; it does not turn the name into a direct function. The OCaml AST follows that distinction. A global callback requires a stored name and retains its return stars, one through four indirection stars, recursive parameters, optional arrays and initializer, and declaration delimiter. It enters the streaming symbol environment as a global variable, which lets `#ifdef` observe it without enabling parenthesis-free direct-call syntax. Tests parse `Kernel/KGlbls.HC:32-35` and the four corresponding `extern` declarations in `Kernel/KernelC.HH` in both JIT and AOT modes. `HCPARSE0131` reports missing callback punctuation, `HCPARSE0132` reports a missing global name, and `HCPARSE0017` remains the shared hosted nesting guard. The global type pass resolves these recursive signatures, global record classification sets `GVF_FUN`, and identifier or explicit-dereference calls use the retained signature. Storage, callback value reads, lowering, and execution are not implemented.

In class and union mode, `PrsVarLst` passes its temporary `fun_ptr` slot to the same `PrsType` branch, stores the returned signature on `CMemberLst.fun_ptr`, and sets `MLF_FUN`. The member AST reuses the recursive function-pointer node without publishing the member to the global symbol environment. It retains return stars outside the callback declarator, one through four callback indirections, nested parameters and defaults, a variadic marker, array suffixes, and comma-group delimiters. Tests parse `CMathODE` at `Kernel/KernelA.HH:251-289`, `CDocEntry` at lines 1191-1222, and the key-device definitions at lines 3754-3771 in both compilation modes. The `CDocEntry` fixture omits only its `#assert !($$&7)` line because runtime `$$` is outside the constant preprocessor; the closing brace remains in the fixture. A line-anchored scan finds 26 direct callback-member forms in `KernelA.HH`. That count covers exact `(*name)(` and `(**name)(` lines rather than claiming every possible declarator shape. `HCPARSE0133` reports malformed callback punctuation, `HCPARSE0134` reports a missing member name, and `HCPARSE0017` remains the recursive signature guard. The member-type pass resolves the complete recursive callback signature and records the generated `MLF_FUN` mask `0x8`; ordinary members carry zero. Closed layout assigns pointer-sized storage and an offset, and the member index retains the full callback header during direct or inherited lookup. A following call through `object.member` or `pointer->member` uses that exact header for fixed arguments, omitted defaults, varargs, and return typing in JIT and AOT analysis. Ordinary members and invalid access shapes are rejected at the member site. The compiler still does not evaluate defaults, read callback storage, lower the call, or execute it.

In `PRS1B_FUN_ARG` mode, `PrsVarLst` treats `=` as the start of a default. It first checks for the `lastclass` keyword and otherwise calls `LexExpression2Bin`. It does this for each parameter independently, so a required parameter may follow one with a default. The OCaml parser keeps all three cases distinct: no source default, an ordinary expression default, or a `lastclass` default. Each default retains its equals sign, and the `lastclass` form retains the keyword spelling and location. An explicit `0` is an integer-literal node and is never confused with either absence or `lastclass`. The same grammar applies inside nested function-pointer signatures.

The checked function-type pass consumes accepted prototypes and definitions together with their semantic scopes and the source-ordered aggregate identity map. It resolves each return and fixed-parameter type to a public primitive, intrinsic storage spelling, or the canonical aggregate identity visible at that declaration. Unnamed slots remain in the signature without acquiring a symbol. Callback parameters resolve recursively, including nested defaults and ellipses. Named fixed parameters on the top-level signature map to their collected symbols. The pass retains the default category and origin but does not evaluate the expression or substitute `lastclass`.

Each fixed slot also keeps its complete ordered register-request list. The shared semantic constructor accepts `reg`, `noreg`, or `reg` with one of the 16 canonical U64 registers and rejects incomplete provenance or a spelling/number mismatch. The derived final value is `REG_UNDEF` (`-128`) for no request, `REG_NONE` (`32`) for `noreg`, `REG_ALLOC` (`33`) for plain `reg`, or the explicit register number `0` through `15`. Later qualifiers replace earlier ones for that derived value without discarding their origins. Function-header identity does not compare this metadata, matching the fields used by `MemberLstCmp`.

`PrsDotDotDot` adds `argc` followed by `argv` after the fixed members. Both use internal `I64`; `argc` is scalar and `argv` is array-shaped. The source writes no `argv` extent, while the compiler stores 127 as a placeholder dimension. The semantic model keeps both facts instead of reporting 127 as a source bound or treating `argv` as a C `char **`. Both synthetic records carry exactly `MLF_DOT_DOT_DOT` and receive the same ordered register requests as the ellipsis. Only a top-level function ellipsis receives those synthetic symbol bindings; an ellipsis nested inside a callback retains its signature marker and request list.

Joined headers use a smaller compatibility projection than their retained semantic signatures. Return types compare by resolved class identity. Each argument compares its source name, member class, and evaluated default. A callback parameter compares as an internal `I64i` pointer at the callback declarator depth, so its return type and nested signature do not affect this warning. Register requests, calling flags, array dimensions, and `MLF_LASTCLASS` are also absent from `MemberLstCmp`. `lastclass` compares as zero because its member record was zero-initialized and that parser branch never stores another `dft_val`.

The replaced header's fixed argument count limits the member-list loop, but variadic `argc` and `argv` remain linked after those fixed arguments. This makes the result depend on declaration order for some fixed-versus-variadic changes. The semantic header analysis preserves that rule and uses the current declaration's `OPTf_WARN_HEADER_MISMATCH` snapshot. It requires exact 64-bit or NUL-terminated string payloads from compile-time evaluation and refuses to infer them from syntax. Ordinary default evaluation and call-site materialization are not implemented. The typed-call analysis below separately records `lastclass` substitution. [Issue #236](https://github.com/frankischilling/holyc-ocaml/issues/236) records the header-comparison boundary.

`PrsVarLst` also derives flags for every fixed parameter record. An unnamed slot receives `MLF_NO_UNUSED_WARN`; a callback declarator receives `MLF_FUN`; and every default receives `MLF_DFT_AVAILABLE`. A `lastclass` default adds `MLF_LASTCLASS`. An accepted expression default containing string-literal storage adds `MLF_STR_DFT_AVAILABLE`, including when the string appears below a call, cast, index, member, unary, or binary node. These rules apply independently at each recursive callback level. The current frontend does not accept `TK_INS_BIN` as a default expression, so it makes no claim about that other pinned `CCF_HAS_MISC_DATA` path. Prototype/definition identity and top-level record-flag transitions are implemented separately under issues [#183](https://github.com/frankischilling/holyc-ocaml/issues/183) and [#191](https://github.com/frankischilling/holyc-ocaml/issues/191). Register requests are retained under [issue #234](https://github.com/frankischilling/holyc-ocaml/issues/234), but register allocation, `OPTf_NO_REG_VAR`, request conflicts, call checking, default evaluation, storage, ABI behavior, and completed linkage remain pending.

Saved DolDoc sources store text before a NUL byte and numbered `CDocBin` records after it. In that mode, `$IB,...,BI=n$` selects the bytes for record `n`, while `$IS,...,BI=n$` selects its declared size. `Compiler/Lex.HC:158-180` emits `TK_INS_BIN` and `TK_INS_BIN_SIZE`; `Compiler/PrsExp.HC:681,698-706` lowers them as an integer immediate and a `U8 *` string constant. The AST therefore keeps these as literal expressions with their record number, declared size, and payload-completeness flag. They are not omitted initializer entries.

`Compiler/Lex.HC:93-105,367-439` also preserves saved DolDoc commands that occur inside a HolyC string. When the compiler reads a document entry while `CCF_IN_QUOTES` is set, `LexDollar` quotes the command text and records both dollar delimiters for `LexInStr`. The hosted lexer reads repository bytes instead of a live `CDoc`, so it applies the observable equivalent when a single dollar starts an uppercase DolDoc command name and the command has a closing delimiter. Quotes and backslashes within that range remain literal bytes, while ordinary HolyC escapes outside it keep their existing meaning. Authored `$$…$$` with escaped inner quotes produces the same decoded value. A single dollar with no recognized command and later delimiter remains a literal dollar, matching the raw `LexInStr` path; this rule does not parse, render, or execute DolDoc commands.

Strict decoding requires every 16-byte `CDocBin` header and declared payload to be present. The pinned cia-foundation Git objects contain newline-normalized binary trailers whose stored sizes can no longer locate every record. Corpus compatibility mode may recover headers and retain shortened payloads, but it marks each affected literal incomplete. Ordinary hosted parsing does not enable this recovery. Byte-accurate recovery needs a verified final TempleOS image or another intact oracle source, tracked in [issue #375](https://github.com/frankischilling/holyc-ocaml/issues/375).

The core-expression parser accepts integer, floating, character, multi-character, string, and inserted-binary literals; identifiers; `$$`; grouped expressions; named `sizeof` and `offset` terms; the eight audited prefix operators; every binary operator in the pinned table below; parenthesized call suffixes; parenthesis-free direct calls; bracket index suffixes; direct or pointer member suffixes; primitive, intrinsic, and visible aggregate postfix casts; and postfix `++` or `--`. Consecutive string tokens form one primary expression, with decoded bytes joined in token order. The combined node retains every physical spelling, byte sequence, and location, including definition and include origins. Parameter defaults, array dimensions, call arguments, indexes, and `_intern` targets call this same parser with context-specific stopping rules and diagnostic wording. It uses the table's numeric precedence and association rather than C precedence. Calls, indexes, member accesses, postfix casts, `sizeof`, `offset`, and a terminal postfix update bind before every binary operator. Calls, indexes, members, and postfix casts may repeat in any order after an ordinary primary expression. `IC_POWER` receives the special handling from `PrsExpression2`, so ``-2`2`` is represented as ``-(2`2)``. Each term, postfix delimiter, operator, cast target, and member identifier keeps its source span, generated source, and definition origin. A fixed limit of 256 nested expression parses rejects adversarial input with `HCPARSE0021`.

`Compiler/PrsExp.HC:PrsFunCall` walks fixed parameters in declaration order. When a parameter has `MLF_DFT_AVAILABLE`, a comma or the closing parenthesis selects its default instead of parsing an expression. This permits the documented `Test(,3);` form and corpus calls such as `PrsStmt(cc,,,cmp_flags)`. The AST records every slot as either omitted or provided, attaches each comma to the slot before it, and gives an omitted slot a zero-width insertion location. Empty `Target()` has no slots, while `Target(,)` has two omitted slots. The syntax tree therefore never conflates a hole with an explicit integer zero.

`PrsUnaryTerm` sends a resolved direct function to `PrsFunCall` before it checks for an opening parenthesis. The parser therefore stores a compact call shape on each accepted function entry. It records fixed parameters in source order, optional names, default availability, and the variadic marker. A parenthesis-free call walks that shape. Each defaulted fixed parameter adds an omitted slot without consuming input, while each required fixed parameter parses one adjacent expression. The variadic loop is gated by `needs_right_paren`, so a direct variadic call without parentheses supplies no extra arguments. `&Function` follows a separate address path, and a local or newer nonfunction entry suppresses the direct call.

A controlled native run confirms `Zero;`, an all-default call, one required argument between defaults, two adjacent required arguments, an empty variadic tail, a binary continuation, and address-of suppression. The values are recorded in `test/oracle/parenthesis-free-calls.json`. The AST uses `Parenthesis_free_call` instead of fabricating punctuation. Omitted positions have zero-width call-site locations. `HCPARSE0105` reports a missing required expression, and `HCPARSE0106` rejects a parenthesis-free call whose function entry lacks fixed-parameter shape. Explicit parenthesized calls do not need that parser shape.

`Sema.Function_call_resolution` gives parenthesized and parenthesis-free calls the same fixed-slot treatment. It keeps a provided expression distinct from an explicit hole and from a trailing slot absent in source. Each provided fixed or variadic value carries a semantic source view with its literal or unresolved top-level kind and provenance. Prefix, postfix-update, and binary views retain their recursive operands and operator origins. Either absent form selects the declared default when one exists; a required parameter instead produces `HCSEMA0040`. Extra fixed arguments produce `HCSEMA0041`, and holes after the fixed parameter block produce `HCSEMA0042` because the variadic loop accepts only expressions. Each direct result retains the declaration visible at that source point and the canonical function identity selected by the JIT or AOT join rule. A call through a typed function-pointer parameter, automatic or static local, global, or checked aggregate member instead retains the selected binding or member lookup and its exact callback signature as an indirect call. Identifier, explicit dereference, direct-member, and pointer-member spellings use the same slot rules. Arbitrary computed callees, aggregate spellings, and unresolved outer names stay deferred. This stage does not evaluate an expression or default, read the callback value, lower the call, or execute it.

Ordinary language `defined` expressions keep the one token inspected by `Compiler/PrsExp.HC:936-954`. The shared semantic leaf distinguishes the pinned identifier-token case from a non-name token, retains the exact spelling and operand provenance, and separately retains the complete expression origin, including repeated wrapper parentheses. Function-body and executable top-level adapters use the same record in JIT and AOT mode, so grouping, operators, casts, call arguments, statements, conditions, and returns do not lose that evidence. This stage does not repeat the preprocessor's `defined(...)` logic, consult local or hash tables, choose `TRUE` or `FALSE`, or emit `IC_IMM_I64`.

The typed-result pass gives each selected default an immutable semantic record without pretending that the caller supplied an expression. The record keeps the exact parameter and default-use identity, resolved parameter type, forwarded result class, ordinary-expression or `lastclass` kind, and the materialization path selected by compilation mode. JIT uses the immediate path. AOT uses the string-constant path for a string-bearing expression default or `lastclass`, and the immediate path otherwise. This is classification only: the compiler does not yet evaluate or copy the stored payload, allocate a string, create a fixup, emit IC, place an argument, or execute the call. A `lastclass` record separately retains the preceding provided result and its source-compatible base spelling.

Return statements have a separate checked result recorded in source order. The result keeps the return keyword and statement origins, optional expression, declared function result type, and the expression's immutable semantic facts. Following `Compiler/OptPass3.HC:249-257`, an integer-side value returned from an `F64` function records `ICF_RES_TO_F64` intent, while an `F64` value returned from another result class records `ICF_RES_TO_INT` intent. Pointers and by-value aggregates stay on the nonfloating path unless a source-visible aggregate backing selects `F64`. `Compiler/PrsStmt.HC:1111-1118` uses class size only for warnings, so a missing value and an unexpected value remain distinct facts rather than hard errors. Return IR, leave-label control flow, active-`try` unwinding, register placement, and execution are not part of this pass. [Issue #292](https://github.com/frankischilling/holyc-ocaml/issues/292) records the boundary.

After a provided fixed expression is optimized, `PrsFunCall` forwards its class and the parameter member class through `OptClassFwd`. A scalar target whose forwarded raw type is `RT_F64` can receive `ICF_RES_TO_F64`; every other fixed target can receive `ICF_RES_TO_INT` when the actual expression is `F64`. `Sema.Function_call_conversion_policy` retains that target split. It follows by-value aggregate backing chains, while a pointer or callback stays on the integer path even when its pointee or return type is `F64`. Declared defaults and provided variadic expressions keep their separate source paths. `Sema.Function_call_conversion_decision` implements the actual half for literals: integer, character, and string literals take the integer path; float literals take the `F64` path; parentheses preserve the result. The pinned `$$`, `sizeof`, `offset`, and `defined` primary paths also produce non-`F64` results before this comparison, so the same decision module classifies them on the integer side without evaluating their values. Bound identifiers reuse the exact occurrence selected by function and module expression binding. Parameters, automatic and static locals, synthetic varargs, and source-visible globals then use their checked semantic type. Scalar `F64` and `F64i` objects take the floating path; other primitive objects take the integer path; and a by-value aggregate follows backing headers visible before the caller. Arrays, callbacks, and synthetic `argv` retain a pointer-shaped value class instead of inheriting their declared base type. Synthetic `argc` remains an integer object. Outer candidates are not assigned a guessed type. `PrsUnaryModifier` assigns a postfix cast target directly to the expression class. The semantic source view therefore uses a scalar public `F64` or intrinsic `F64i` cast as the floating result and every other primitive or pointer cast as the non-`F64` result. A named aggregate cast retains the identity visible before its caller. Its by-value result follows backing headers published before that source position, while a pointer stops on the integer path. An outer cast replaces the operand class. [Issue #460](https://github.com/frankischilling/holyc-ocaml/issues/460) also retains the exact checked operand beneath that cast result. Nested casts keep their immediate cast child, and a cast around grouping or a binary tree keeps that checked wrapper or binary root. That semantic edge allocates no IR. [Issue #462](https://github.com/frankischilling/holyc-ocaml/issues/462) consumes it for checked primitive numeric trees and emits `IC_HOLYC_TYPECAST` with the full cast span and source-derived `was_paren` payload. Numerical conversion and folding remain later work. Prefix views retain the operator and recursive operand. The pinned unary-plus and unary-minus paths forward that operand class. `OptPass012` leaves logical not on the operand class, including `F64`, while address-of produces a pointer and therefore takes the integer path. Its `IC_COM` branch assigns internal `I64` to the pushed result after optional immediate folding, so bitwise complement takes the integer path without evaluating its operand here. `PrsExpression2` constructs `IC_PP_` or `IC_MM_` with the same forwarded operand class used by the postfix forms, and `OptPass012` keeps that class. Prefix dereference removes one checked pointer layer and forwards the pointee through the backing headers visible before the caller. The combined decision records no conversion, `ICF_RES_TO_F64` intent, or `ICF_RES_TO_INT` intent. The later expression-result pass validates update storage. These passes do not read identifier storage, evaluate an expression, apply an update, or emit an IC flag.

`Sema.Function_call_expression_result` now performs the source-result half before target conversion. It assigns deterministic IDs while walking provided fixed arguments and then each provided variadic argument in source order. Every result keeps the source origin, known semantic type, value category, remaining array rank, intrinsic conversion requirement, forwarded result class, and any separate execution class in one immutable record. A nested resolved direct or typed indirect call also keeps the exact call-resolution record. `PrsFunCall` carries `tmpf->return_class` on its call and cleanup ICs at lines 547-586, so the semantic result uses the return type from the active direct header or callback signature visible at the nested call. Pointer returns are address values; zero-depth returns are object values; a by-value aggregate return follows only the backing headers already visible to the caller. A nested identifier used by address-of, an update, or assignment remains an lvalue; the completed parent is an address or object value. Prefix dereference follows the pointer-class adjustment at `PrsExp.HC:145-154`: it removes one semantic pointer layer without changing the public, intrinsic, or aggregate base. When the source class has no pointer stars, the class remains unchanged; `OptPass012.HC:275-289` handles the separate `U0` warning later. An array already supplies an address in the pinned parser, so dereferencing it yields its declared element type without subtracting a stored pointer layer. `PrsPopDeref` removes the pending data dereference for a callback, so that result is a function value. The dereference node remains an lvalue beneath address-of, an update, or assignment and becomes an object value in an ordinary call argument. A caller-supplied outer global record may retain the checked `CHashGlblVar` class, recursive callback header, and array rank selected by `PrsExp.HC:867-904`. The result engine uses those facts for primitive, pointer, aggregate, array, and callback leaves while keeping the exact outer occurrence and binding. A record with no checked type remains unavailable instead of becoming a guessed pointer. Scalar and fully indexed outer callback calls reuse `Function_call_resolution.bind_indirect_arguments`, keep that occurrence and binding on both the call and its result, and derive the return type from the supplied recursive header. An indexed call additionally keeps the typed outer base and every integer-target subscript result. Partial, excessive, or absent indexing of an array callback produces `HCSEMA0046`. Ordinary outer objects remain unavailable as callees. Unknown callees at the start of a hosted function statement currently require explicit grouping, such as `(OuterCallback)()`, because the parser still distinguishes that position from unresolved declaration syntax. `Sema.Function_call_conversion_decision` consumes the exact root result. Fixed paths record target-specific conversion intent; variadic paths record the actual class without inventing a target or conversion. Results are owned by the semantic session, aggregate member index, policy traversal, and optional outer-expression batch that produced them. Assignment execution, runtime outer storage and address selection, unrelated computed callback-call checking, default evaluation, variadic promotion, ABI placement, and hidden argument-count construction remain outside this boundary. [Issue #332](https://github.com/frankischilling/holyc-ocaml/issues/332) records typed outer values in function expressions, [issue #336](https://github.com/frankischilling/holyc-ocaml/issues/336) records scalar outer callback calls in executable top-level code, [issue #338](https://github.com/frankischilling/holyc-ocaml/issues/338) records scalar outer callback calls in function bodies, [issue #340](https://github.com/frankischilling/holyc-ocaml/issues/340) records fully indexed callback arrays in function bodies, and [issue #344](https://github.com/frankischilling/holyc-ocaml/issues/344) records the executable top-level outer-array path.

`PrsUnaryTerm` gives `&Function` its own branch at `PrsExp.HC:620-671`, before the generic `IC_ADDR` path. The selected source-visible `CHashFun` is retained as a direct-function value with its source publication, exact resolved declaration, and canonical joined identity. Address-of then keeps the internal `RT_PTR` type, which aliases intrinsic `RT_I64`, at pointer depth zero. It does not apply the ordinary object rule that adds a pointer layer. The parser's bare-function branch remains separate and still selects `PrsFunCall`, so this does not turn a normal function name into a first-class value. Local or global storage with the same spelling and function-pointer variables continue through their existing object or callback paths.

The checked declaration state selects one explicit semantic path. A JIT unresolved extern uses its `exe_addr` slot; a resolved JIT function uses an immediate address; and a resolved AOT function supplies an absolute-address input. Ordinary AOT externs and imports report `HCSEMA0046` at `&`, matching the `Cf_EXTERN` rejection outside assembly. `_extern` clears that state and therefore takes the resolved AOT path. `_intern` functions stay outside the pinned noninternal branch and receive an explicit unsupported diagnostic. These records describe later work: they do not read a slot, assign a numeric address, create `IC_DEREF`, `IC_IMM_I64`, or `IC_ABS_ADDR`, emit an import or relocation, or lower an expression. [Issue #286](https://github.com/frankischilling/holyc-ocaml/issues/286) records the retained function value, and [issue #288](https://github.com/frankischilling/holyc-ocaml/issues/288) records the mode-sensitive path.

## Local declarations

Inside a function, `Compiler/PrsStmt.HC:PrsStmt` routes a known `HTT_CLASS` or `HTT_INTERNAL_TYPE` to `PrsVarLst` instead of the global declaration path. A leading `static` selects the static-local mode. Automatic locals may place `reg` or `noreg` after the shared type on each declarator, and `reg` may consume one canonical U64 register name. `PrsType` may return ordinary pointer layers or a recursive callback signature. `PrsVarLst` then reads the local name or callback name, any array dimensions, and either a comma or the final semicolon. An ordinary automatic initializer is one `PrsExpression`; an ordinary static initializer enters `PrsStaticInit`, which delegates to recursive `PrsVarInit2`. Callback locals have no direct initializer path. It calls `MemberAdd` before parsing an ordinary initializer or requesting the following token, so a new name is visible in its own initializer and in later declarators.

After `PrsVarLst` returns, `PrsStmt` exits only when the next token is `}`. Otherwise it continues its loop without requiring a statement comma. The AST records all statements consumed by that one source call in a `statement_sequence`, even when every separator is a semicolon. This matters in unbraced control flow. In `if(0) I64 branch=1;out=7;`, both the declaration and assignment belong to the false branch. Braces stop the continuation at `}`. A native run against the pinned compiler produced `0` for the unbraced form and `7` for the braced comparison.

The AST keeps the storage class, shared primitive or named type specifier, and every declarator in source order. Each declarator records its own register request, optional explicit register, pointer layers, optional recursive callback signature, array dimensions, initializer, and delimiter. `Adam/Snd/SndMath.HC` supplies a comma group with repeated `reg`; `Demo/Asm/AsmAndC1.HC` and `Demo/Asm/AsmAndC2.HC` show `noreg` and explicit `R15`; and `Kernel/KMisc.HC` supplies grouped scalar static initializers. ## Top-level statement sequences

`PrsStmt` skips leading commas before selecting a statement form. It accepts a lone semicolon, parses an ordinary expression, and returns only when the next token is not a comma. A comma may replace the semicolon after an expression, and repeated commas are skipped before the next statement. The same loop applies when a semicolon-terminated statement is followed by a comma.

The AST keeps ordinary expression, empty, `goto`, label, `break`, and `return` statements and comma-linked sequences as different shapes. A sequence records every leading comma, every statement in source order, and every following comma. Expressions, `goto`, `break`, and value-bearing returns record whether they ended with their own semicolon or at another valid boundary. A group containing only commas has no semantic statements but still keeps those source locations, matching the pinned loop's behavior at end of input.

At top level, a known global or function name can begin an expression statement. An identifier absent from the current symbol environment becomes a label only when the next token is `:`; otherwise it stays on the unresolved declaration path. This prevents a known global or function followed by `:` from silently changing meaning. Labels and `goto` statements also work after sequence commas. The same sequence representation is used recursively inside compound blocks, conditional branches, loop bodies, and function definitions. Within a function, a known primitive type can begin a local declaration at the same sequence boundaries. A local declaration also continues directly into the next statement unless a closing brace ends the current block. `HCPARSE0047` reports a missing expression-statement terminator. `HCPARSE0048` reports another unsupported form at a comma boundary.

## Compound statements

When `PrsStmt` sees `{`, it advances past the opening brace and calls itself until it reaches `}` or end of input. This makes empty and nested blocks ordinary statement forms. After consuming the closing brace, a comma continues the surrounding `PrsStmt` loop; without that comma, the current statement group ends.

The AST records both braces, every child statement in source order, and one location spanning the complete block. A block may appear at top level or inside another block. Its children use the same expression, empty, output-literal, sequence, conditional, loop, `goto`, label, `break`, `return`, and block nodes as top-level statements. Include and definition expansions retain their normal origins on either brace.

This is a syntactic boundary only. A block does not create a semantic scope yet, whether it appears at top level, inside another block, or as a function body. Primitive locals in a function join its function-wide parser context even when they appear in a nested block. Storage, lifetime, lowering, and execution remain unimplemented. `HCPARSE0049` reports end of input before a closing brace and points back to the opener. `HCPARSE0050` reports a top-level closing brace without a matching opener. A comma immediately before `}` still expects another statement and receives `HCPARSE0048`, matching the source loop rather than treating the comma as an optional trailing delimiter. The hosted parser accepts at most 256 nested blocks and reports `HCPARSE0051` beyond that point. This fixed guard is a denial-of-service limit, not a TempleOS syntax rule.

## Conditional statements

`Compiler/PrsStmt.HC:PrsIf` requires `(` immediately after `if`, parses one ordinary expression, requires `)`, and then calls `PrsStmt` for the then branch. If the following keyword is `else`, it calls `PrsStmt` again for that branch. Recursive statement parsing gives an `else` to the nearest unmatched `if` without a separate disambiguation rule.

The AST records the `if` keyword, both parentheses, the condition, the complete then branch, and an optional else clause with its own keyword and branch. A branch may be an empty, expression, output, sequence, block, loop, `break`, `return`, or nested conditional statement. Comma-linked branch statements use the same sequence node as top-level and block input. JIT and AOT modes share this syntax, and tokens supplied by an include or definition keep their normal provenance.

This pass does not convert the condition to a Boolean, resolve names, validate branch types, build control flow, lower `IC_BR_ZERO`, or execute either branch. `HCPARSE0052` and `HCPARSE0053` report missing condition parentheses. `HCPARSE0054` and `HCPARSE0056` report missing then and else branches, while `HCPARSE0055` reports an unmatched `else`. The hosted parser accepts at most 256 nested conditional statements and reports `HCPARSE0057` beyond that point. This guard limits recursive parsing of untrusted input; it is not a TempleOS language limit.

## While statements

`Compiler/PrsStmt.HC:PrsWhile` requires `(` immediately after `while`, parses one ordinary expression, requires `)`, and calls `PrsStmt` for the body. The source emits a condition branch, parses the body with the loop's break label, and emits a jump back to the condition. The current parser preserves this syntax without claiming those executable semantics.

The AST records the `while` keyword, both parentheses, the condition, and the complete body. A body may use any currently supported statement form, including blocks, comma-linked sequences, nested loops, and conditionals. Recursive parsing keeps the usual dangling-`else` behavior: an `else` after an `if` whose body is a loop belongs to that `if`, while an `else` inside a loop body belongs to the nearest inner `if`. JIT and AOT modes share the node, and include or definition frames keep their normal provenance.

`HCPARSE0058` and `HCPARSE0059` report missing condition parentheses, while `HCPARSE0060` reports a missing body. The hosted parser accepts at most 256 nested loop statements and reports `HCPARSE0061` beyond that point. The count is shared with `do ... while` so mixed nesting cannot bypass the guard. This is a denial-of-service limit, not a TempleOS language rule. Break-target validation, condition truth conversion, label creation, control-flow construction, semantic checks, IR lowering, and execution remain unimplemented.

## Do-while statements

`Compiler/PrsStmt.HC:PrsDoWhile` emits the loop-entry label before it asks `PrsStmt` to parse the body. It then requires `while`, an opening parenthesis, one ordinary expression, a closing parenthesis, and a final semicolon. The source branches back to the entry label when the condition is nonzero, so the body precedes the condition both syntactically and at execution time.

The AST records the `do` and `while` keywords separately, the complete body, both condition parentheses, the condition, and the required final semicolon. The body uses the common statement path and therefore accepts blocks, comma-linked sequences, pre-test or post-test loops, conditionals, output statements, ordinary expressions, and empty statements. Nearest-`if` else association remains unchanged across the loop boundary. JIT and AOT modes use the same syntax, and every token retains include or definition provenance.

`HCPARSE0062` reports a missing or comma-only body. `HCPARSE0063` through `HCPARSE0066` cover a missing `while`, opening parenthesis, closing parenthesis, or final semicolon. An empty condition uses the shared `HCPARSE0018` expression diagnostic. Mixed `while` and `do ... while` nesting shares the 256-level `HCPARSE0061` guard. Break-target validation, condition truth conversion, label creation, `IC_BR_NOT_ZERO`, semantic checks, IR lowering, and execution remain unimplemented.

## For statements

`Compiler/PrsStmt.HC:PrsFor` requires `(`, then delegates the initializer to the ordinary statement parser. This makes a lone semicolon a valid empty initializer. The condition is a required expression followed by a required semicolon. The update is optional; when present, `PrsFor` calls `PrsStmt` with semicolon checking disabled, so the update stops at `)` and may retain comma-linked statements. The loop body returns to the normal statement path.

The AST keeps the keyword, both parentheses, initializer statement, condition, condition semicolon, optional update statement, and body as separate fields with source provenance. An absent update remains `None` rather than an invented empty statement. Bodies and header statements use the common recursive representation, so existing blocks, conditionals, loops, output statements, expressions, empty statements, and comma-linked sequences keep their usual shapes. A primitive local declaration cannot occupy the initializer. Its source parser continues beyond the declaration semicolon and consumes the condition as another statement, after which `PrsFor` reports `Missing )`. The hosted parser rejects the same form with `HCPARSE0069`.

`HCPARSE0067` reports a missing opening parenthesis. `HCPARSE0068` reports a missing initializer statement, while an empty condition uses `HCPARSE0018`. `HCPARSE0069` reports the missing condition semicolon, `HCPARSE0070` reports an invalid update boundary or missing closing parenthesis, and `HCPARSE0071` reports a missing or comma-only body. All three loop forms share the 256-level `HCPARSE0061` hosted guard. Break-target validation, condition truth conversion, internal control-flow label creation, deferred update control flow, semantic checks, IR lowering, and execution remain unimplemented.

## Break statements

The `KW_BREAK` branch in `Compiler/PrsStmt.HC:PrsStmt` consumes the keyword, requires an active `lb_break`, emits `IC_JMP` to that label, and then joins the common statement terminator path. That path accepts `;` or a statement comma when semicolon checking is active. `PrsFor` disables semicolon checking for its update, so that boundary stops before `)` instead of inventing a terminator. `Compiler/CompilerA.HH` assigns `KW_BREAK` value 19, and `Doc/HolyC.DD` uses `break;` throughout its switch examples.

The AST retains the keyword, an optional semicolon, and the complete statement location. A comma-terminated `break` has no semicolon and remains the first element of the ordinary statement-sequence node. A `break` parsed as a `for` update also has no semicolon. Blocks, loops, conditionals, top-level tooling mode, includes, and definition expansions all use the same node and preserve their normal provenance.

This parser intentionally accepts the source shape before it knows whether a loop or switch encloses it. The semantic control-flow pass must reproduce the source `lb_break` check and reject a missing target. `HCPARSE0072` reports a token other than `;` or `,` at an active statement boundary. Recovery stops before an enclosing block close so the parser does not add a false missing-brace diagnostic. Jump-label creation, IR lowering, and execution remain unimplemented.

## Return statements

The `KW_RETURN` branch in `Compiler/PrsStmt.HC:PrsStmt` first requires a current function. It emits one `SysUntry` call for each active `try` region, then treats an immediate semicolon as a valueless return. Otherwise it parses an expression, emits `IC_RETURN_VAL`, marks the function as having a return, and jumps to the function's leave label. The branch finishes through the common statement terminator, so a value-bearing return may end at `;`, at a statement comma, or before `)` in a semicolon-free `for` update. A valueless form requires its immediate semicolon; `return,` is not shorthand for `return;`.

The AST retains the keyword, an optional value expression, an optional semicolon, and the complete statement location. It accepts the syntax at top level for tooling and in every recursive statement context, while preserving include and definition provenance. Semantic validation now rejects an explicit return anywhere under an executable top-level statement with `HCSEMA0066`; function definitions are outside that traversal. Function returns still require value checking, active-`try` unwinding, function metadata, leave-label resolution, and lowering to `IC_RETURN_VAL` plus the jump. `HCPARSE0073` reports an invalid boundary after a parsed value, and `HCPARSE0074` reports a missing value when the token after `return` cannot begin one. Recovery leaves an enclosing `}` available to the block parser.

## Goto statements and function labels

The `KW_GOTO` branch in `Compiler/PrsStmt.HC:PrsStmt` requires an identifier, finds or creates a `CMT_GOTO_LABEL`, increments its use count, emits `IC_JMP`, and joins the common statement terminator. The unresolved-identifier branch finds or creates the same label record, rejects a second definition, marks the label defined, emits `IC_LABEL`, and requires `:`. A local variable remains on the expression path. `COCGoToLabelFind` searches both language and assembly label records within the current code-control list, while `COCDel` detects unresolved and unused labels. `Doc/ScopingLinkage.DD` records function scope and the source compiler's confusing failure when a label collides with a global object.

The AST uses separate `goto_statement` and `label_statement` nodes. A goto keeps its keyword, identifier target, optional semicolon, and complete location; a label keeps its name, colon, and location. The shared comma sequence records a comma boundary, and a goto in a `for` update stops before `)` without inventing a semicolon. An absent name immediately followed by `:` selects the label path. Known globals and functions retain expression routing, which preserves the source collision instead of quietly accepting a label. Include and definition expansions keep their normal origins in both dump formats. `HCPARSE0075` reports a missing or nonidentifier target, and `HCPARSE0076` reports a token other than `;` or `,` at an active boundary.

Top-level label syntax is accepted only as a tooling representation until function definitions exist. Native HolyC rejects a language label without a current function. Semantic work must assign stable function-scoped label IDs, resolve forward and backward references, diagnose duplicate, unresolved, unused, and colliding names, and lower `IC_LABEL` and `IC_JMP`. No binding, control-flow construction, lowering, or execution is claimed by this parser slice.

## Lock statements

`Compiler/PrsStmt.HC:PrsStmt` consumes `lock`, increments `CCmpCtrl.lock_cnt`, parses one ordinary statement, and then restores the count. This accepts a compound statement such as `lock {value++;}` and the unbraced `lock value++;` form used by `Demo/MultiCore/Lock.HC`. Because the nested call is the normal statement parser, a lock may contain another lock or a comma-linked statement sequence. `Compiler/PrsLib.HC:ICAdd` adds `ICF_LOCK` to instructions created while the count is nonzero.

The AST retains the `lock` keyword, its recursively parsed body, and their complete combined location. It does not flatten the body because later IR lowering needs the lexical region. The syntax is available in JIT and AOT parser modes, at top level for tooling, and inside every implemented recursive statement context. Include and definition expansions retain their ordinary provenance in human and JSON dumps.

`HCPARSE0077` reports a missing or comma-only body. An independent 256-level `HCPARSE0078` hosted guard prevents unbounded recursion through repeated unbraced locks; no corresponding TempleOS language limit was found. This parser slice does not mark IR instructions with `ICF_LOCK`, determine whether an operation accepts an x86 `LOCK` prefix, select machine instructions, or execute multicore code.

## Switch statements

`Compiler/PrsStmt.HC:PrsSwitch` accepts two header forms. `switch (expression)` is the bounded form associated with `IC_SWITCH`, while `switch [expression]` is the no-bound form associated with `IC_NOBOUND_SWITCH`. Both forms require a braced body. The body may contain ordinary statements, `case:`, `case expression:`, inclusive `case low...high:`, and `default:`. `KW_DFT` is the pinned compiler's internal keyword name; the spelling entered in HolyC source is `default`. An implicit case starts at zero or advances from the previous case. The source compiler also swaps a reversed range before populating its jump table.

`start:` and `end:` delimit a sub-switch region. The pinned compiler keeps a stack of these regions, creates a separate break label for each one, and treats statements before the first case in a region as its front porch. The language guide restricts control transfers out of that front porch. The AST preserves this structure as recursive elements instead of flattening `start` and `end` into ordinary labels. It also keeps the selected delimiter mode, expression, braces, each case pattern, default labels, ordinary statements, and full source order. Switches can appear wherever the shared statement parser is currently available, including blocks, loops, `for` updates, conditionals, locks, and try or catch bodies. JIT and AOT syntax is identical, and include or definition frames keep the provenance of delimiters and labels.

Inside a checked function, each selector has a source-ordered semantic result and an explicit bounded or no-bound mode. The result retains the switch keyword and statement origins, expression type, integer or `F64` class, and any nested direct or callback call. It remains the source expression value. This pass does not subtract the lowest case value or choose between `IC_SWITCH` and `IC_NOBOUND_SWITCH`. [Issue #296](https://github.com/frankischilling/holyc-ocaml/issues/296) records this boundary.

The switch diagnostic codes from `HCPARSE0084` to `HCPARSE0097`, with `HCPARSE0089` unused, report the hosted depth limits and malformed headers, braces, ranges, colons, or sub-switch boundaries. Recovery stops at the next structural label or enclosing switch close, but a recovered error still removes the public AST. This slice does not evaluate case expressions, assign implicit values, swap range endpoints, reject duplicates, validate a default, enforce front-porch transfer rules, bind `break`, create jump tables, emit switch or sub-call ICs, lower control flow, or execute a switch.

## Try and catch statements

`Compiler/PrsStmt.HC:PrsTryBlk` compiles a required statement after `try`, requires `catch`, and then compiles another required statement. Both calls use the ordinary statement parser with an incremented active-try count, so braces are optional and either side may contain another pair or a comma-linked sequence. The compiler surrounds the first body with calls to `SysTry` and `SysUntry`, installs handler labels, and uses the active count when a `return` must leave nested try regions. `Compiler/PrsExp.HC` and `Kernel/Job.HC` contain unbraced forms, while `Demo/Exceptions.HC` contains braced and nested forms. `Doc/HolyC.DD` also notes that lowercase `throw` is an ordinary function call, not a separate statement keyword.

The AST retains the `try` keyword, recursively parsed body, `catch` keyword, recursively parsed handler, and complete paired location. It accepts the syntax in JIT and AOT modes, at top level for tooling, and in every implemented recursive statement context. Definition and include frames keep their usual provenance. The parser does not invent an optional handler or flatten either side.

`HCPARSE0079`, `HCPARSE0080`, and `HCPARSE0081` report a missing body, missing `catch`, or missing handler. A standalone `catch` reaches the pinned compiler's generic `Missing expression` path; the hosted parser preserves rejection but uses the more useful `HCPARSE0082` message. An independent 256-level `HCPARSE0083` guard bounds recursive unbraced pairs, with no matching source-language limit identified. This slice does not emit `SysTry` or `SysUntry`, allocate handler labels, transfer exceptions, unwind returns, lower `throw` calls, or execute exception code.

## `no_warn` statements

`Compiler/PrsStmt.HC` advances past `KW_NO_WARN` and calls `PrsNoWarn`. That routine visits identifiers while `cc->local_var_entry` names the active function member, sets `MLF_NO_UNUSED_WARN`, and advances across one comma after each target. The accepted names are therefore fixed parameters, synthetic variadic `argc` and `argv`, and locals already published in the function-wide parser context. A global, an unresolved spelling, or a later local is not a valid target.

The internal comma and the outer statement comma are separate. `no_warn a,b;` keeps one comma between targets, while `no_warn a,b,;` also keeps the comma after `b`. If another comma follows, the common `PrsStmt` loop owns that second comma as a statement separator. An empty `no_warn;` is valid. In a `for` update, an empty form may end at `)`, and a named form may do so only after its internal trailing comma. A named target without either a comma or semicolon follows the pinned `Expecting ','` failure path.

The AST records the keyword, ordered targets, every internal comma, an optional semicolon, and complete source provenance. `HCPARSE0157` reports a token or name that is not a visible parameter or local. `HCPARSE0158` reports a missing target delimiter or statement boundary.

`MemberFind` increments `use_cnt` when the target token is read, so a suppression contributes one lookup. Function completion first checks `MLF_NO_UNUSED_WARN`: a count greater than one reports an unneeded suppression unless the name is `_anon_`. Without that flag, a zero count reports an unused variable only when `OPTf_WARN_UNUSED_VAR` is enabled. A local initializer resets the declared local's count after parsing its value; uses of earlier bindings in the same initializer remain counted.

The semantic binding stream keeps an ordinary use, a specialized name query, a `no_warn` lookup, and an initializer reset as different source-ordered events. A query represents the root of `sizeof` or `offset`, or the single operand of `defined` when that operand has name shape. It never represents a member-path spelling or a non-name `defined` operand. `Sema.Local_warning_analysis` exposes separate ordinary, query, suppression, and combined counts without changing the session symbol table. Prototypes receive no body warnings. `HCSEMA0031` and `HCSEMA0032` reject inconsistent suppression or reset events, `HCSEMA0033` rejects inconsistent warning inputs, and the structured findings use `HCSEMA0034` for an unused variable and `HCSEMA0035` for an unneeded `no_warn`.

A query contributes only when its root resolves to a parameter or a local visible at that source position. The declared local's post-initializer reset clears both ordinary and query uses of itself while preserving uses of earlier bindings. This result is counting evidence only: member lookup, operator values, type syntax, labels, and assembly tokens are unresolved. The API accepts one compiler-option mask for the batch until source-positioned `Option(...)` execution supplies a state for each function. The warnings are available through `holyc_lib`; no `holyc check` renderer exists yet.

## Brace-delimited assembly statements

`Compiler/PrsStmt.HC:PrsStmt` dispatches `asm` to the assembly block path in both compilation modes. The top-level AOT path calls `Compiler/Asm.HC:PrsAsmBlk` directly, while top-level JIT and function compilation join through `CMPF_ASM_BLK`. `PrsAsmBlk` requires `{`, consumes assembly tokens until `}`, recognizes label delimiters, and selects directives and instructions through the `HTT_ASM_KEYWORD` and `HTT_OPCODE` records loaded from `Compiler/OpCodes.DD`.

The AST retains a brace-delimited assembly statement as structure rather than opaque text. It keeps the keyword, both braces, every source token, and display groups based on physical source lines. It also records ordinary global `name:`, exported global `name::`, and local `@@name:` labels. Canonical opcodes retain their spelling; aliases retain both their source spelling and canonical opcode. Directives retain their TempleOS IDs, and registers retain their source family and number. Other identifiers, language keywords, literals, operators, and punctuation remain explicitly classified. Definition-generated tokens and included blocks keep the same provenance used elsewhere in the parser.

Physical lines are only a deterministic dump aid. The source assembler can place more than one operation on a line, and the parser does not infer instruction boundaries from newline positions. Brace-delimited body tokens are not yet split into operand nodes. The parser also does not validate directive arguments, select an encoding form, resolve labels, create fixups, or emit bytes.

A raw-token audit at the pinned commit finds 45 brace-delimited blocks in 40 `.HC` and `.HH` files under `Compiler`, `Kernel`, `Adam`, and `Demo`. Six occur inside another source block. `reference/assembly-blocks.json` records every path, line, and top-level or nested context. `HCPARSE0145` reports a missing opening brace, and `HCPARSE0146` reports end of input before the close.

## Function-local direct assembly statements

`PrsStmt` recognizes `HTT_OPCODE` and `HTT_ASM_KEYWORD` records directly inside a function. It rejects either form without a current function and otherwise joins `PrsAsmBlk` with `CMPF_ASM_BLK | CMPF_ONE_ASM_INS`. That entry skips the opening brace. `PrsAsmBlk` checks the first instruction form's `arg1` and `arg2` fields, dispatches assembler directives by their checked keyword IDs, and may continue when another opcode or assembler keyword follows. The continuation is token-based rather than line-based.

The AST implements a source-ordered stream of instruction and directive items. An instruction keeps its source spelling, canonical alias identity, zero-, one-, or two-operand list, separating comma, optional semicolon, source span, and generated-source provenance. Operands remain classified as register, immediate, or memory forms. Size prefixes such as `U64`, segment prefixes such as `FS:`, and every token inside an address remain available to later assembler passes.

Direct directive items retain `IMPORT`; `DU8`, `DU16`, `DU32`, and `DU64`, including postfix `DUP`; `BINFILE`; `LIST`; `NOLIST`; and `USE16`, `USE32`, and `USE64`. Arguments and values may use optional commas where the source parser accepts them. `IMPORT`, the data directives, and `BINFILE` require a semicolon; the listing and mode directives may omit one. Parsing a `BINFILE` item records only its string token and never reads the named file. `ORG` and `ALIGN` remain illegal in function assembly, the type-sized spellings remain operand or declaration prefixes, and `DUP` cannot start an item.

Immediate syntax uses the ordinary HolyC expression parser without parenthesis-free function calls. Direct bracketed addresses stay lossless rather than being forced into the language-expression AST. A checked integer spelling that currently names a class or internal type falls back to the assembler keyword table, matching `PrsAsmArg`; this preserves the `U64` size in `Kernel/KInts.HC` after `KernelA.HH` publishes its intrinsic-backed union. Visible locals and unrelated newer compiler symbols still shadow size, opcode, and register spellings. Exact excerpts from `Adam/AMem.HC`, `Kernel/Job.HC`, `Demo/Graphics/Balloon.HC`, `Demo/Asm/AsmAndC3.HC`, `Demo/Lectures/Ring3.HC`, and `Kernel/KInts.HC` parse in JIT and AOT modes.

`HCPARSE0147` rejects supported direct assembly items at top level and points to `asm { ... }`. `HCPARSE0149` through `HCPARSE0152` cover a missing operand, missing comma, unclosed address bracket, and extra operand. `HCPARSE0153` through `HCPARSE0156` cover forbidden function-local directives and malformed import, data, and file items. Direct labels, directive evaluation and state changes, operand validation, instruction-form selection, lowering, encoding, and execution remain pending. Parsed syntax is not evidence that an item would assemble.

## Statement-position output literals

`PrsStmt` treats a string or character literal in statement position as a call shorthand. Strings select `Print`, and characters select `PutChars`. The current parser implements this syntax for top-level items and recursively inside compound blocks, conditional branches, and loop bodies. HolyC permits executable top-level statements without a conventional `main`.

The marker determines how the fixed argument begins:

- A nonempty marker starts the fixed expression. For example, `"value";` passes that string expression, while `'A'+1;` passes the complete addition expression.
- An empty string marker is consumed before the format expression, as in `"" fmt,name;`.
- An empty character marker is consumed before the character expression, as in `'' value;`.
- A `Print` statement may retain further comma-led expressions before its required semicolon.
- `PutChars` has one fixed argument. A following comma ends that statement and continues the enclosing statement sequence.

The AST records an explicit `Print` or `PutChars` target, the original marker, whether the fixed expression began at or after that marker, every additional `Print` argument and comma, an optional semicolon where the source permits a sequence comma, and all source origins. Top-level declarations, prototypes, and statements remain in one source-ordered item list in JIT and AOT modes. Blocks retain the same ordering among their children. Function and executable top-level semantic passes now retain typed values, resolve the source-visible target, and bind values to its checked header. Call lowering and execution are not implemented yet.

The semantic library binds ordinary names under executable top-level statements against the module publications visible before each statement. It walks nested expressions and statements in source order, retains definition-generated provenance, and resolves names absent from the module through a supplied JIT task-parent or AOT enclosing-compilation chain followed by the assembler table. Module publications keep precedence, and an unresolved name receives `HCSEMA0054` at its original source. The next pass builds one immutable semantic tree for each accepted executable statement. Roots identify expression statements, output arguments, conditions, switch selectors and case values, and return values. Calls retain their callee expression, exact identifier binding, syntax, provided expressions, and omitted slots. The leaf classifier then reuses the resolved global and function records. An ordinary global keeps its exact type and object, array, callback, or callback-array shape. A direct function keeps its visible declaration and mode-specific address policy. A class record remains an aggregate offset base, matching the `HTt_CLASS` route to `PrsOffsetOf`. A metadata-bearing outer global keeps its checked primitive, pointer, aggregate, array, or callback shape plus the exact source occurrence and outer binding. An outer record without that payload receives an explicit typed-metadata requirement and remains unavailable. Scalar roots, direct or pointer object members, aggregate offset paths, direct module calls, scalar module callbacks, fully indexed module callback arrays, aggregate-member callbacks, and scalar or fully indexed metadata-bearing outer callbacks then pass through the same result engine used for function expressions. An outer callback call uses a rank-zero `CHashGlblVar` callback directly or consumes every declared array dimension before binding arguments. It retains the exact occurrence and table binding; an indexed form also retains its completed callee result. A member callback call requires the exact `MLF_FUN`-backed lookup, preserves it through parentheses and every declared subscript, and uses its stored recursive signature. In every call path, explicit holes, trailing absences, declared defaults, and provided variadic expressions remain distinct. Each record keeps its source-visible callable facts, typed index, fixed, and variadic results, provided variadic count, source order, and expression-result identity. Returns follow the visible primitive, pointer, or aggregate type. A focused condition view then groups the typed roots for `if`, `while`, `do while`, and `for` with their containing statement and keyword origin. It retains zero branches for `if`, `while`, and `for`, and the nonzero back edge for `do while`, without converting the value to `Bool`. `HCSEMA0055` rejects mismatched trees, `HCSEMA0056` rejects stale leaf inputs, `HCSEMA0057` rejects inconsistent result, rank, member-call, or slot inputs, and `HCSEMA0063` rejects foreign or discontinuous condition batches. Ordinary outer objects, records without checked metadata, partial outer or module callback arrays, partial or unindexed callback-member arrays, and unrelated computed callees remain unavailable. Default evaluation and payload copying, runtime storage reads and address calculation, side effects, IR, `IET_MAIN`, and top-level execution remain unimplemented.

The public tree builder rejects an explicit top-level return before returning this structure. The lower-level AST and semantic constructors retain their return shape so malformed or manually assembled inputs can still be inspected, but that shape is not an accepted executable tree.

A second contextual view groups executable top-level switch selector roots. It keeps the containing statement, switch keyword, contiguous selector identity, exact typed result, and the bounded or no-bound choice carried by the AST. `HCSEMA0064` rejects a foreign table or discontinuous selector sequence. Selector and case evaluation, range-origin subtraction, labels, jump-table construction, switch IR, `IET_MAIN`, and execution remain later work. [Issue #352](https://github.com/frankischilling/holyc-ocaml/issues/352) records this boundary.

A third view joins executable top-level `case` metadata to its typed roots. It distinguishes an implicit case with no expression, a single explicit value, and a range whose ellipsis and two endpoints stay together. Every explicit value reuses its exact expression result; only an `F64` value records the conversion to integer required by `LexExpressionI64`. `HCSEMA0065` rejects foreign ownership, discontinuous identities, and missing or unexpected roots. The pass does not evaluate case values, assign implicit numbers, normalize reversed ranges, detect duplicates, create labels or a jump table, emit switch IR, produce `IET_MAIN`, or execute code. [Issue #354](https://github.com/frankischilling/holyc-ocaml/issues/354) records this boundary.

Before building those executable expression trees, a statement validator walks blocks, sequences, branches, loops, locks, switches and sub-switches, and both sides of `try`/`catch`. It rejects the first explicit top-level `return` with `HCSEMA0066` at the keyword while leaving every function definition untouched. This is distinct from `Compiler/CMain.HC:LexStmt2Bin`, which may turn the final ordinary top-level expression into `IC_RETURN_VAL2`; that implicit result has no source `return` and is not lowered yet. [Issue #356](https://github.com/frankischilling/holyc-ocaml/issues/356) records this boundary.

The top-level output target pass groups each fixed root with the trailing roots that share its output identity. It retains the marker separately from a following expression after `""` or `''`, including definition provenance. `Print` and `PutChars` lookup considers only function publications before the containing statement, so a later header stays invisible and a same-name object does not hide an older function. A missing module header falls through the exact outer chain already attached to the expression batch. Module targets keep the checked header, resolved declaration, and canonical identity; outer targets keep the selected entry without a guessed signature. `HCSEMA0058` rejects inconsistent semantic batches, and `HCSEMA0059` points a missing target at its literal marker. [Issue #346](https://github.com/frankischilling/holyc-ocaml/issues/346) records this boundary.

The following argument pass uses one shared fixed-slot rule for function-body and top-level output. Provided and defaulted slots remain distinct; provided values retain integer or `F64` conversion intent; string-bearing defaults use an AOT string-constant path instead of JIT's immediate path; and only roots beyond the fixed parameter count enter a variadic tail. A selected outer entry stays deferred until a checked header for the exact symbol is supplied. `HCSEMA0060` rejects inconsistent inputs, `HCSEMA0061` reports a missing required slot at the marker, and `HCSEMA0062` reports an excess nonvariadic value at that value. Format parsing, default evaluation, vararg promotion, lowering, and output remain separate work. [Issue #348](https://github.com/frankischilling/holyc-ocaml/issues/348) records this boundary.

Power and assignments carry `ASSOCF_RIGHT`. Shifts, division, modulo, and subtraction carry `ASSOCF_LEFT`. Other records have no association flag in the source, so the API reports `Unspecified`. The default-expression parser treats only `ASSOCF_RIGHT` as right-associative; both `Left` and `Unspecified` group to the left, matching the loop in `PrsExpression2` without inventing a C rule.

The prose precedence list in `Doc/HolyC.DD` omits `%=`. The executable table includes `TK_MOD_EQU` at `PREC_ASSIGN`, mapped to `IC_MOD_EQU`; that source record is authoritative.

Compound recognition is not a flat list in TempleOS. Three ordered arrays resolve shared prefixes, while `Lex` handles `<<=`, `>>=`, `..`, `...`, and `$$` separately. The current lexer consumes the generated spellings in longest-first order, but the generated audit data retains each original recognition group and source line.

| `OPTf_GLBLS_ON_DATA_HEAP` | 35 | Off | Allocation and linkage | Applied during global semantic resolution; AOT data-heap initializers are rejected |
| `OPTf_NO_BUILTIN_CONST` | 36 | Off | Code emission | Applied to functions, not statements |
| `OPTf_USE_IMM64` | 37 | Off | Optimization and code emission | Not completely implemented in the pinned source |

HolyC's `Option(bit, state)` changes the current compile controller and returns the bit's previous state. `GetOption(bit)` reads that controller. Nested compilation copies its parent's option mask, so source can temporarily change an option around a declaration or function and then restore the previous value. The pinned kernel, startup, and demo sources use this pattern for linkage, private symbols, global allocation, warning control, and optimization boundaries.

`Sema.Compiler_option` provides the checked registry, typed lookup, the initial mask, and a pure form of the previous-state update. Semantic resolution consumes `OPTf_EXTERNS_TO_IMPORTS` and `OPTf_GLBLS_ON_DATA_HEAP`; record classification consumes `OPTf_KEEP_PRIVATE`; local warning analysis consumes `OPTf_WARN_UNUSED_VAR`. The compiler does not yet execute `Option` in HolyC input or apply the remaining parser, optimizer, and backend effects.

## Current boundary

The implemented language specification supplies immutable primitive and intrinsic storage type facts, operator tables, compiler-option facts, and syntax for primitive, intrinsic, or published aggregate names in globals, bound prototypes, unbound function definitions, automatic and static locals, arrays, and postfix casts. It also covers `extern` class and union forwards; ordinary, type-backed, and single-base class and union bodies with grouped pointer, array, and recursive function-pointer members, member metadata, recursive anonymous unions, empty member semicolons, source-positioned aggregate-offset directives, and attached top-level globals; recursive compound blocks; `if` and `else`; all three loop forms; `goto`; function labels; `lock`; both switch modes and structural sub-switches; paired `try`/`catch`; `break`; `return`; brace-delimited assembly blocks; function-local direct instruction and directive syntax; and `Print` and `PutChars` shorthand statements. Declaration syntax includes ordered prefixes, ordinary, alternate-name, and `_intern` bindings, pointers through depth four, recursive function-pointer parameters, globals, aggregate members, and locals, scalar and recursive braced global and static-local initializers, scalar automatic-local initializers, parameter and automatic-local register qualifiers, varargs, parenthesized and direct parenthesis-free calls, and core expressions in `_intern` targets, dimensions, defaults, initializers, aggregate offsets, member metadata, conditions, switch labels, and output arguments. It enforces the source parser's AOT gate for both import spellings and accepts `_intern` plus every implemented statement form in JIT and AOT modes.

The semantic library assigns stable module, aggregate, and function scopes and symbols; reconciles source-ordered aggregate identities; resolves definition headers, direct member heads, recursive member callbacks, global types, and top-level function signatures; retains the checked `MLF_FUN` fact on callback members; calculates closed class and union byte layouts; validates direct and inherited member names; reconciles function identities and global records; applies `OPTf_EXTERNS_TO_IMPORTS` and `OPTf_GLBLS_ON_DATA_HEAP` from retained declaration snapshots; classifies source-backed flags and consumer intent; and binds function-local language gotos to language or structural assembly-block labels. AOT data-heap definitions reject initializers during this semantic boundary, while JIT keeps their initializer shape. `holyc dump-layout` exposes the completed aggregate facts as deterministic human or JSON data. These APIs validate their complete AST and semantic batches before returning and keep the symbol table unchanged during each resolution or classification pass. They are library boundaries rather than a claim that the whole parsed program has been checked.

Inside a checked function, ordinary and implicit-output statements, switch selectors, and case values use the immutable expression-result model. Ordinary and output statements carry `ICF_RES_NOT_USED` intent; output also retains its synthetic target and argument shape. `PrsFunCall` resolves that target with `HashFind` and the `HTT_FUN` mask. The semantic target pass reproduces the relevant lookup order: the newest visible module function header wins, same-name nonfunction records are skipped, and lookup then continues through the supplied outer chain. A module result keeps its checked header and joined identity. An outer result keeps the selected hash entry without inventing type information. The argument pass binds only a checked header, fills fixed slots from supplied values or declared defaults, records `ICF_RES_TO_F64` and `ICF_RES_TO_INT` intent where the source does, and keeps later values as a variadic tail only when that header permits one. A selector retains bounded or no-bound mode. A case retains one implicit, single, or ranged pattern, and ranged endpoints stay paired. Explicit integer-like values need no semantic conversion; an explicit `F64` value records the integer conversion performed when TempleOS evaluates it through `LexExpressionI64`. Runtime statement disposal and output, format handling, default evaluation, vararg promotion, call lowering, case evaluation, implicit-value assignment, reversed-range normalization, duplicate checks, and jump-table construction remain later stages.

Executable top-level output uses the same kind-filtered target and fixed-slot rules but separate adapters because no function scope exists. Target resolution derives source-order visibility and the outer chain from the typed top-level batch. Argument binding consumes that exact result and accepts only the conversion policy and optional checked outer headers that it cannot derive. The result is not yet an ABI call or an execution result.

The compiler still does not resolve types in casts outside the documented direct-call source view, or resolve `sizeof` or `offset`; bind or evaluate defaults nested in callback members; create semantic block scopes; compare function headers; allocate runtime storage; evaluate `_intern` addresses, default payloads, initializers, symbol-dependent aggregate offsets, or metadata; resolve alternate binding addresses; create fixups or loader records; complete task-level linkage; honor register requests; materialize ordinary call defaults; format, promote, lower, or execute implicit output calls; validate break targets or the remaining function-return rules; calculate runtime member addresses or use counts; resolve assembly operand references or repeated assembly definitions by output address; validate assembly operands or directives; evaluate or apply assembler state and output effects; evaluate switch cases or build jump tables; construct executable control flow; implement exception transfer; execute top-level code; or support whole-value backing semantics, subinteger access, metadata lookup, direct local callback initialization, automatic local braced initializers, remaining control flow, general promotions and value conversions, floating execution, compile-time compiler-option changes, or structured semantic diagnostics. Those claims remain absent from the compatibility report until their own source-grounded tests pass.
