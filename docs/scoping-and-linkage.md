# Scoping and linkage

This document records the behavior established from TempleOS commit `c26482bb6ad3f80106d28504ec5db3c6a360732c`. The main references are `Compiler/PrsStmt.HC`, `Compiler/PrsLib.HC`, `Compiler/Asm.HC`, `Compiler/AsmResolve.HC`, `Compiler/CompilerA.HH`, `Doc/ScopingLinkage.DD`, and `Doc/Options.DD`.

## Source behavior

JIT compilation searches the current task's symbol table and then its parent tasks. New declarations enter the current task's table and may shadow older names where the source permits duplicates. A plain `extern` function or global variable binds to the same name when it already exists and can also create a forward declaration.

A plain `import` names a symbol that the TempleOS loader resolves when an AOT module is loaded. If the symbol is unavailable then, uses remain incomplete until a later definition can resolve them. `PrsGlblVarLst` rejects `PRS0_IMPORT` when `CCF_AOT_COMPILE` is clear.

`_extern` and `_import` bind a HolyC declaration to a separately named system or imported symbol. `_intern` binds through a compile-time address expression. Those forms have more syntax and state than plain `extern` and `import`.

`OPTf_EXTERNS_TO_IMPORTS` changes ordinary and underscored extern declarations into their import forms. The pinned compiler uses this while compiling shared headers in different JIT and AOT contexts.

## Semantic scope foundation

`Kernel/KHashA.HC:_HASH_ADD` inserts a new entry at the front of its bucket. `SYS_HASH_SINGLE_TABLE_FIND` walks that chain from the front and decrements an instance counter only for entries whose spelling and requested type mask match. `SYS_HASH_FIND` carries the remaining counter through each table's `next` link. The result is newest-first lookup in one table, followed by the next table, without deleting older declarations.

`Sema.Symbol_table` preserves that boundary with stable table-local IDs. It can represent task, module, function, block, aggregate, and assembler-block contexts, and every child names one explicit parent. Lookup takes a set of semantic kinds and an optional positive instance number; later instances can continue into the parent. Scope and symbol handles are tied to their owning table, so a handle from another session is rejected before an ID or entry is consumed. Human and JSON renderers walk scopes and symbols in ID order and retain pinned, ordinary source, generated-source, or synthesized provenance. The JSON schema is `holyc-semantic-symbol-table-v1`.

Each `Session.t` owns one table and seeds its task root with the 17 internal type spellings constructed by `Compiler/CInit.HC`. This does not reproduce a live TempleOS task tree. [Issue #164](https://github.com/frankischilling/holyc-ocaml/issues/164) records the identity and lookup boundary.

`Compiler/PrsStmt.HC:PrsClass` installs a class or union name before its optional attached global list. `PrsGlblVarLst` then installs each global declarator in source order, while `PrsFunJoin` supplies function entries and source metadata. `Sema.Declaration_collection` and `Driver.Semantic_collection` preserve that order for an accepted AST: one module scope receives aggregate forwards and definitions, aggregate-attached globals, ordinary globals, function prototypes, and function definitions. The result retains each module-item index, grouped-declarator index, and complete identifier provenance. A repeated name remains a separate entry, so newest and nth lookup continue to work.

Collection deliberately keeps every declaration entry. `Sema.Aggregate_resolution` then applies the module-local `PrsClass` rule: each aggregate forward starts an identity, and a definition completes only the newest same-name identity when that identity is still unresolved. A completed identity retains both sites and uses the definition symbol as canonical; older forwards and shadowed definitions remain separate. The shared `HTT_CLASS` category means a class/union spelling change is retained but not rejected. The pass validates its declaration collection against the same AST and session and does not mutate the symbol table. [Issue #175](https://github.com/frankischilling/holyc-ocaml/issues/175) records this boundary.

`PrsType` reads an optional aggregate backing before `PrsClass` publishes the new identity. `PrsClass` then publishes that identity before it reads an optional base. `Driver.Aggregate_header_resolution` preserves both lookup points instead of querying the completed module table: a named backing sees the prior source state, while a base sees the newly published canonical symbol. `Sema.Type` keeps public primitive spellings, intrinsic storage spellings, aggregate identities, and pointer depths zero through four distinct. The header result retains definition, keyword, backing, pointer, colon, and base-name provenance. If a later definition completes a selected forward, the canonical symbol from aggregate reconciliation updates the identity without rewriting the header. [Issue #177](https://github.com/frankischilling/holyc-ocaml/issues/177) records this boundary.

These aggregate-specific results do not reconcile functions or globals, check general duplicate legality, follow backing chains, reject inheritance cycles, apply a linkage spelling, publish a module into a persistent JIT task, or resolve type uses outside aggregate member heads and top-level function signatures. Top-level executable statements intentionally add no declaration entry. Separate passes add aggregate members and function bindings below the module scope. [Issue #166](https://github.com/frankischilling/holyc-ocaml/issues/166) records the collection boundary.

`Compiler/PrsVar.HC:PrsVarLst` calls `MemberAdd` for each completed member declarator. Comma groups enter left to right. Its anonymous-union branch recurses with the same `CHashClass`, so nested fields belong to the containing aggregate namespace. `Sema.Member_collection` creates one aggregate scope for each definition already collected at top level, adds every named direct member in that order, and retains both the grouped-declarator index and the recursive member path. A metadata name, offset directive, or empty separator adds no symbol. Repeated names remain separate collection entries so the later duplicate pass can apply `MemberAdd`'s exceptions for `pad`, `reserved`, and `_anon_` with full type and inheritance context.

The aggregate scope's lexical parent is its module. It is not connected to the base identity recorded in the aggregate header: `MemberFind` performs that separate search only after checking the current class. A later pass now binds each direct member's base and pointer layers at its source position, but layout, inherited lookup, duplicate diagnostics, metadata evaluation, complete member-callback types, and member-access resolution remain pending. [Issue #168](https://github.com/frankischilling/holyc-ocaml/issues/168) records the direct-member identity boundary, and [issue #179](https://github.com/frankischilling/holyc-ocaml/issues/179) records the member type-reference boundary.

`Compiler/PrsStmt.HC:PrsFunJoin` builds a function's fixed member list through `PrsVarLst`. Unnamed fixed parameters occupy signature positions without adding a member. `Compiler/PrsVar.HC:PrsDotDotDot` then appends `argc` followed by `argv` for a variadic function. When `PrsFun` accepts a definition, it points both `cc->htc.local_var_lst` and `cc->htc.fun` at that same `CHashFun`; the automatic and static local branches in `PrsStmt` keep passing the function to `PrsVarLst`. Braces and other nested statements therefore do not create C-style local namespaces.

`Sema.Function_collection` creates one child scope for each prototype and definition already collected at top level. Named parameters retain their fixed-signature indexes, so an unnamed parameter leaves a visible gap rather than renumbering later entries. Variadic `argc` and `argv` use the ellipsis location as their shared provenance. `Driver.Function_collection` walks blocks, branches, loops, sequences, locks, switches and sub-switches, and both sides of `try`/`catch` in parser order. Every accepted automatic or static local enters the same function scope, with its declaration and grouped-declarator indexes retained. Repeated names remain separate entries and newest-first lookup sees the latest one. Local types, default and initializer evaluation, register requests, storage offsets, duplicate rules, ordinary expression references, prototype reconciliation, and linkage remain pending. [Issue #170](https://github.com/frankischilling/holyc-ocaml/issues/170) records this collection boundary.

`Compiler/PrsStmt.HC:PrsGlblVarLst` supplies the return type to `PrsFunJoin`, which uses `PrsVarLst` for the fixed signature. `PrsType` recursively constructs callback signatures: outer stars belong to the return type, and one through four stars inside the callback declarator represent its indirection. `MemberLstCmp` compares fixed slots and their available defaults, while `PrsFunCall` may select those defaults in non-trailing positions. The semantic pass retains ordinary-expression versus `lastclass` defaults and their origins, but it does not evaluate either form.

`Driver.Function_type_resolution` replays canonical aggregate publication in module order and resolves each prototype or definition against the identities visible at that declaration. It binds public, intrinsic, or aggregate return and fixed-parameter types; recursively resolves callbacks; preserves unnamed fixed slots; and associates named top-level slots with the parameter symbols already in the function scope. Top-level varargs retain `argc` and `argv` as intrinsic `I64`; `argc` is scalar, while `argv` has no source extent and keeps the compiler's array placeholder 127. `Sema.Function_type_resolution` validates the AST, declarations, aggregate identities, scopes, symbols, slot order, recursive type targets, and synthetic bindings as one immutable batch. It does not reconcile a prototype with a definition, evaluate or substitute defaults, check calls, resolve member callback or local types, assign flags or registers, calculate storage, apply ABI rules, or decide linkage. [Issue #181](https://github.com/frankischilling/holyc-ocaml/issues/181) records this boundary.

The `goto` branch in `Compiler/PrsStmt.HC` finds or creates a `CMT_GOTO_LABEL`, increments its use count, and emits a jump. The identifier-label branch uses the same record, marks it defined, and rejects a second language definition. `Compiler/PrsLib.HC:COCGoToLabelFind` searches both `CMT_GOTO_LABEL` and `CMT_ASM_LABEL`, so a function-local assembly definition can satisfy a language `goto`. `Compiler/Asm.HC` adds those assembly definitions to the function's code-control list and contributes one use to suppress the ordinary unused-label warning. `Compiler/PrsLib.HC:COCDel` later rejects an undefined record and warns about an unused language definition.

`Driver.Label_resolution` walks every recursive statement route in parser order and collects language gotos, language definitions, and the three structural labels retained by brace-delimited assembly blocks. `Sema.Label_resolution` validates the complete batch before mutation, creates one `Symbol.Label` identity per defined spelling in each function, and maps every occurrence to that identity. Label order follows the first occurrence, while symbol provenance comes from the definition rather than an earlier forward `goto`. Prototypes receive an empty result, and separate function scopes can reuse the same spelling. Top-level language occurrences, missing targets, duplicate language definitions, mixed language/assembly definitions, mismatched AST collections, and foreign session handles fail without adding a label. [Issue #172](https://github.com/frankischilling/holyc-ocaml/issues/172) records this boundary.

`Compiler/Asm.HC:1032-1062` has a narrower rule for repeated assembly definitions: a repeat is valid only when the existing value equals the current output address. The semantic pass retains every such occurrence and its definition count because layout has not assigned addresses yet. [Issue #174](https://github.com/frankischilling/holyc-ocaml/issues/174) tracks that assembler check. Assembly operand references marked through `Compiler/AsmResolve.HC`, direct-assembly labels, unused warnings, collision checks against reconciled global objects, jump construction, and IR lowering also remain pending.

## Implemented parser boundary

The AST keeps `public`, `static`, `interrupt`, `haserrcode`, `argpop`, and `noargpop` as ordered staged modifiers. It keeps one ordinary, alternate-name, or `_intern` binding separate from the declared type. An `_extern` or `_import` node retains the target identifier that appears before the type. An `_intern` node retains the unevaluated target expression instead. Function parameters retain ordered `reg` and `noreg` qualifiers, their position around the type, and an optional canonical U64 register name. Automatic local declarators separately retain after-type `reg` and `noreg` requests plus an optional U64 register. Static locals retain their storage spelling and reject that automatic-only qualifier position. Those separations follow `PrsStmt` and `PrsVarLst`. Calling modifiers and register requests remain syntax here; no linkage, allocation, or ABI rule is applied during parsing.

An `extern class Name;` or `extern union Name;` item retains the ordinary binding, aggregate spelling, name, semicolon, modifiers, and source provenance. `PrsClass` publishes the source entry before its next `Lex` call, so the OCaml parser publishes the name as `Symbol_visibility.Class` before preprocessing asks for another token. A following `#ifdef Name` can therefore observe it in JIT or AOT mode. Class and union remain distinct AST kinds even though both enter the common class-symbol category. A visible class symbol can start a later declaration type, aggregate member, or postfix cast. An ordinary definition publishes its name before reading members, which permits self-referential pointers and lets a prior forward name continue into the definition path. The parser records syntax and streaming visibility; aggregate reconciliation models the resulting `Cf_EXTERN` completion identity, and the member type pass binds accepted member uses to that canonical identity. General duplicate checks, type resolution outside aggregate member heads and top-level function signatures, layout, and linkage remain separate work.

The default parser mode is JIT. It accepts `extern`, `_extern`, and `_intern`; rejects `import` and `_import` with `HCPARSE0006`; and does not publish a rejected name. An explicit AOT parser configuration accepts all five bindings. Each accepted binding and target retains its spelling, source segments, generated frame, invocation site, and definition site. The type-safe target representation distinguishes no target, a symbol target, and an expression target. Singleton and comma-separated globals share that binding representation whether their base is primitive or a published class name and whether the stored value is ordinary or a function pointer. Bound function prototypes retain it alongside their return type, parameters, and punctuation. A missing alternate target receives `HCPARSE0007`.

This is syntax handling plus the source-backed AOT gate. An accepted prototype is published to the streaming environment with function identity and a compact call shape. The shape records fixed parameters in declaration order, optional names, default availability, and whether the signature is variadic. It is sufficient to recognize a direct parenthesis-free call, but it is not a semantic function type. A function-pointer global instead enters the environment with global-variable identity, matching the `CHashGlblVar` path in `PrsGlblVarLst`; its retained signature does not enable direct-call syntax. The parser does not look up an ordinary or alternate target, evaluate an `_intern` expression, compare headers, resolve a forward reference or alias, create an import or export record, assign storage or an executable address, construct a semantic function-pointer type, set `Ff_INTERNAL`, clear `Cf_EXTERN`, apply `OPTf_EXTERNS_TO_IMPORTS`, or model task-parent lookup. Those behaviors belong to semantic linkage, AOT emission, and the loader model.

Parameter defaults retain their source expressions, including defaults before required parameters. Parenthesized call nodes retain each provided or omitted slot, so later checking can match holes to defaults without confusing them with explicit zero. A direct function name without parentheses walks the retained call shape. Each defaulted fixed position adds an omitted slot, each required position parses one adjacent expression, and variadic extras remain absent. Definitions publish their shape before body parsing, so recursion works. `&Function`, a local name, or a newer nonfunction entry suppresses this call form. Index and member nodes retain source shape without assigning an element type, address, offset, or lvalue class. Semantic default evaluation, call resolution, argument checking, index scaling, member lookup, layout, and string-default storage are not implemented. Primitive and named global, local, or aggregate member arrays retain their ordered dimensions. Aggregate member type results retain dimension origins, but no pass evaluates sizes, calculates storage, or applies linkage. `_intern` likewise retains syntax without applying its source-defined address and flag effects.

Unbound function definitions retain their complete header and one ordinary statement body. The function enters the streaming environment before that body is requested. Named parameters, synthetic variadic `argc` and `argv`, and accepted local names then enter a function-wide parser context. Each local is published before its initializer or following token is parsed, matching the `MemberAdd` order in `PrsVarLst`. A local name shadows a class or direct function for later syntax routing. A callback local remains a variable entry: its retained signature does not enable parenthesis-free direct-call syntax. An ordinary static local can retain a scalar or recursively braced initializer; an automatic ordinary local retains one scalar expression. This parser context determines syntax while the semantic function-collection pass gives the named parameters and locals stable identities in a separate function scope. Neither layer assigns block lifetimes, storage offsets, ABI effects, or executable addresses. Aggregate definition nodes retain an optional public, intrinsic, or named backing type, its pointer layers, an optional single base, ordinary grouped members, member return pointers, recursive callback declarators, arrays, recursive anonymous unions, explicit source-positioned offset directives, and either a standalone semicolon or attached globals. The aggregate is published before the base token is requested, matching `PrsClass`; the base must resolve through the shared visible class category. Each attached global is published before the parser requests the next token, matching `PrsGlblVarLst`. An attached function-pointer global keeps its recursive signature, while a callback member keeps the same signature shape without entering the top-level symbol environment. Every attached global keeps its optional scalar or recursively braced initializer. The semantic collection passes give each named direct member, fixed parameter, synthetic variadic binding, and local declarator an identity. Member type resolution additionally binds each direct member's public, intrinsic, or aggregate base plus ordinary pointers and retains callback-head and array shape; it does not resolve recursive parameters inside a member callback, set `MLF_FUN`, calculate offsets, evaluate initializers, or assign storage. Function type resolution separately binds top-level function returns and recursive fixed-parameter signatures, but nested callback slots do not receive independent symbols. Callback signatures on globals, members, and locals remain unresolved. Register allocation, direct local callback initialization, automatic local braced initializers, inherited layout and member lookup, metadata, aggregate-offset expression evaluation, negative-offset and union-base state, type resolution outside aggregate member heads and top-level function signatures, backing compatibility, whole-value access, subinteger access, layout, cycle checks, and duplicate-declaration rules remain unavailable.

Member names have a narrow contextual rule. TempleOS lexes keyword spellings as `TK_IDENT` and asks `PrsKeyWord` for a keyword interpretation only where the grammar expects one. The OCaml lexer retains distinct keyword tokens, but ordinary and recursive function-pointer aggregate declarators accept them as names after their type and pointer prefix. This does not publish a top-level symbol, and it does not relax global, local, parameter, function, aggregate, or label names. Twelve pinned `U0 start;` members and all 48 checked keyword spellings exercise this boundary under issue #147.

Member metadata follows the same contextual identifier boundary but has no independent symbol-table entry. Each declarator keeps its source-ordered names and either an extended string or ordinary expression value. Duplicate metadata names remain present. Direct-member collection creates one symbol for the declarator name and deliberately ignores those metadata names. A later metadata pass must reproduce TempleOS's prepended list and last-written lookup precedence rather than silently deduplicating them. The parser does not yet evaluate expression values, allocate `CMemberLstMeta`, set `MLMF_IS_STR`, or implement `MemberMetaData` and `MemberMetaFind`. Issue #149 records this syntax and the remaining semantic boundary.

## Parser visibility inspection

`holyc dump-symbols FILE` runs the ordinary preprocessor and parser, then prints the session environment in stable ID order. The default view includes the 570 entries seeded from the pinned language, type, register, directive, and opcode tables. `--source-only` keeps entries published from the input stream. `--format=json` selects the structured form; both renderers identify schema `holyc-symbol-visibility-v2` and reference commit `c26482bb6ad3f80106d28504ec5db3c6a360732c`.

Source-published classes, globals, and direct functions keep their primary span, contributing source segments, definition invocation, and definition site. Direct functions also keep the fixed parameter order, optional names, default availability, and variadic marker used by parenthesis-free parsing. Active local contexts use their stable context IDs and lexically sorted name lists. The command writes diagnostics to stderr and returns status 1 after an error, but still writes the state accumulated before the failure to stdout.

This is the parser's source-order routing state. It explains why a token was treated as a type, direct call, ordinary name, or shadowed spelling. It does not reconcile declarations, populate the semantic table, assign storage, resolve imports or aliases, construct a runtime task-parent chain, decide linkage, or produce a loader symbol table. [Issue #161](https://github.com/frankischilling/holyc-ocaml/issues/161) tracks that semantic work; [issue #162](https://github.com/frankischilling/holyc-ocaml/issues/162) records this inspection boundary.
