# Scoping and linkage

This document records the behavior established from TempleOS commit `c26482bb6ad3f80106d28504ec5db3c6a360732c`. The main references are `Compiler/PrsStmt.HC`, `Compiler/PrsLib.HC`, `Compiler/Asm.HC`, `Compiler/AsmInit.HC`, `Compiler/AsmResolve.HC`, `Compiler/CMain.HC`, `Compiler/CompilerA.HH`, `Kernel/KernelA.HH`, `Kernel/KHashA.HC`, `Kernel/KTask.HC`, `Doc/ScopingLinkage.DD`, and `Doc/Options.DD`.

## Source behavior

JIT compilation searches the current task's symbol table and then its parent tasks. New declarations enter the current task's table and may shadow older names where the source permits duplicates. A plain `extern` function can supply a header that a later declaration replaces. A plain `extern` global creates its own record; a later definition may redirect that record to the new storage.

A plain `import` names a symbol that the TempleOS loader resolves when an AOT module is loaded. If the symbol is unavailable then, uses remain incomplete until a later definition can resolve them. `PrsGlblVarLst` rejects `PRS0_IMPORT` when `CCF_AOT_COMPILE` is clear.

`_extern` and `_import` bind a HolyC declaration to a separately named system or imported symbol. `_intern` binds through a compile-time address expression. Those forms have more syntax and state than plain `extern` and `import`.

`OPTf_EXTERNS_TO_IMPORTS` changes ordinary and underscored extern declarations into their import forms. The pinned compiler uses this while compiling shared headers in different JIT and AOT contexts.

`OPTf_GLBLS_ON_DATA_HEAP` is sampled only after the binding-specific global arms. Ordinary definitions and `_intern` use data-heap policy while the bit is set; `extern`, `_extern`, `import`, and `_import` do not. AOT data-heap globals cannot have an initializer, do not receive the code-heap export bit on this path, and reject any preceding same-name global as an unimplemented source case. JIT data-heap globals may still be initialized.

## Semantic scope foundation

`Kernel/KHashA.HC:_HASH_ADD` inserts a new entry at the front of its bucket. `SYS_HASH_SINGLE_TABLE_FIND` walks that chain from the front and decrements an instance counter only for entries whose spelling and requested type mask match. `SYS_HASH_FIND` carries the remaining counter through each table's `next` link. The result is newest-first lookup in one table, followed by the next table, without deleting older declarations.

`Sema.Symbol_table` preserves that boundary with stable table-local IDs. It can represent task, module, function, block, aggregate, and assembler-block contexts, and every child names one explicit parent. Lookup takes a set of semantic kinds and an optional positive instance number; later instances can continue into the parent. Scope and symbol handles are tied to their owning table, so a handle from another session is rejected before an ID or entry is consumed. Human and JSON renderers walk scopes and symbols in ID order and retain pinned, ordinary source, generated-source, or synthesized provenance. The JSON schema is `holyc-semantic-symbol-table-v1`.

Each `Session.t` owns one table and seeds its task root with the 17 internal type spellings constructed by `Compiler/CInit.HC`. This does not reproduce a live TempleOS task tree. [Issue #164](https://github.com/frankischilling/holyc-ocaml/issues/164) records the identity and lookup boundary.

`Compiler/PrsStmt.HC:PrsClass` installs a class or union name before its optional attached global list. `PrsGlblVarLst` then installs each global declarator in source order, while `PrsFunJoin` supplies function entries and source metadata. `Sema.Declaration_collection` and `Driver.Semantic_collection` preserve that order for an accepted AST: one module scope receives aggregate forwards and definitions, aggregate-attached globals, ordinary globals, function prototypes, and function definitions. The result retains each module-item index, grouped-declarator index, and complete identifier provenance. A repeated name remains a separate entry, so newest and nth lookup continue to work.

Collection deliberately keeps every declaration entry. `Sema.Aggregate_resolution` then applies the module-local `PrsClass` rule: each aggregate forward starts an identity, and a definition completes only the newest same-name identity when that identity is still unresolved. A completed identity retains both sites and uses the definition symbol as canonical; older forwards and shadowed definitions remain separate. The shared `HTT_CLASS` category means a class/union spelling change is retained but not rejected. The pass validates its declaration collection against the same AST and session and does not mutate the symbol table. [Issue #175](https://github.com/frankischilling/holyc-ocaml/issues/175) records this boundary.

`PrsType` reads an optional aggregate backing before `PrsClass` publishes the new identity. `PrsClass` then publishes that identity before it reads an optional base. `Driver.Aggregate_header_resolution` preserves both lookup points instead of querying the completed module table: a named backing sees the prior source state, while a base sees the newly published canonical symbol. `Sema.Type` keeps public primitive spellings, intrinsic storage spellings, aggregate identities, and pointer depths zero through four distinct. The header result retains definition, keyword, backing, pointer, colon, and base-name provenance. If a later definition completes a selected forward, the canonical symbol from aggregate reconciliation updates the identity without rewriting the header. [Issue #177](https://github.com/frankischilling/holyc-ocaml/issues/177) records this boundary.

These aggregate-specific results do not reconcile functions or globals, check general duplicate legality, follow backing chains, reject inheritance cycles, apply a linkage spelling, or publish a module into a persistent JIT task. Top-level executable statements intentionally add no declaration entry. Separate passes add aggregate members and function bindings below the module scope, then resolve type references for aggregate member heads, globals, and top-level function signatures. [Issue #166](https://github.com/frankischilling/holyc-ocaml/issues/166) records the collection boundary.

`Compiler/PrsVar.HC:PrsVarLst` calls `MemberAdd` for each completed member declarator. Comma groups enter left to right. Its anonymous-union branch recurses with the same `CHashClass`, so nested fields belong to the containing aggregate namespace. `Sema.Member_collection` creates one aggregate scope for each definition already collected at top level, adds every named direct member in that order, and retains both the grouped-declarator index and the recursive member path. A metadata name, offset directive, or empty separator adds no symbol. Repeated names remain separate collection entries so the later duplicate pass can apply `MemberAdd`'s exceptions for `pad`, `reserved`, and `_anon_` with full type and inheritance context.

The aggregate scope's lexical parent is its module. It is not connected to the base identity recorded in the aggregate header: `MemberFind` performs that separate search only after checking the current class. Later passes bind each direct member's base and complete callback type at its source position, calculate closed layout, and build the direct-before-base member index. Metadata evaluation, general cycle diagnostics, and member-access expression resolution remain pending. [Issue #168](https://github.com/frankischilling/holyc-ocaml/issues/168) records the direct-member identity boundary, and [issue #179](https://github.com/frankischilling/holyc-ocaml/issues/179) records the member type-reference boundary.

`Compiler/PrsStmt.HC:PrsFunJoin` builds a function's fixed member list through `PrsVarLst`. Unnamed fixed parameters occupy signature positions without adding a member. `Compiler/PrsVar.HC:PrsDotDotDot` then appends `argc` followed by `argv` for a variadic function. When `PrsFun` accepts a definition, it points both `cc->htc.local_var_lst` and `cc->htc.fun` at that same `CHashFun`; the automatic and static local branches in `PrsStmt` keep passing the function to `PrsVarLst`. Braces and other nested statements therefore do not create C-style local namespaces.

`Sema.Function_collection` creates one child scope for each prototype and definition already collected at top level. Named parameters retain their fixed-signature indexes, so an unnamed parameter leaves a visible gap rather than renumbering later entries. Variadic `argc` and `argv` use the ellipsis location as their shared provenance. `Driver.Function_collection` walks blocks, branches, loops, sequences, locks, switches and sub-switches, and both sides of `try`/`catch` in parser order. Every accepted automatic or static local enters the same function scope, with its declaration and grouped-declarator indexes retained. Collection preserves repeated entries, and the generic symbol-table lookup remains newest first. Type resolution, completed-namespace validation, and function-local expression binding are separate checked passes; default and initializer evaluation, storage offsets, prototype reconciliation, and linkage remain pending. [Issue #170](https://github.com/frankischilling/holyc-ocaml/issues/170) records this collection boundary.

`Compiler/PrsStmt.HC:PrsGlblVarLst` supplies the return type to `PrsFunJoin`, which uses `PrsVarLst` for the fixed signature. `PrsType` recursively constructs callback signatures: outer stars belong to the return type, and one through four stars inside the callback declarator represent its indirection. `MemberLstCmp` compares selected fixed-slot records and their evaluated defaults, while `PrsFunCall` may select those defaults in non-trailing positions. The type pass retains ordinary-expression versus `lastclass` defaults and their origins without evaluating either form. Header analysis accepts the later evaluated payload as a separate checked input.

`Driver.Function_type_resolution` replays canonical aggregate publication in module order and resolves each prototype or definition against the identities visible at that declaration. It binds public, intrinsic, or aggregate return and fixed-parameter types; recursively resolves callbacks; preserves unnamed fixed slots; and associates named top-level slots with the parameter symbols already in the function scope. Each fixed slot receives a derived member-list mask: unnamed slots carry `MLF_NO_UNUSED_WARN`, callbacks carry `MLF_FUN`, and defaults carry `MLF_DFT_AVAILABLE` plus the applicable `MLF_LASTCLASS` or `MLF_STR_DFT_AVAILABLE` bit. Nested callback slots derive their own masks. Top-level varargs retain `argc` and `argv` as intrinsic `I64`; `argc` is scalar, `argv` has no source extent and keeps the compiler's array placeholder 127, and both carry exactly `MLF_DOT_DOT_DOT`. `Sema.Function_type_resolution` validates the AST, declarations, aggregate identities, scopes, symbols, slot order, recursive type targets, and synthetic bindings as one immutable batch. It does not reconcile a prototype with a definition, evaluate or substitute defaults, check calls, assign registers, calculate storage, apply ABI rules, or decide linkage. [Issue #181](https://github.com/frankischilling/holyc-ocaml/issues/181) records the type boundary, and [issue #220](https://github.com/frankischilling/holyc-ocaml/issues/220) records the parameter masks. Aggregate callback members reuse this recursive signature value through the member type pass. [Issue #216](https://github.com/frankischilling/holyc-ocaml/issues/216) records that separate publication and validation boundary, while [issue #218](https://github.com/frankischilling/holyc-ocaml/issues/218) records the derived `MLF_FUN` member fact.

`PrsGlblVarLst` calls `PrsType` for each ordinary or aggregate-attached declarator. Return pointers stay on the selected type, callback stars stay inside the function-pointer declarator, and `PrsArrayDims` records the ordered suffix before the compiler stores the result on `CHashGlblVar`. `Driver.Global_type_resolution` follows the same publication order. A named global sees the canonical aggregate identity available before its declaration; globals attached to a definition see that definition first. `Sema.Global_type_resolution` keeps the collected global symbol, item and declarator positions, resolved type, recursive callback signature, every array bracket and optional expression, initializer shape, delimiter, and source provenance. An empty first dimension remains distinct from an explicit zero expression. The pass does not evaluate extents or initializers, reconcile repeated globals, apply a binding or compiler option, assign storage, or emit relocations. [Issue #185](https://github.com/frankischilling/holyc-ocaml/issues/185) records this boundary.

The automatic and static branches in `PrsStmt` pass the current `CHashFun` to `PrsVarLst`. That routine handles `reg` and `noreg` per declarator, calls `PrsType`, adds the local before parsing its initializer, and ends the local declaration after its semicolon. Static locals retain `MLF_STATIC` and may use recursive initializers; callback locals retain `MLF_FUN`; automatic ordinary locals accept one expression initializer. `Driver.Local_type_resolution` replays aggregate publication up to the function declaration, matches every recursive local AST node to its collected function-scope symbol, and resolves public, intrinsic, aggregate, and recursive callback types. `Sema.Local_type_resolution` retains storage and its source tokens, register requests and explicit register names, array brackets, initializer shape, grouped delimiters, and complete provenance. It also derives the private declaration-time mask independently for each declarator: zero for an automatic object, `MLF_FUN` for an automatic callback, `MLF_STATIC` for a static object, and both bits for a static callback. It validates the batch without evaluating extents or initializers, assigning stack or static storage, allocating registers, lowering addresses, or applying ABI rules. Function-local expression binding consumes this batch through the completed namespace index described below. [Issue #200](https://github.com/frankischilling/holyc-ocaml/issues/200) records the type boundary, and [issue #222](https://github.com/frankischilling/holyc-ocaml/issues/222) records the local mask boundary.

`Compiler/LexLib.HC:MemberAdd` checks `MemberFind` before it inserts a parameter or local. An ordinary repeated spelling is therefore an error anywhere in the shared function namespace, including across a parameter and a nested local or across automatic and static declarations. The exact spellings `pad`, `reserved`, and `_anon_` bypass that check. Their equal keys enter the member tree below the existing node, so a completed lookup selects the earliest source occurrence. `Driver.Function_binding_index` reconciles every collected binding with the function and local type batches. `Sema.Function_binding_index` validates ownership, function order, parameter-before-local order, binding kinds, and stable symbols before it returns an immutable index. `HCSEMA0014` reports an invalid batch, `HCSEMA0015` reports an ordinary duplicate, and `HCSEMA0016` reports a query for an unindexed function. Lookup does not change `use_cnt`. Top-level duplicate-declaration rules remain unimplemented. [Issue #202](https://github.com/frankischilling/holyc-ocaml/issues/202) records this boundary.

`Compiler/Lex.HC:493-499` calls `MemberFind` before it asks the global hash chain about an identifier. `Compiler/PrsExp.HC:761-807` therefore lowers a visible parameter or local before its global-expression cases. `PrsVarLst` inserts a local only after `PrsType` and `PrsArrayDims` have consumed the declarator, but before it parses either the automatic or static initializer. `Driver.Function_expression_binding` reproduces that order over the AST. Named parameters, `argc`, and `argv` start visible. Each array dimension is visited before its declarator is published, then the initializer is visited with the new local available. The local remains visible for every later statement, even after a nested block ends. A same-named global is considered only when no function binding is visible.

`Sema.Function_expression_binding` checks those publication events against the immutable namespace and retains every ordinary identifier occurrence in source order. A match stores the selected stable binding; a miss remains a nonlocal candidate for the compilation-unit pass below. The three permitted repeated names keep the first source binding. Member suffix names, type syntax, `sizeof`, `offset`, `defined`, labels, and assembly tokens do not enter this ordinary-identifier stream. `HCSEMA0017` reports invalid cross-pass input, `HCSEMA0018` reports a mismatched publication, and `HCSEMA0019` reports an indexed local that was never published. Resolution does not mutate symbols or count uses. [Issue #204](https://github.com/frankischilling/holyc-ocaml/issues/204) records this boundary.

The active compilation unit is the next table in the lookup chain. `HashAdd` puts every aggregate, function, and global record at the front of its bucket, so a lookup sees the newest source-visible spelling without separating declaration kinds. `PrsClass`, `PrsFunJoin`, and `PrsGlblVarLst` publish their current records before reading the aggregate body, function body, or initializer. `Driver.Module_expression_binding` reconciles those three checked semantic streams with the original declaration collection and retains both each publication-site symbol and its canonical aggregate or function identity. Global publications retain their individual record identity and existing alias edge.

`Sema.Module_expression_binding` advances the mixed publication stream and ordered functions together. It publishes through the current function header before resolving that body, which permits recursion without leaking a later declaration backward. A visible function binding still wins. Otherwise the newest same-named aggregate, function, or global publication becomes the module binding. A name absent from the compilation unit remains an explicit outer candidate for later JIT task, parent-task, AOT parent, assembler, export, or loader lookup. `HCSEMA0020` reports invalid cross-pass input, and `HCSEMA0021` reports a function result without its compilation-unit publication. The pass is read-only and does not count uses, decide whether a selected declaration is valid for the surrounding expression, or perform outer lookup. [Issue #206](https://github.com/frankischilling/holyc-ocaml/issues/206) records this boundary.

`CHashTable` has one explicit `next` field. `Kernel/KHashA.HC` searches every matching record in the current table before following that link. `Kernel/KTask.HC:Spawn` links a child task table to its parent task table, and `Compiler/AsmInit.HC` links Adam's table to `cmp.asm_hash`. `Compiler/CMain.HC` selects a different successor for AOT: a nested compilation sees its enclosing compilation, while a top-level compilation sees the assembler table directly.

`Sema.Outer_environment` records that remaining chain as an immutable snapshot. A JIT snapshot begins with the current task at depth zero, continues through parent tasks in depth order, and ends with one assembler table. An AOT snapshot contains zero or more enclosing compilations in depth order and the assembler table, so its top-level form is assembler-only. Entries are supplied oldest to newest within one table; lookup selects the newest same-name record there before moving to the next table. Aggregate, function, global, and export-system records retain separate kinds and stable semantic symbols.

`Sema.Outer_expression_binding` preserves every local or module result from the earlier passes and consults the snapshot only for an explicit outer candidate. A successful result retains the selected entry, its table role, and the original occurrence provenance. An absent ordinary name fails with `HCSEMA0024`; it is not guessed to be an import. `HCSEMA0022` covers malformed chains and `HCSEMA0023` covers mismatched sessions or compilation modes. Environment construction and lookup are read-only. The project does not yet create these snapshots from a persistent hosted task runtime, assign record addresses, resolve alternate binding targets, create imports or fixups, validate the selected kind against the expression, or count uses. [Issue #208](https://github.com/frankischilling/holyc-ocaml/issues/208) records this boundary.

`Compiler/PrsStmt.HC:PrsGlblVarLst` calls `HashAdd` for a fresh `CHashGlblVar` before it calls `PrsGlblInit`. The initializer can therefore find its own record and every earlier comma declarator or module publication. A later declarator has not entered the hash table yet, so a same-named record in the outer chain may still win there. Recursive braced initializers use the same `PrsExpression` lookup at every scalar leaf.

`Driver.Global_initializer_binding` collects ordinary identifier occurrences from scalar and recursively braced initializer trees and retains a zero-based element path for each leaf. `Sema.Global_initializer_binding` validates the global records against the same AST and module publication stream, advances through the owning global publication, and then resolves each occurrence against the newest visible module record or the supplied JIT or AOT outer environment. Member suffix names stay outside the ordinary-name stream. `HCSEMA0025` reports inconsistent semantic input, while `HCSEMA0026` reports a name absent from both the visible module prefix and the complete outer chain. Resolution is read-only and does not type, evaluate, convert, store, lower, or execute an initializer. [Issue #210](https://github.com/frankischilling/holyc-ocaml/issues/210) records this boundary.

Array extents use the opposite side of the global publication boundary. `PrsGlblVarLst` calls `PrsType` before it allocates and publishes the current `CHashGlblVar`; `PrsType` calls `PrsArrayDims`, whose explicit expressions pass through `LexExpressionI64`. An extent can therefore see earlier module records, including an earlier declarator in the same comma group, but it cannot see its own record or a later declaration. If an older task, enclosing compilation, or assembler record has the same spelling, ordinary hash lookup may select that outer record.

`Sema.Global_binding_environment` provides the checked cursor used by both global expression passes. `Driver.Global_dimension_binding` pairs every ordinary, function-pointer, and aggregate-attached global with its exact AST dimensions, retains an empty first dimension without inventing an occurrence, and visits ordinary identifier expressions in source order. `Sema.Global_dimension_binding` resolves those occurrences before publishing the owner, then publishes it for the next declarator. `HCSEMA0027` reports inconsistent semantic associations, while `HCSEMA0028` reports a name absent from both lookup stages. Resolution is deterministic and read-only; it does not calculate an extent, convert a target value, type an expression, allocate storage, or change layout. [Issue #212](https://github.com/frankischilling/holyc-ocaml/issues/212) records this boundary.

Function defaults have a third publication boundary. `Compiler/PrsStmt.HC:PrsFunJoin` finds or inserts the named function record before it calls `PrsVarLst`, so the current header is visible to a recursive default. `PrsFun` does not install that function member list as `cc->htc.local_var_lst` until `PrsFunJoin` has returned. Although `PrsVarLst` has already added each parameter to the function record, those members are not the active local lookup environment while the header is being parsed. A parameter spelling in a default therefore falls through to the compilation-unit and outer tables instead of selecting the parameter.

`Sema.Module_binding_environment` supplies the checked mixed-publication cursor shared by this pass and the global binders. `Driver.Function_default_binding` visits ordinary expression identifiers in defaults on top-level named prototypes and definitions. Member suffixes, type syntax, `sizeof`, `offset`, and `defined` do not become ordinary occurrences. `Sema.Function_default_binding` publishes through the owning header, then selects the newest visible module record or the supplied JIT or AOT outer record. Each result retains the source declaration and the canonical identity chosen by function reconciliation, so joined headers remain distinct source sites while recursive defaults point at the active record. `lastclass` remains a distinct default kind and produces no ordinary occurrence. `HCSEMA0029` rejects inconsistent semantic associations, while `HCSEMA0030` reports a name absent from both lookup stages. Resolution is deterministic and read-only. It does not evaluate or substitute defaults, compare joined headers, check calls, or traverse defaults inside callback, member, global, or local declarators. [Issue #214](https://github.com/frankischilling/holyc-ocaml/issues/214) records this boundary.

Function identity reconciliation is a separate pass. TempleOS prepends hash entries, so both lookup paths inspect the newest same-name record first. In JIT mode, `PrsFunJoin` reuses that record only while `Cf_EXTERN` remains set; a definition, `_extern`, or `_intern` clears the bit, and a later declaration starts a shadowing identity. In AOT mode, it reuses the newest record unless `HTF_IMPORT` is set. An `import` or `_import` marks the selected record as imported, making it a barrier for the next same-name declaration. `Driver.Function_resolution` checks the parsed binding form against the resolved function batch, and `Sema.Function_resolution` applies that matrix in module order. Each declaration retains its compiler-option snapshot. When `OPTf_EXTERNS_TO_IMPORTS` is enabled, the semantic declaration keeps `extern` or `_extern` as its source kind but uses import as its effective kind before the matrix runs. The converted record therefore becomes the same AOT barrier as an explicit import and reaches the same AOT-only error in JIT mode. Each identity keeps its original symbol, every declaration site, its final unresolved-extern, imported, or resolved state, and the immediately replaced header for compatibility analysis. The pass is deterministic and does not mutate the symbol table. It does not search parent task tables or resolve alternate binding targets or addresses. [Issue #183](https://github.com/frankischilling/holyc-ocaml/issues/183) records identity selection; [issue #230](https://github.com/frankischilling/holyc-ocaml/issues/230) records the compiler-option conversion.

`Sema.Function_header_analysis` consumes those replacement pairs. It compares return types by resolved HolyC identity and projects each parameter to the fields that `MemberLstCmp` reads. An unnamed slot uses `_anon_`; a callback uses internal `I64i` at its callback indirection depth; `lastclass` supplies zero bits; scalar and floating defaults use their exact 64-bit payload; and string defaults compare through the first NUL. `MemberLstCmp` also reads `member_class_base`, but `MemberAdd` fills that field only for local variables, so function parameters compare as null on both sides. The replaced header's fixed argument count controls the loop even though synthetic `argc` and `argv` remain in the linked list. This preserves the source's asymmetric result when a variadic header is replaced by a longer fixed header.

The current declaration's `OPTf_WARN_HEADER_MISMATCH` snapshot decides whether comparison runs. A disabled option produces no warning and no invented match result. Enabled analysis emits `HCSEMA0037` for the return type and `HCSEMA0038` for the argument list independently, retaining both declaration sites and the current function origin. `HCSEMA0036` rejects missing values, a scalar/string storage mismatch, foreign semantic state, or a declaration batch that no longer matches identity resolution. Compile-time evaluation, call-site default substitution, and source-positioned `Option(...)` execution remain separate work. [Issue #236](https://github.com/frankischilling/holyc-ocaml/issues/236) records the comparison boundary.

Function record state is replayed after identity selection. A new `CHashFun` starts with `Cf_EXTERN` and receives only the staged interrupt, error-code, argument-pop, and no-argument-pop bits. A joined header keeps the record's stored bits instead of copying new staged bits. Every header replaces `HTF_PUBLIC`, while `HashSrcFileSet` can add `HTF_PRIVATE` without clearing it later. Varargs and the derived `Ff_RET1` bit also accumulate because the pinned parser sets them but does not clear an older value when it reuses a record.

`Sema.Function_record_classification` applies the binding-specific changes after each header. `_intern` sets `Ff_INTERNAL` and clears `Cf_EXTERN`; `_extern` clears `Cf_EXTERN`, sets `Ff__EXTERN`, and adds `HTF_RESOLVE` in AOT mode; imports add `HTF_IMPORT` and retain their exact loader spelling; and a definition adds `HTF_EXPORT | HTF_RESOLVE` in AOT mode before clearing `Cf_EXTERN`. This order preserves a source quirk: a definition followed by `extern` and then `import` may keep export and resolve bits on the imported record. `AsmResolve` tests the import branch first, so import publication wins and resolution is reported as shadowed.

The classifier exposes the downstream policy without performing it: internal, direct, JIT extern-slot, AOT import, or AOT extern calls; `HashVal`'s record-versus-address result; runtime address-lookup visibility; map eligibility; and AOT publication and resolution intent. Its low-level API accepts one compiler-option snapshot per declaration. The driver defaults to the snapshot retained by resolution and accepts a batch override only when its `OPTf_EXTERNS_TO_IMPORTS` bit agrees with that snapshot. This prevents classification from relabeling a declaration after identity selection. Header comparison is handled by the evaluated-input analysis above. Default evaluation, source-positioned `Option(...)` execution, alternate address lookup, fixup creation, map writing, import/export emission, ABI validation, and call lowering remain separate work. [Issue #191](https://github.com/frankischilling/holyc-ocaml/issues/191) records this boundary.

Global records follow a different rule. `PrsGlblVarLst` allocates and prepends a fresh `CHashGlblVar` for every declarator, including repeated names. In JIT mode, a definition redirects only the newest same-name plain extern when that record still has `HTF_UNRESOLVED`; a definition, import-like record, or `_extern` record is a barrier. In AOT code-heap mode, a definition redirects the newest prior same-name global regardless of its binding state. The compiler copies the new address fields into that older record and adds `GVF_ALIAS`. It does not merge the records, clear the older flags, compare their types, or retarget an earlier edge. Three AOT definitions therefore form `first -> second -> third`, not `first -> third`.

`Sema.Global_resolution` preserves that direction with one immutable result record per checked global and an optional immediate alias target on the older record. Plain externs retain distinct JIT unresolved and AOT declared states; `_extern`, import forms, `_intern`, and ordinary definitions remain distinguishable. Each declaration also retains its source kind, effective kind, compiler-option snapshot, and derived storage policy. `OPTf_EXTERNS_TO_IMPORTS` converts the two extern forms before mode validation, while preserving the local or alternate target spelling. An AOT code-heap definition still redirects the immediately preceding same-name record after that conversion: the pinned alias test checks only that the older entry is a global record, so an import is not an alias barrier. `OPTf_GLBLS_ON_DATA_HEAP` selects data-heap storage only for ordinary and `_intern` definitions. The semantic validator rejects initialized AOT data-heap definitions before alias reconciliation and preserves the pinned error when such a definition follows any same-name global. Alternate symbol targets and `_intern` expression ranges are retained without evaluating an address. The driver accepts one batch option snapshot until source compiler-option execution can provide separate source-position states. The pass does not allocate storage, resolve a target, inspect parent tasks, emit the unused-extern warning, apply visibility, or create loader records. [Issue #187](https://github.com/frankischilling/holyc-ocaml/issues/187) records global reconciliation; [issue #230](https://github.com/frankischilling/holyc-ocaml/issues/230) records extern conversion; [issue #232](https://github.com/frankischilling/holyc-ocaml/issues/232) records data-heap policy.

`Kernel/KernelA.HH` gives a global record two independent flag domains. `HTF_*` bits describe hash-table state, while `GVF_*` bits describe the stored global value. `tools/global_record_flag_source.ml` checks all nine hash flags, all six global flags, the global hash type, seven source checksums, and the consumer sites that distinguish the domains. The generated registry is exposed through `Sema.Global_record_flag`; no handwritten duplicate owns the numeric values.

`Sema.Global_record_classification` derives both masks from each resolved record and its source-position state. Ordered parser staging matters: `public static` does not retain `HTF_PUBLIC`, while `static public` does. `OPTf_KEEP_PRIVATE` adds `HTF_PRIVATE` independently, so a record may be both public and private or both imported and private. A JIT plain extern receives `HTF_UNRESOLVED` and `GVF_EXTERN`, which makes `HashVal` use the address slot. An AOT import receives `HTF_IMPORT` and `GVF_IMPORT`; `_import` retains its alternate target as the import name. An AOT `_extern` receives `HTF_EXPORT` and `GVF_ALIAS`. A code-heap definition or `_intern` record is exportable in AOT mode, but a data-heap definition is not. Function-pointer and array shape add `GVF_FUN` and `GVF_ARRAY`, and an older record redirected by global reconciliation gains `GVF_ALIAS`.

The result also states the source-backed consumer policy: direct or extern-slot JIT access, code-heap, data-heap, import, or unsupported plain-extern AOT access; aliased-address ownership; map eligibility; and AOT publication intent. Publication is intentionally named as intent because `AsmResolve` emits an import only when a use produced a fixup. The classifier does not allocate an address, resolve an alternate target, decide whether an unused import is emitted, write a map or patch record, or mutate the symbol table. Its low-level API accepts one compiler-state snapshot per record. The driver defaults to the snapshot retained by resolution and rejects an override whose `OPTf_EXTERNS_TO_IMPORTS` or `OPTf_GLBLS_ON_DATA_HEAP` bit would contradict the effective binding or storage policy. Source-positioned option execution remains separate work. [Issue #189](https://github.com/frankischilling/holyc-ocaml/issues/189) records this boundary.

The `goto` branch in `Compiler/PrsStmt.HC` finds or creates a `CMT_GOTO_LABEL`, increments its use count, and emits a jump. The identifier-label branch uses the same record, marks it defined, and rejects a second language definition. `Compiler/PrsLib.HC:COCGoToLabelFind` searches both `CMT_GOTO_LABEL` and `CMT_ASM_LABEL`, so a function-local assembly definition can satisfy a language `goto`. `Compiler/Asm.HC` adds those assembly definitions to the function's code-control list and contributes one use to suppress the ordinary unused-label warning. `Compiler/PrsLib.HC:COCDel` later rejects an undefined record and warns about an unused language definition.

`Driver.Label_resolution` walks every recursive statement route in parser order and collects language gotos, language definitions, and the three structural labels retained by brace-delimited assembly blocks. `Sema.Label_resolution` validates the complete batch before mutation, creates one `Symbol.Label` identity per defined spelling in each function, and maps every occurrence to that identity. Label order follows the first occurrence, while symbol provenance comes from the definition rather than an earlier forward `goto`. Prototypes receive an empty result, and separate function scopes can reuse the same spelling. Top-level language occurrences, missing targets, duplicate language definitions, mixed language/assembly definitions, mismatched AST collections, and foreign session handles fail without adding a label. [Issue #172](https://github.com/frankischilling/holyc-ocaml/issues/172) records this boundary.

`Compiler/Asm.HC:1032-1062` has a narrower rule for repeated assembly definitions: a repeat is valid only when the existing value equals the current output address. The semantic pass retains every such occurrence and its definition count because layout has not assigned addresses yet. [Issue #174](https://github.com/frankischilling/holyc-ocaml/issues/174) tracks that assembler check. Assembly operand references marked through `Compiler/AsmResolve.HC`, direct-assembly labels, unused warnings, collision checks against reconciled global objects, jump construction, and IR lowering also remain pending.

## Implemented parser boundary

The AST keeps `public`, `static`, `interrupt`, `haserrcode`, `argpop`, and `noargpop` as ordered staged modifiers. It keeps one ordinary, alternate-name, or `_intern` binding separate from the declared type. An `_extern` or `_import` node retains the target identifier that appears before the type. An `_intern` node retains the unevaluated target expression instead. Function parameters retain ordered `reg` and `noreg` qualifiers, their position around the type, and an optional canonical U64 register name. Automatic local declarators separately retain after-type `reg` and `noreg` requests plus an optional U64 register. Static locals retain their storage spelling and reject that automatic-only qualifier position. Those separations follow `PrsStmt` and `PrsVarLst`. Calling modifiers and register requests remain syntax here; no linkage, allocation, or ABI rule is applied during parsing.

An `extern class Name;` or `extern union Name;` item retains the ordinary binding, aggregate spelling, name, semicolon, modifiers, and source provenance. `PrsClass` publishes the source entry before its next `Lex` call, so the OCaml parser publishes the name as `Symbol_visibility.Class` before preprocessing asks for another token. A following `#ifdef Name` can therefore observe it in JIT or AOT mode. Class and union remain distinct AST kinds even though both enter the common class-symbol category. A visible class symbol can start a later declaration type, aggregate member, or postfix cast. An ordinary definition publishes its name before reading members, which permits self-referential pointers and lets a prior forward name continue into the definition path. The parser records syntax and streaming visibility; aggregate reconciliation models the resulting `Cf_EXTERN` completion identity, while later passes bind accepted member, global, and function-signature uses to canonical identities. General duplicate checks, other type contexts, layout, and linkage remain separate work.

The default parser mode is JIT. It accepts `extern`, `_extern`, and `_intern`; rejects `import` and `_import` with `HCPARSE0006`; and does not publish a rejected name. An explicit AOT parser configuration accepts all five bindings. Each accepted binding and target retains its spelling, source segments, generated frame, invocation site, and definition site. The type-safe target representation distinguishes no target, a symbol target, and an expression target. Singleton and comma-separated globals share that binding representation whether their base is primitive or a published class name and whether the stored value is ordinary or a function pointer. Bound function prototypes retain it alongside their return type, parameters, and punctuation. A missing alternate target receives `HCPARSE0007`.

This is syntax handling plus the source-backed AOT gate. An accepted prototype is published to the streaming environment with function identity and a compact call shape. The shape records fixed parameters in declaration order, optional names, default availability, and whether the signature is variadic. It is sufficient to recognize a direct parenthesis-free call, but it is not a semantic function type. A function-pointer global instead enters the environment with global-variable identity, matching the `CHashGlblVar` path in `PrsGlblVarLst`; its retained signature does not enable direct-call syntax. The global type pass now constructs that signature as an immutable semantic type without changing the symbol category. Later function and global resolution applies `OPTf_EXTERNS_TO_IMPORTS` from explicit declaration snapshots. These passes still do not look up an ordinary or alternate binding target, evaluate an `_intern` expression, create an import or export loader record, assign storage or an executable address, or model task-parent lookup. Those behaviors belong to later semantic linkage, AOT emission, and the loader model.

Parameter defaults retain their source expressions, including defaults before required parameters. Parenthesized call nodes retain each provided or omitted slot, so semantic checking can match holes to defaults without confusing them with explicit zero. A direct function name without parentheses walks the retained call shape. Each defaulted fixed position adds an omitted slot, each required position parses one adjacent expression, and variadic extras remain absent. Definitions publish their shape before body parsing, so recursion works. `&Function`, a local name, or a newer nonfunction entry suppresses this form. The direct-call pass resolves either syntax against the function header visible at the call site and retains the joined function identity separately. It fills explicit holes and absent trailing positions from declared defaults, reports missing or extra fixed slots, counts only provided variadic expressions, and keeps callback variables and unresolved outer names deferred. A following pass classifies each provided fixed target as the forwarded `F64` or integer result path, including source-visible aggregate backing chains. Literal actuals, the audited `$$`, `sizeof`, `offset`, and `defined` primaries, primitive, intrinsic, or named aggregate postfix casts, and the checked prefix paths then select the exact conversion intent. A named cast retains the aggregate identity visible before the caller and follows only backing headers already published there; a pointer cast stops on the integer path. Cast targets retain spelling, pointer, include, and generated-source origins. Unary plus, unary minus, logical not, pre-increment, and pre-decrement keep the recursive operand class, while address-of and bitwise complement select the integer path. Complement uses the `I64` result assigned by `OptPass012`, not its operand class. Dereference remains unresolved. Defaults and variadic expressions stay separate, and no conversion flag is applied. Default evaluation, lvalue checks, update effects, indirect-call checking, and lowering also remain unavailable. Index and member nodes retain source shape but are not bound to an element type, address, offset, or lvalue class. Closed aggregate layouts and member indexes supply the relevant byte facts once a later expression pass identifies the aggregate. Index scaling, AST member binding, and string-default storage remain unimplemented. Primitive and named global, local, or aggregate member arrays retain their ordered dimensions. Global type results keep each opening bracket, optional expression, closing bracket, and complete dimension origin; member type results retain dimension origins. The closed aggregate pass evaluates member extents when they need no unresolved symbols. Global and local extent evaluation, storage, and linkage remain unavailable. `_intern` likewise retains syntax without applying its source-defined address and flag effects.

Binary argument views use the checked generated IC identity rather than source spelling alone. Power takes the `F64` path. Logical and comparison operators take the integer path. Arithmetic, shift, and bitwise families combine recursive audited operand classes, while assignment families wait for lvalue typing. This classification does not resolve an identifier merely because it appears under a binary operator, and it does not evaluate or apply the operator. [Issue #252](https://github.com/frankischilling/holyc-ocaml/issues/252) records this boundary.

Postfix-update argument views retain their checked operator identity, source origin, and recursive operand. The direct-call conversion decision forwards that operand class for `IC__PP` and `IC__MM`. This does not validate the lvalue or apply the update. [Issue #255](https://github.com/frankischilling/holyc-ocaml/issues/255) records this boundary.

Direct-call identifier views reuse the completed expression bindings rather than looking up the spelling again. A local occurrence points to its exact parameter, synthetic vararg, automatic-local, or static-local binding. A module occurrence points to the source global publication and then to its checked global type. The join uses stable symbol IDs and preserves publication order, so local shadowing and same-name module replacements cannot silently select a later record. Object values retain their resolved type; arrays and callbacks retain a separate pointer-shaped value classification. Outer candidates do not acquire a guessed type. [Issue #259](https://github.com/frankischilling/holyc-ocaml/issues/259) records this boundary.

Pre-increment and pre-decrement use the existing recursive prefix view. Their direct-call result class now follows the audited operand class, matching the shared source optimizer branch. Lvalue validation and update effects remain separate. [Issue #257](https://github.com/frankischilling/holyc-ocaml/issues/257) records this boundary.

Unbound function definitions retain their complete header and one ordinary statement body. The function enters the streaming environment before that body is requested. Named parameters, synthetic variadic `argc` and `argv`, and accepted local names then enter a function-wide parser context. Each local is published before its initializer or following token is parsed, matching the `MemberAdd` order in `PrsVarLst`. A local name shadows a class or direct function for later syntax routing. A callback local remains a variable entry: its retained signature does not enable parenthesis-free direct-call syntax. An ordinary static local can retain a scalar or recursively braced initializer; an automatic ordinary local retains one scalar expression. This parser context determines syntax while the semantic function-collection pass gives the named parameters and locals stable identities in a separate function scope. The local type pass then binds their complete object or callback types and keeps register, array, initializer, and delimiter facts. None of these layers assigns block lifetimes, storage offsets, ABI effects, or executable addresses. Aggregate definition nodes retain an optional public, intrinsic, or named backing type, its pointer layers, an optional single base, ordinary grouped members, member return pointers, recursive callback declarators, arrays, recursive anonymous unions, explicit source-positioned offset directives, and either a standalone semicolon or attached globals. The aggregate is published before the base token is requested, matching `PrsClass`; the base must resolve through the shared visible class category. Each attached global is published before the parser requests the next token, matching `PrsGlblVarLst`. An attached function-pointer global keeps its recursive signature, while a callback member keeps the same signature shape without entering the top-level symbol environment. Every attached global keeps its optional scalar or recursively braced initializer. The semantic collection passes give each named direct member, fixed parameter, synthetic variadic binding, and local declarator an identity. Member type resolution additionally binds each direct member's public, intrinsic, or aggregate base plus ordinary pointers, then resolves complete recursive callback signatures after publishing the current aggregate identity. Callback parameters do not receive independent symbols. Their defaults retain expression or `lastclass` form and provenance, but this pass does not bind or evaluate those default expressions or assign runtime storage. The checked member-list registry gives each semantic callback member `MLF_FUN` (`0x8`), while an ordinary object member carries zero. Closed aggregate layout subsequently evaluates supported extent and offset expressions, records union overlap and base prefixes, and calculates member offsets. The aggregate member index validates source-compatible duplicates and searches direct members before the single base chain. Function type resolution separately binds top-level function returns and recursive fixed-parameter signatures, but nested callback slots do not receive independent symbols. Global type resolution binds ordinary and attached globals, including complete recursive callback signatures, while preserving their global-variable identity. Register allocation, direct local callback initialization, automatic local braced initializers, metadata, symbol-dependent aggregate-offset expressions, casts, `sizeof`, `offset`, backing compatibility, whole-value and subinteger access, general cycle diagnostics, and nonmember duplicate-declaration rules remain unavailable.

Member names have a narrow contextual rule. TempleOS lexes keyword spellings as `TK_IDENT` and asks `PrsKeyWord` for a keyword interpretation only where the grammar expects one. The OCaml lexer retains distinct keyword tokens, but ordinary and recursive function-pointer aggregate declarators accept them as names after their type and pointer prefix. This does not publish a top-level symbol, and it does not relax global, local, parameter, function, aggregate, or label names. Twelve pinned `U0 start;` members and all 48 checked keyword spellings exercise this boundary under issue #147.

Member metadata follows the same contextual identifier boundary but has no independent symbol-table entry. Each declarator keeps its source-ordered names and either an extended string or ordinary expression value. Duplicate metadata names remain present. Direct-member collection creates one symbol for the declarator name and deliberately ignores those metadata names. A later metadata pass must reproduce TempleOS's prepended list and last-written lookup precedence rather than silently deduplicating them. The parser does not yet evaluate expression values, allocate `CMemberLstMeta`, set `MLMF_IS_STR`, or implement `MemberMetaData` and `MemberMetaFind`. Issue #149 records this syntax and the remaining semantic boundary.

`no_warn` uses that function-wide parser context directly. The target token is accepted only when the current lookup reports a local shadow, which covers fixed parameters, synthetic variadic bindings, and locals published earlier in source order. A same-named global remains irrelevant once a local is visible; a global by itself, an unresolved name, or a later local is rejected. The semantic function-binding stream resolves each accepted target to that same stable binding. It records the suppression separately from ordinary expression uses and records the count reset after an initialized local.

`sizeof`, `offset`, and `defined` take a narrower route through the same publication-ordered environment. The root of `sizeof` or `offset` becomes a query, as does a name-shaped `defined` operand. Member-path spellings do not become queries; the pinned parser undoes their incidental `MemberFind` increments. A non-name `defined` operand also contributes nothing. These records leave the ordinary occurrence list unchanged, so compilation-unit and outer-table binding still consume only ordinary expressions.

`Sema.Local_warning_analysis` copies the declaration-time member mask, adds `MLF_NO_UNUSED_WARN` to its immutable result, and computes ordinary, query, suppression, and combined source counts. A definition reports an unflagged zero-count binding when `OPTf_WARN_UNUSED_VAR` is enabled. A flagged binding reports an unneeded suppression when its combined count exceeds one, except for `_anon_`; that second warning does not depend on the option. The post-initializer reset clears ordinary and query uses of the binding being declared while leaving earlier bindings alone. Prototypes produce no warnings. The result retains binding and suppression origins, but it does not mutate `Sema.Symbol_table` or allocate a `CMemberLst`.

Type syntax, member lookup, query values, labels, and assembly tokens remain outside this pass. The driver currently receives one compiler-option mask for the batch, so source-executed option changes and a CLI diagnostic renderer remain later work.

## Typed results for direct-call expressions

Provided fixed arguments on resolved direct function-body calls receive immutable semantic results before target conversion. Each result belongs to the active semantic symbol table and the exact conversion-policy traversal that supplied its source position. A result keeps a deterministic expression ID, exact origin, known type when this slice can prove one, value category, and the forwarded integer, `F64`, or unresolved class.

The value category does not replace symbol identity. A bound parameter, local, or global still points to its source-ordered binding. In value context an ordinary object becomes an object value; the same occurrence remains an lvalue beneath address-of or an update. Arrays and callbacks keep distinct categories, and an unavailable type stays unavailable. Replaying the pass does not change use counts or symbol-table contents.

The following conversion pass accepts only results from the same policy traversal. `HCSEMA0046` reports a foreign session during expression-result construction, while `HCSEMA0045` reports a foreign session or mismatched traversal during conversion selection. This prevents a source result from being paired with a target header selected by another analysis run. General member lookup, dereference, indexing, assignment, function values, indirect calls, storage, and linkage remain outside this slice.
