# Scoping and linkage

This document records the behavior established from TempleOS commit `c26482bb6ad3f80106d28504ec5db3c6a360732c`. The main references are `Compiler/PrsStmt.HC`, `Compiler/CompilerA.HH`, `Doc/ScopingLinkage.DD`, and `Doc/Options.DD`.

## Source behavior

JIT compilation searches the current task's symbol table and then its parent tasks. New declarations enter the current task's table and may shadow older names where the source permits duplicates. A plain `extern` function or global variable binds to the same name when it already exists and can also create a forward declaration.

A plain `import` names a symbol that the TempleOS loader resolves when an AOT module is loaded. If the symbol is unavailable then, uses remain incomplete until a later definition can resolve them. `PrsGlblVarLst` rejects `PRS0_IMPORT` when `CCF_AOT_COMPILE` is clear.

`_extern` and `_import` bind a HolyC declaration to a separately named system or imported symbol. `_intern` binds through a compile-time address expression. Those forms have more syntax and state than plain `extern` and `import`.

`OPTf_EXTERNS_TO_IMPORTS` changes ordinary and underscored extern declarations into their import forms. The pinned compiler uses this while compiling shared headers in different JIT and AOT contexts.

## Implemented parser boundary

The AST keeps `public`, `static`, `interrupt`, `haserrcode`, `argpop`, and `noargpop` as ordered staged modifiers. It keeps one ordinary, alternate-name, or `_intern` binding separate from the declared type. An `_extern` or `_import` node retains the target identifier that appears before the type. An `_intern` node retains the unevaluated target expression instead. Function parameters retain ordered `reg` and `noreg` qualifiers, their position around the type, and an optional canonical U64 register name. Automatic local declarators separately retain after-type `reg` and `noreg` requests plus an optional U64 register. Static locals retain their storage spelling and reject that automatic-only qualifier position. Those separations follow `PrsStmt` and `PrsVarLst`. Calling modifiers and register requests remain syntax here; no linkage, allocation, or ABI rule is applied during parsing.

An `extern class Name;` or `extern union Name;` item retains the ordinary binding, aggregate spelling, name, semicolon, modifiers, and source provenance. `PrsClass` publishes the source entry before its next `Lex` call, so the OCaml parser publishes the name as `Symbol_visibility.Class` before preprocessing asks for another token. A following `#ifdef Name` can therefore observe it in JIT or AOT mode. Class and union remain distinct AST kinds even though both enter the common class-symbol category. A visible class symbol can start a later declaration type, aggregate member, or postfix cast. An ordinary definition publishes its name before reading members, which permits self-referential pointers and lets a prior forward name continue into the definition path. This is still syntax and streaming visibility only. The parser does not clear `Cf_EXTERN` when a body arrives, assign semantic type identity, compare duplicates, or apply layout and linkage rules.

The default parser mode is JIT. It accepts `extern`, `_extern`, and `_intern`; rejects `import` and `_import` with `HCPARSE0006`; and does not publish a rejected name. An explicit AOT parser configuration accepts all five bindings. Each accepted binding and target retains its spelling, source segments, generated frame, invocation site, and definition site. The type-safe target representation distinguishes no target, a symbol target, and an expression target. Singleton and comma-separated globals share that binding representation whether their base is primitive or a published class name. Bound function prototypes retain it alongside their return type, parameters, and punctuation. A missing alternate target receives `HCPARSE0007`.

This is syntax handling plus the source-backed AOT gate. An accepted prototype is published to the streaming environment with function identity and a compact call shape. The shape records fixed parameters in declaration order, optional names, default availability, and whether the signature is variadic. It is sufficient to recognize a direct parenthesis-free call, but it is not a semantic function type. The parser does not look up an ordinary or alternate target, evaluate an `_intern` expression, compare headers, resolve a forward reference or alias, create an import or export record, assign an executable address, set `Ff_INTERNAL`, clear `Cf_EXTERN`, apply `OPTf_EXTERNS_TO_IMPORTS`, or model task-parent lookup. Those behaviors belong to semantic linkage, AOT emission, and the loader model.

Parameter defaults retain their source expressions, including defaults before required parameters. Parenthesized call nodes retain each provided or omitted slot, so later checking can match holes to defaults without confusing them with explicit zero. A direct function name without parentheses walks the retained call shape. Each defaulted fixed position adds an omitted slot, each required position parses one adjacent expression, and variadic extras remain absent. Definitions publish their shape before body parsing, so recursion works. `&Function`, a local name, or a newer nonfunction entry suppresses this call form. Index and member nodes retain source shape without assigning an element type, address, offset, or lvalue class. Semantic default evaluation, call resolution, argument checking, index scaling, member lookup, layout, and string-default storage are not implemented. Primitive and named global, local, or aggregate member arrays retain their ordered dimensions, but the parser does not evaluate sizes, calculate storage, or apply linkage. `_intern` likewise retains syntax without applying its source-defined address and flag effects.

Unbound function definitions retain their complete header and one ordinary statement body. The function enters the streaming environment before that body is requested. Named parameters, synthetic variadic `argc` and `argv`, and accepted local names then enter a function-wide parser context. Each local is published before its initializer is parsed, matching the `MemberAdd` order in `PrsVarLst`. A local name shadows a class symbol for later syntax routing. This context does not create semantic bindings, block lifetimes, storage offsets, ABI effects, or executable addresses. Aggregate definition nodes retain ordinary grouped members, pointers, arrays, recursive anonymous unions, and punctuation, but they do not establish semantic member identities or offsets. Register allocation, local function-pointer declarators, aggregate initializers, backing types, inheritance, metadata, explicit aggregate offsets, function-pointer members, semantic type resolution, layout, and duplicate-declaration rules remain unavailable.

The unit suite parses the unfiltered first 27 lines of `Compiler/CExts.HC` after supplying the 11 required forward names and the 12 consecutive ordinary definitions at `Kernel/KernelA.HH:116-179`. Existing binding, aggregate-forward, prototype, function-definition, local, array, call, and index fixtures retain their coverage. The controlled native result is `test/oracle/parenthesis-free-calls.json`; no native oracle was needed for named type or aggregate-body dispatch because the checked `PrsStmt` and `PrsVar` branches state the token and symbol behavior directly.
