# Native stream generation

JIT `#exe` now executes StreamPrint in native code and feeds the resulting text
back to the original parser. The maintained example generates
`I64 Answer=40;`, prints `made` through ordinary Print, and returns 42:

```sh
holyc run --mode=jit --target=host-jit-task --code-byte-limit=524288 examples/native-stream-generation.hc
```

StreamPrint formats into a separate native generation buffer. Its original
extern slot can be captured, copied, indexed, passed to a function, or saved as a
default. A later source body for that name leaves earlier captures attached to
their original private entry. Functions declared in the executing task can keep
these callbacks across later `#exe` directives. Nested directives retain the
original parser context and LIFO generation buffers.

Each native entry publishes only the bytes its formatter committed. The C bridge
roots an opaque capture containing the exact original generation target and
arena. Completion checks the original domain, active stream and unchanged byte
budget before consuming that capture once. A metadata copy, foreign target,
replayed capture or expired arena cannot authorize source bytes. No interpreter
executes the source commands and no host formatter supplies their text.

Ordinary output and generated text have separate byte allowances. Both charge
the task's cumulative output-work allowance. A successful formatting call
commits its complete draft; a failed call leaves earlier generated bytes charged.
Aborting a stream discards its text but retains reached output and resource
charges. `--generated-byte-limit` bounds cumulative generated bytes independently
of `--output-byte-limit`. Native tasks accept a generated-byte allowance up to
16 MiB. Instruction, frame, call depth, IR and machine-code limits still apply.
Provider entries are currently emitted in each fragment that needs them, so
longer histories can require a larger explicit code allowance.

The pinned StreamPrint formats before checking the active stream. Native calls
outside `#exe` therefore report `HCIRVM0027` after formatting; format, pointer,
byte and work faults can occur first. StreamExePrint retains its original I64
signature and formats through its own temporary buffer. JIT calls then report
`HCIRVM0027`, including calls through saved callbacks. Its successful synchronous
AOT execution still requires native AOT source tasks and a bridge that resumes
the original parser while the calling native function is suspended.

The private generation context does not implement the exported HolyC ABI,
TempleOS task scheduling or arbitrary compile-time execution. Module functions
outside an executing `#exe` task keep their existing visibility boundary. Native
AOT tasks, floating execution, aggregate object execution, object/BIN relocation,
loader integration and bootstrap acceptance remain open.

`Compiler/CMisc.HC:68-81` supplies StreamPrint's format-before-context order and
stream append. `Compiler/CMain.HC:673-690` supplies StreamExePrint's synchronous
AOT context and return value. Both come from the pinned TempleOS tree.

The shared source fixtures cover values, callbacks, saved defaults, replacement
order, nested generation and reached failures. Fresh IR and native executions
compare values, ordinary output and exact formatting work. Native capture tests
also check ABI, domain, arena, metadata-copy, GC, replay and expiry boundaries.
CLI checks exercise the maintained example and exact resource edges in both
targets.
